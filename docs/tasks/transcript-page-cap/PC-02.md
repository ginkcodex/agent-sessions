# PC-02 — Engine pages capped by size around an anchor

- **Status:** ✅ Done
- **Estimate:** 2 h
- **Depends on:** —
- **Plan:** [transcript-page-cap.md](../../plan/transcript-page-cap.md)

## Scope

`PageCap{MaxBytes, Anchor}` and `MessagesPage.Capped` in
`internal/engine`; `capPage` applies the cap to `pageOf`'s page as the plan's Engine section
says (uncapped page first, anchor clamped into it, grow outward by
`model.MessageBytes`, anchor always kept). `Service.GetMessagesCapped` and
`Engine.GetMessagesCapped`; `GetMessages` unchanged. The method joins the
`Backend` interface in PC-03, with its other implementations.
`GetMessagesSince` stays uncapped.

## Likely files

`internal/engine/types.go`, `service.go`, `engine.go`, `backend.go`,
`service_test.go` or a new `page_cap_test.go`.

## Acceptance criteria and tests

- No cap (`MaxBytes` 0): pages equal today's.
- Anchor -1 with offset -1: newest messages within budget, real `Offset`,
  `Capped` true when any were dropped, `HasMore` false.
- Anchor at the page's end, start and middle: the kept messages are
  contiguous and contain the anchor; middle grows both ways.
- One message over budget: returned alone.
- Anchor outside the page is clamped; empty transcript returns an empty page.
