# PC-04 — Viewer asks for capped pages

- **Status:** ⬜ Not started

## Scope

`api.getMessages(ref, offset, limit, cap?)` calls `GetMessagesCapped`
when a cap is given and the binding exists, else `GetMessages`; the mock
API applies the cap with the engine's rules. `TranscriptView.svelte`
passes `PAGE_BYTES` (256 KB) and the anchors of the plan's Viewer table;
`loadEarlierMessages` uses `page.offset`; a window from a capped page
refreshes with its own length, not `max(length, PAGE_SIZE)`.

## Likely files

`frontend/src/lib/api.ts`, `mock/mockApi.ts`, `transcriptRefresh.ts`,
`components/transcript/TranscriptView.svelte`, `frontend/src/lib/types.ts`
(`MessagesPage.capped`), tests in `frontend/test/`.

## Acceptance criteria and tests

- First load, back to bottom, earlier, more and search jump each send their
  anchor and the budget.
- Earlier pages are placed by `page.offset`; no gap or duplicate when the
  cap shortened the page.
- A capped window's refresh does not fetch the dropped messages; an
  uncapped one behaves as today.
- An older binding without `GetMessagesCapped` falls back to
  `GetMessages`.
- `npm test` and `npm run check` pass.
