# PC-04 — Viewer asks for capped pages

- **Status:** ✅ Done
- **Estimate:** 4 h
- **Depends on:** PC-03
- **Plan:** [transcript-page-cap.md](../../plan/transcript-page-cap.md)

## Scope

`api.getMessages(ref, offset, limit, cap?)` calls `GetMessagesCapped`
when a cap is given and the binding exists, else `GetMessages`; the mock
API applies the cap with the engine's rules. `TranscriptView.svelte`
passes `PAGE_BYTES` (256 KB) and the anchors of the plan's Viewer table;
`loadEarlierMessages` uses `page.offset`; a window from a capped page
refreshes with its own length, not `max(length, PAGE_SIZE)`.

## Likely files

`frontend/src/lib/api.ts`, `mock/mockApi.ts`, `transcriptRefresh.ts`, a new
`pageCap.ts`, `components/transcript/TranscriptView.svelte`, tests in
`frontend/test/`. (`MessagesPage.capped` and `PageCap` types came with
PC-03.)

## Acceptance criteria and tests

- First load, back to bottom, earlier, more and search jump each send their
  anchor and the budget.
- Earlier pages are placed by `page.offset`; no gap or duplicate when the
  cap shortened the page.
- A capped window's refresh does not fetch the dropped messages; an
  uncapped one behaves as today.
- An older binding without `GetMessagesCapped` falls back to
  `GetMessages`.
- `npm test` and `npm run check` pass.

## Evidence

- `pageCap.ts`: `PAGE_SIZE` (50, moved from `TranscriptView.svelte`),
  `PAGE_BYTES` (256 KB), `pageCap(anchor)`, and `capPage`, the engine's rule
  in TypeScript for the mock.
- `api.ts`: `getMessages(ref, offset, limit, cap?)` calls
  `GetMessagesCapped` when a cap is given and the binding has it, else
  `GetMessages`. `mockApi.ts` caps by JSON length with `capPage` and rejects
  invalid caps as the engine does.
- `TranscriptView.svelte`: first load and back to bottom `pageCap(-1)`;
  search jump `pageCap(max(messageIndex, 0))`; earlier `pageCap(end - 1)`
  and `pageOffset = page.offset`; more `pageCap(end)`. The window records
  `capped` (`windowCapped`), and a refresh asks for `refreshLimit(win,
  PAGE_SIZE)`: the window's own length when capped, else at least a page.
- `transcriptRefresh.ts`: `TranscriptWindow.capped`, set by `windowOf` and
  kept by `refresh` through a delta and through the full-page fallback;
  `refreshLimit`.
- `test/transcript-page-cap.test.mjs` (7 tests): `capPage` cases matching
  the Go ones; `pageCap`; the mock caps by size and rejects invalid caps;
  an earlier page ends right at the window (`offset + length = end`), a
  later page keeps its start, a jump keeps its match; a capped window
  refreshed after a new message asks for 2 messages by delta (no page
  call), stays capped, and stays capped through an older host's full-page
  fallback; uncapped windows still ask for ≥ 50; the desktop API calls
  `GetMessagesCapped` with a cap, `GetMessages` without one or on an older
  App binding; `TranscriptView` passes each request's anchor, uses
  `page.offset` and `refreshLimit`.
- `npm run check`: 0 errors. `npm test`: 1134 pass, 1 skipped (was 1127).
  `npm run build` succeeds. `go test ./internal/app/` (binding contract)
  passes.
- Not checked: scrolling, filling and jumps in a running app with real large
  sessions (PC-06); the mock's sample sessions are too small to be capped.
