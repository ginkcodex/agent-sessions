## Scope

`GetMessagesCapped` on the `engine.Backend` interface;
`GetMessagesParams.Cap` (`omitempty`); the server's `getMessages`
passes it to `GetMessagesCapped`; `rpc.Client.GetMessagesCapped` sends
it; `offlineBackend.GetMessagesCapped` keeps the offline error;
`App.GetMessagesCapped` binding and its name in `appBinding.ts`; test
fakes implement the new method.

## Likely files

`internal/engine/backend.go`, `internal/rpc/types.go`, `server.go`, `client.go`,
`dispatcher_test.go`, `internal/app/app.go`, `offline.go`,
`frontend/src/lib/appBinding.ts`, `api.ts` and `types.ts` (binding
signature and `PageCap` type).

## Acceptance criteria and tests

- RPC round trip with a cap returns the capped page; without the field the
  full page (as an older client sends).
- An older server's reply (full page) is valid for the new client: the
  params decode on a server without `Cap` (unknown fields ignored).
- Offline backend returns its error for the capped call.

## Evidence

- `engine.Backend` gains `GetMessagesCapped`. `rpc.GetMessagesParams.Cap`
  (`*engine.PageCap`, `omitempty`); the server's `getMessages` calls
  `GetMessagesCapped` when `Cap` is set, else `GetMessages`.
  `rpc.Client.GetMessagesCapped` sends the same method with `Cap`; no
  capability, since an older server ignores the field and returns the whole
  page. `offlineBackend.GetMessagesCapped` returns the offline error.
  `App.GetMessagesCapped` binding, `app.PageCap` alias, `GetMessagesCapped`
  in `APP_METHODS`. Frontend types: `PageCap`, `MessagesPage.capped`, and the
  optional `GetMessagesCapped` on `WailsAppBinding` (PC-04 uses it).

  capped request decodes into the old params shape. `dispatcher_test.go`
  mock implements the method. `internal/app/page_cap_test.go`: the binding
  passes the cap to the active backend; offline returns `ErrDisconnected`.
