## Scope

`GetMessagesCapped` on the `engine.Backend` interface;
`GetMessagesParams.Cap` (`omitempty`); the server's `getMessages`
passes it to `GetMessagesCapped`; `rpc.Client.GetMessagesCapped` sends
it; `offlineBackend.GetMessagesCapped` keeps the offline error;
`App.GetMessagesCapped` binding and its name in `appBinding.ts`; test
fakes implement the new method.

## Likely files

`internal/engine/backend.go`, `internal/rpc/types.go`, `server.go`, `client.go`,
`dispatcher_test.go`, `internal/app/app.go`, `offline.go`,
`frontend/src/lib/appBinding.ts`, generated bindings.

## Acceptance criteria and tests

- RPC round trip with a cap returns the capped page; without the field the
  full page (as an older client sends).
- An older server's reply (full page) is valid for the new client: the
  params decode on a server without `Cap` (unknown fields ignored).
- Offline backend returns its error for the capped call.
