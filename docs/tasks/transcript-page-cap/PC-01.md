# PC-01 — Measure first transcript pages by provider

- **Status:** ✅ Done
- **Estimate:** 1 h
- **Depends on:** —
- **Plan:** [transcript-page-cap.md](../../plan/transcript-page-cap.md)

## Scope

A read-only measurement test that loads each provider's sessions of one
project as a freshly started server does, and reports load times, the JSON
size of the viewer's first page (newest 50 messages), its bytes by part
kind, the largest message and the page a 256 KB cap would send. Run it on
`plgl`, `be`, and record the results.

## Likely files

`internal/provider/all/measure_load_test.go`, `docs/perf.md`.

## Acceptance criteria and tests

- Skipped unless `AS_MEASURE_CWD` is set; never writes agent data.
- Results in `docs/perf.md` (PC-01).

## Evidence

- `TestMeasureTranscriptLoad`: per provider a cold and warm `Scan`, then
  per session in the project the first `LoadIncremental` on a fresh
  provider, a second one, and one resumed from the first's state; totals,
  the `AS_MEASURE_TOP` (default 5) slowest sessions with first-page JSON
  size, largest message and capped page, and the largest first page by part
  kind.
- Run on `plgl` (binary in `/tmp`, deleted after), `be`: Codex first
  pages 0.44–1.29 MB, mostly tool output; with the cap 4–32 messages,
  ≤ 0.25 MB. Claude first pages unchanged by the cap. Numbers in
  `docs/perf.md` (PC-01).
- `go test ./internal/provider/all/` passes (the test skips without the
  variable).
- Not measured: transfer and render time in the desktop app (PC-06).
