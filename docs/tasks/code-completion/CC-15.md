## Done

- **Chrome harness** (`file-editor-chrome.test.mjs`):
  - `openChrome` handles the spawn `error` event, so a bad
    `AS_TEST_CHROME` fails at once with the path and the reason. Every step
    has a deadline: 20 s for the DevTools address, 10 s for the connection
    and for the page to mount the editor, 15 s per DevTools call. Any
    failure kills Chrome before it throws. Timers are cleared once settled.
  - Pending calls fail when the socket closes; a call on a closed socket
    fails at once.
  - `close()` waits for Chrome to exit (SIGKILL after 5 s), so the profile
    folder is removed after it.
  - `serve()` resolves the path inside `dist` and gives 404 for anything
    outside, and 400 for a malformed path.
  - All three tests use `caretToEnd`.
  - Fixed sleeps became `until(read, ok, what)`, which polls with a deadline
    and fails with the last value read. Two named waits stay, on purpose:
    - `settle()` (400 ms), where nothing should happen (setting off,
      read-only, no second ask, a late import);
    - `newUndoStep()` (600 ms), past the history's 500 ms group delay, where
      a test needs typing to be its own undo step.
  - `acceptable()` waits until the popup's items have held still for
    150 ms before Tab or Enter. CodeMirror ignores accept keys for its
    `interactionDelay` (75 ms) after the options change. With polling
    alone, Tab indented and Enter broke the line.
  - The resolve test's fake `resolveEdits` waits at a gate. The test opens
    it after its keystrokes, instead of a 150 ms timer. The "typed during
    the wait" case now also checks that the import answered afterwards adds
    nothing.
  - The snippet test checks each undo step: `;` first, then `X`, then the
    item with its import.
- **jsdom and store tests:**
  - `live-lifecycle-integration.test.mjs` counts `complete()` calls (0) for
    the harness without the capability and for a Markdown file;
  - `assert.equal` for the cancel count;
  - the keymap test finds the Tab accept binding by key;
  - the snippet click-elsewhere step asserts there is a next field before,
    none after, and one selection range.
- **Settings:** the dialog test already rendered the checked and unchecked
  states. A new test loads `PreferencesStore` with a fake `localStorage`:
  on by default, off read back, on again, and on when storage throws.

## Evidence

Run on macOS arm64, 2026-11-18:

- Headless Chrome (Google Chrome, `file-editor-chrome.test.mjs`): 3 pass in
  7 runs in a row. Before `acceptable()`, 3 runs failed the same 2 tests the
  same way (Tab indented, Enter broke the line), which is how the
  interaction delay was found.
- `AS_TEST_CHROME=/nonexistent`: all 3 fail in 0.8 s with
  `Chrome did not start (/nonexistent): spawn /nonexistent ENOENT`.
- A page that never loads (`http://127.0.0.1:9/`), run through
  `openChrome` alone: fails after 10.4 s with `timed out waiting for the
  page … to mount the editor`. No Chrome process was left for its profile.
- `serve()` through raw HTTP requests: `/` and `/index.html` give 200.
  `/../secret.txt`, `/%2e%2e/secret.txt`, `/%2F..%2Fsecret.txt` and
  `/..%5Csecret.txt` give 404, and a malformed escape gives 400.
- Frontend: `npm test` (1596 pass, 4 skipped, 0 fail), `npm run check` (0
  errors), `npm run build`. No Go code changed.

Not checked:

- A DevTools socket that closes mid-call. The code path was read, not
  forced.
- The harness on Windows or Linux Chrome.
