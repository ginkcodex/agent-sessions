# CC-08 — ruby-lsp completion and Pyright auto-imports

- **Status:** ⬜ Not started
- **Estimate:** 2 h
- **Depends on:** CC-06
- **Plan:** [code-completion.md](../../plan/code-completion.md)

## Goal

Ruby files get language-server completion, and Python completion suggests
names from modules not imported yet, without asking for approval again.

## Approval

Both settings are part of the server's fingerprint. A project is approved
once, and its grant carries over to a new fingerprint (`GrantStore.lookup`
for "Always allow", `Trust.lookup` for this session's approval), so an
approved project stays approved. Running Ruby and Python servers end their
leases and restart once with the new settings.

## Scope

- `rubyLspOptions` in `ruby_lsp.go`: `"completion": true`. The other
  features stay as they are.
- `pyrightSettings` in `pyright_lsp.go`: `"autoImportCompletions": true`.
- Update the golden policy tests and the comments that explain the
  settings.
- Check the ruby-lsp evidence notes (`testdata/ruby-lsp/evidence.json`) for
  anything completion depends on, such as indexing state; an empty answer
  while ruby-lsp indexes should look like no suggestions, not an error.

## Done when

- ruby-lsp advertises `completionProvider` with the new options, and a
  Ruby file gets server suggestions.
- Pyright offers an auto-import item whose extra edit adds the import.
- A Ruby and a Python project approved with the old settings, both "Always
  allow" and this session only, are still approved with the new ones.

## Tests

- Go tests for the new settings and policy hashes.
- Grant carry-over tests from the old to the new fingerprint, for both
  approval modes, with the real Pyright and ruby-lsp server configs.
- Real-server check with ruby-lsp and Pyright (may be done in CC-09).
