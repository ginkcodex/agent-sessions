# CC-13 — Review fixes: completion on the host

- **Status:** ✅ Done
- **Estimate:** 3 h
- **Depends on:** CC-02, CC-03, CC-10
- **Plan:** [code-completion.md](../../plan/code-completion.md)

## Found by

A code review of the `feature/code-completion` branch.

## Scope

- **Conflicting extra edits.** An item whose `additionalTextEdits` overlap
  each other or the main edit is dropped from the answer, as an item with
  an out-of-range edit is. Today the overlapping edit alone is dropped, so
  part of an import could go in. Resolved edits (CC-10) are all or none in
  the same way: an overlap drops them all.
- **Resolve checks the document it asked about.** After the server
  answers, the edits are kept only if the document is still the same open
  lifecycle (the same `documentState`) at the version asked. Document IDs
  are never reused (`closedDocs`), so this is a guard, not a fix of a seen
  failure.
- **Kept raw items are bounded.** A session keeps each open URI's last
  answer as the server's raw JSON for `completionItem/resolve`. Only the
  normalized text is capped (2 MiB), so 64 open documents could keep up to
  64 frames of 8 MiB. Cap the raw bytes a session keeps across its URIs:
  keeping a new answer drops the oldest other answers first, and an answer
  larger than the cap keeps only the items that fit. Items past the cap
  are not resolvable: the info panel shows the listed details.
- **Comment.** `lspSession.completions` says a change drops the kept
  answer; since CC-10 it does not.

## Not changed

- The review suggested also checking, after a resolve, that the kept
  answer is still `resultID` and that the route still answers at the
  version. Edits are checked against the text of that version, and a
  document's text at a version never changes, so a newer answer or a
  restarted server does not make them wrong.

## Done when

- An item with overlapping extra edits is not offered; resolved edits that
  overlap are all dropped.
- A session's kept raw completion items never exceed the cap.

## Tests

- Go: overlapping listed edits (with each other and with the main edit)
  drop the item; overlapping resolved edits give none; the kept-bytes cap
  evicts the oldest other answer, trims one oversized answer, and an item
  past it resolves to `staleVersion`; a closed and replaced document does
  not get edits.

## Done

- `completionItem` (`lsp_completion.go`) leaves out an item whose extra
  edits overlap each other or the main edit; edits that only touch are
  kept. `resolvedEdits` returns none when any two overlap.
- `ResolveCompletion` keeps the edits only if the open document is the same
  `documentState` the request was routed to, at the version asked
  (`resolveRoute` returns it).
- `keptItems` records each answer's raw bytes and a sequence number.
  `keepCompletion` keeps at most `maxKeptCompletion` (8 MiB) per session:
  an answer keeps the items that fit, then other URIs' answers are dropped,
  oldest first. A pending request's slot holds no bytes and stays. An item
  past the cap is not kept, so its resolve fails with `staleVersion`
  (`completionGone`) and the info panel shows the listed details.
- The `lspSession.completions` comment and the plan say what is kept and
  dropped.
