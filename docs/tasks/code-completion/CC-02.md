# CC-02 — Language server completion requests

- **Status:** ⬜ Not started
- **Estimate:** 4 h
- **Depends on:** —
- **Plan:** [code-completion.md](../../plan/code-completion.md)

## Goal

Ask the running language server for completions at a position in an open
document, with validated and bounded answers, in the same way NAV-01 asks
for definitions.

## Scope

- `initializeParams` (`lsp_session.go`) declares `textDocument.completion`:
  `contextSupport: true`; `completionItem` with `snippetSupport: false`,
  `documentationFormat: ["markdown", "plaintext"]`, `labelDetailsSupport`,
  `deprecatedSupport`, `tagSupport` (deprecated),
  `resolveSupport.properties: ["documentation", "detail"]`; and
  `completionItemKind.valueSet` 1–25. No `insertReplaceSupport`.
- `ServerCapabilities` gains `Completion`, `CompletionTriggers` (capped at
  32 single characters) and `CompletionResolve`, read from
  `completionProvider` by `negotiateCapabilities`.
- New `internal/codediagnostics/lsp_completion.go`:
  - `Manager.Complete(ctx, c, documentID, version, position, trigger)`.
    `trigger` is `invoked`, or `character` with the character. The route
    checks are `navigationRoute`'s; of several owners, the one that offers
    completion answers.
  - `SessionDocuments.Complete` sends `textDocument/completion` with the
    completion context, and a 5 s timeout with `$/cancelRequest`.
  - Normalization reads `CompletionItem[]` and `CompletionList`. Kept:
    label, label details, kind, detail, sortText, filterText, insertText or
    textEdit (one range), insertTextFormat, additionalTextEdits, deprecated.
    Dropped: `command`, `commitCharacters`, items whose ranges are invalid
    or whose main edit does not cover the position on its line, extra edits
    that overlap the main edit or each other.
  - Caps: 2,000 items (more sets `isIncomplete` and `truncated`), 1 KiB per
    short field, 64 KiB of documentation, 2 MiB per answer, 100 extra edits
    per item.
- Errors use navigation's codes (`navigationCallError`).

## Done when

- A fake server's answers in both forms come back normalized; caps,
  dropped items and ranges behave as described.
- Stale version, a position outside the text and a missing capability fail
  before reaching the server.
- `ServerConfig.Policy()` does not change (golden test).

## Tests

- `lsp_completion_test.go` with the fake server used by
  `lsp_navigation_test.go`: both answer forms, every cap, invalid and
  overlapping ranges, Ruff/Pyright routing, timeout with cancel on the fake
  clock, server errors, not running.
- Capability negotiation and initialize-params tests.
- `go test ./internal/codediagnostics/...`, `golangci-lint`.
