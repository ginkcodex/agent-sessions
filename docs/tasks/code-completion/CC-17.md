# CC-17 — Review fixes: late answers, awaited items and language labels

- **Status:** ⬜ Not started
- **Estimate:** 3 h
- **Depends on:** CC-06, CC-12, CC-14
- **Plan:** [code-completion.md](../../plan/code-completion.md)

## Found by

A second code review of the `feature/code-completion` branch.

## Scope

All in `fileEditor.ts`:

- **A cancelled query writes nothing.** `codeSuggestions` records the
  learned trigger characters and the unfinished word from an answer even
  when CodeMirror aborted the query. Only the 1.5 s timeout is covered
  today. A stale unfinished entry makes the next keystroke ask as
  `incomplete` instead of `invoked`. An aborted query writes nothing, and
  the unfinished word is kept only while the document is the one asked
  about.
- **An awaited item whose word is gone goes nowhere.** After typing during
  the import wait (CC-12), the item replaces the mapped range. When the
  user deleted or replaced the whole word meanwhile, that range is empty,
  and the item would still be put in there. A pick whose range was not
  empty and is now empty is dropped.
- **Language labels without doing the work twice.** `languageLabels` runs
  each language source again to know its labels. That second run has no
  link to the query's cancellation, and for an async source it does the
  whole work for nothing. A source seen to answer with a promise is not run
  again for labels. Words it offers may then repeat its items, which
  CodeMirror shows as two rows; no language package used here answers
  asynchronously today.

## Done when

- An answer for an aborted query leaves the trigger and unfinished state as
  they were.
- Deleting the word during the wait puts nothing in; typing elsewhere still
  does (CC-12).
- An async language source is run once per query, not twice.

## Tests

- `file-editor.test.mjs` (jsdom): an aborted query's answer does not
  change the next trigger kind; a deleted or replaced word during the wait
  gets no item, and undo history is unchanged; an async language source
  runs once per query after its first answer.
