# CC-01 — Completion without a language server

- **Status:** 🟡 Partial: Cmd+I and Option+\` / Option+I not yet checked in the native macOS app
- **Estimate:** 4 h
- **Depends on:** —
- **Plan:** [code-completion.md](../../plan/code-completion.md)

## Goal

A completion popup in the Go to File editor that works in every project and
on every host: words from the open file and the completions CodeMirror's
language packages provide.

## Scope

- Add `@codemirror/autocomplete` to `frontend/package.json` as a direct
  dependency, at the version the language packages already use.
- In `fileEditor.ts`, add `autocompletion()` in a new compartment:
  - `activateOnTyping` follows the setting.
  - Our own trigger keymap instead of CodeMirror's `completionKeymap`
    entries for `startCompletion`: Cmd+I on macOS, with Ctrl+Space as a
    second key; Ctrl+Space on Windows and Linux. Option+\` and Option+I
    are not bound (dead keys on the US layout; they also disturb Vietnamese
    input). The other completion keys (arrows, Page Up/Down, Enter,
    Escape) stay CodeMirror's.
  - Check in the macOS app that Cmd+I reaches the editor and is not taken
    as italic by the web view or the app menu. If it is taken, use
    Option+Esc instead and update the plan.
  - Sources: the language's own data (`languageData` autocomplete) and a
    word source for the document. The word source returns nothing for
    documents over `HIGHLIGHT_LIMIT`.
  - No popup while the editor is read-only (`disabled`).
- Keys: the completion keymap goes before `indentWithTab`. Enter and Tab
  accept; Escape closes the popup first. `handleKey` must not treat that
  Escape as closing a hover, the search panel or the dialog.
- Theme the popup (`.cm-tooltip-autocomplete`, selected row, detail, info
  panel) with the app's CSS variables for light and dark, using the editor
  font.
- Setting: `PreferencesStore.suggestWhileTyping` (on by default, its own
  storage key), shown as "Suggest code while typing" in a new Editor section
  under Settings › General. Changing it reconfigures open editors.

## Done when

- Typing a prefix of a word in the file offers it; typing in a CSS file
  offers properties; Enter and Tab insert the choice.
- With no popup, Tab indents and Escape keeps its old meaning.
- With the setting off, typing opens nothing and the shortcut still does
  (Cmd+I on macOS, Ctrl+Space elsewhere).
- Option+\` and Option+I type their accents as before.
- Large and read-only documents show no word suggestions.

## Evidence

Done on `feature/code-completion` (2026-11-18):

- `@codemirror/autocomplete` ^6.20.4 is a direct dependency (the version
  already installed).
- `fileEditor.ts`:
  - `completing` compartment with one extension per mode: typing, shortcut
    only (setting off), or none (read-only). The same extension is reused on
    every `update`, so an open popup survives the per-keystroke options.
  - `completionKeys`, at `Prec.highest`, before `indentWithTab`:
    - Cmd+I (macOS) and Ctrl+Space open suggestions. Option+\` and Option+I
      are not bound.
    - CodeMirror's arrows, Page Up/Down and Escape.
    - Tab accepts.
    - Enter (`acceptOrBreakLine`) accepts, except when the selected item is
      exactly the name just typed; then it closes the popup and breaks the
      line.
  - `documentWords` wraps `completeAnyWord`. It returns nothing over
    `HIGHLIGHT_LIMIT`, leaves out the complete typed word and leaves out
    names the language's own sources answer with at once. CodeMirror's own
    merge misses CSS properties, whose `apply` is `name: `.
  - `handleKey` closes suggestions on Escape before a hover, the search
    panel or the dialog.
  - Popup theme: editor font, app colours, details panel not clipped.
- `PreferencesStore.suggestWhileTyping`
  (`agent-sessions:suggest-while-typing`, on by default). Settings ›
  General › Editor shows "Suggest code while typing", with the platform's
  shortcut in the hint. `FileEditor.svelte` passes it as `suggest`.
- Found by the Chrome check and fixed: in a JS file, after typing a declared
  name in full, the language still offered that exact name, so Enter
  accepted a no-op instead of breaking the line.
