# CC-20 — Review fixes: say which answers resolve, and an empty trigger list

- **Status:** ⬜ Not started
- **Estimate:** 3 h
- **Depends on:** CC-04, CC-06, CC-12
- **Plan:** [code-completion.md](../../plan/code-completion.md)

## Found by

A third code review of the `feature/code-completion` branch (`/code-review develop...feature/code-completion`), checked against the code before this task was written.

## Scope

- **Only answers that resolve wait on accept.** Every answer with a
  `ResultID` gets `resolveEdits` in the editor, so accepting any server item
  without listed edits closes the popup and waits for a flush and a resolve,
  even from servers without `completionItem/resolve` (gopls), which can
  never add an import that way. Typing during that wait puts a snippet in
  as plain text. `CompletionResult` gains `resolves` (the answering
  server's `resolveProvider`, set by the Manager). The store gives extra
  edits, and `FileViewer.svelte` gives `resolveEdits`, only for such
  answers; an older host, which does not send it, gets none, as before
  CC-10.
- **The "typed in full" guess** (`itemText`) applies only to answers that
  resolve: an item that names a module (`labelDescription`) on a server
  that resolves may still add an import. Other servers' items with a label
  description break the line after a word typed in full again.
- **An empty trigger list is sent.** `triggerCharacters` has `omitempty`, so
  a server without trigger characters sends none, and the editor keeps
  asking after every likely trigger (`.`, `(`, `"`, `:` and so on), each
  time flushing pending typing. The field is always sent; an empty string
  means none.

## Done when

- Accepting a gopls item applies at once, with no resolve.
- A vtsls item still waits for its import.
- A server without trigger characters is asked after none.

## Tests

- Go: `resolves` follows `resolveProvider`; `triggerCharacters` is present
  and empty in the JSON of an answer from a server without them; RPC
  carries `resolves`.
- Frontend: the store gives no extra edits and no resolve for an answer
  without `resolves`; the editor applies a server item at once without
  `resolveEdits`; Enter after a word typed in full breaks the line for an
  item with a label description from a server that does not resolve; an
  empty trigger list stops asking after `.`.
