# CC-03 — Completion item details

- **Status:** ✅ Done
- **Estimate:** 2 h
- **Depends on:** CC-02
- **Plan:** [code-completion.md](../../plan/code-completion.md)

## Goal

Show an item's documentation and full detail when it is selected, without
sending the server's opaque item data to the frontend.

## Scope

- `Complete` gives each answer a result ID. The session keeps the raw items
  of the last answer per document; a newer answer, a document change or
  close, or a session restart drops them.
- `Manager.ResolveCompletion(ctx, c, documentID, resultID, index)` sends
  `completionItem/resolve` with the kept item, when the server offers
  resolve, and returns only `detail` and `documentation`, capped as in
  CC-02. A server without resolve returns what the list already had.
- An unknown or dropped result ID fails with `staleVersion`.
- Resolved `additionalTextEdits` are ignored. Applying them would need the
  edit checks again, and gopls and vtsls send them in the list already.

## Done when

- Resolve returns the server's documentation for a kept item, and
  `staleVersion` after the document changed or a new answer replaced it.
- At most one answer per document is kept, and memory is released on
  close.

## Tests

- Fake-server tests: resolve round trip with `data`, no resolve provider,

- `go test ./internal/codediagnostics/...`.

## Done

- `lsp_completion_resolve.go`: `Manager.ResolveCompletion`,
  `SessionDocuments.ResolveCompletion`, `LiveDocuments.ResolveCompletion`,
  `CompletionDetails` (with `Validate`) and the session's kept items.
- Result IDs come from a per-session counter. A request takes its URI's slot
  when it starts, so an earlier request that answers later is not kept. The
  slot is dropped on a document change, open, close and on errors; a
  restarted session is another generation, so its old IDs are
  `staleVersion`.
- The Manager keeps one `keptAnswer` per document (result ID, item count,
  version, owner, generation), ordered by a request sequence. Resolve checks
  the ID, version and index before anything reaches a server. An unknown ID
  is `staleVersion`; an empty or overlong ID, or an index outside the
  answer, is `invalidArgument`.
- The text-range check of edits moved from the Manager into the provider
  (`CompletionRequest.Text`, a lazy per-line `lineIndex`), so kept raw
  items stay aligned with the indexes the frontend sees.
- Fields the resolved item leaves empty keep the list's values. Resolved
  `additionalTextEdits` are ignored. Server error text is not passed on.
