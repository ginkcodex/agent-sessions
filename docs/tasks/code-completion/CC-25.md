## Scope

- **A caller's abort.** `resolveAt` shares one resolve between callers. When
  one caller aborts while another still waits (the info panel moves on
  while an accept waits for the import), the aborting caller only drops its
  count and keeps waiting on the shared promise; `details` then returns the
  resolved details to a caller that gave up. CodeMirror drops info for a
  changed completion state, so nothing stale shows today, but the doc
  comment says each caller waits only until its signal aborts. Each caller
  gets its own promise that rejects at its abort.
- **Retention test.** The test that only version 0 and the latest version
  are kept reads the store's private maps through `gc()` and `WeakRef`,
  with `v8.setFlagsFromString('--expose-gc')` at run time. A single GC is
  not guaranteed to clear a WeakRef, so the test can turn flaky. The
  per-answer resolve cache moves to its own module with a `keys()` view,
  and the retention test checks it directly.

## Done when

- An aborted caller's promise rejects at once while others keep waiting.
- No test uses `gc()` or `setFlagsFromString`.
