## Scope

- **An awaited item at an empty range goes before what was typed.** An item
  accepted right after a trigger character (`obj.`) replaces nothing. While
  its import is awaited, its range is mapped with `from` to the right and
  `to` to the left; on an empty range both end up after typed text, so
  `obj.` + accept `foo` + `x` gives `obj.xfoo`. An empty range is mapped to
  the left, so the item goes before the typed text: `obj.foox`.
- **The language's own sources run once per query.** `languageLabels` runs
  each language source that answers at once again, beside CodeMirror's own
  run, to leave its names out of the document's words. The labels are read
  from a single run instead, shared with CodeMirror's.

## Done when

- `obj.` + accept + `x` during the wait gives `obj.foox`.
- Per query, each language source runs once.

## Tests

- Frontend (jsdom): the empty-range case, with typing during the wait;
  a counting language source runs once per query, and its names still
  stay out of the words.

## Evidence

- Cost measured first (Node, `@codemirror/lang-javascript` with TypeScript
  and `lang-python`, a 4,000-line file, the caret at the end): the
  language's sources took about 1 ms per keystroke (median; up to 3 ms),
  so running them twice cost as much again. Across all of
  `@codemirror/language-data` and the Svelte package, no position has
  more than two `autocomplete` sources.
- Empty range: `pendingPick` maps an empty range's start with assoc -1,
  so the awaited item stays before text typed at its place.
- Sources run once: the editor lists its sources itself (`override`):
  `LANGUAGE_SLOTS` (8) stable slots that run the language's sources at the
  position, in their order, then `codeSuggestions`. `runLanguageSource`
  keeps a source's at-once answer per state, position and kind of query,
  and the words' `languageLabels` reads it from there, so each source runs
  once per query. A word list a language gives is run as
  `completeFromList`. Our own `languageData` entry is gone.
- Tests (`file-editor.test.mjs`):
  - new: an item after `obj.` awaited while `x` is typed gives `obj.foox`,
    with the caret after the typing;
  - new: running `completionSources` as CodeMirror runs a query (a context
    per source, in order) runs a counting language source once, and its
    label is left out of the words; the next keystroke runs it again;
  - changed: the same state and position reuse a source's answer (it was
    run on every call before); the checks that `codeSuggestions` is in
    `languageData` are gone, the behaviour checks around them stay.
  - Each new check failed with the old code put back (the memo off, the
    old mapping).
- Runs: `npm test` 1604 pass, 0 fail; `npm run check` 0 errors; `npm run
  build` OK; Chrome tests 3 pass (the real popup with language sources,
  words and a server).
- Not checked: CodeMirror's own query loop counting runs in a real
  browser (the jsdom tests use a stub view, so the query is run as
  CodeMirror runs it); native GUI.
