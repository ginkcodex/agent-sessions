# CC-09 — Real-server and SSH QA

- **Status:** 🟡 Partial (local real servers done; not yet: SSH latency, native GUI and IME checks, rust-analyzer, Intelephense, JDT LS, Windows and Linux)
- **Estimate:** 3 h
- **Depends on:** CC-07, CC-08
- **Plan:** [code-completion.md](../../plan/code-completion.md)

## Goal

Check completion against real language servers and a real remote host, and
record what was and was not checked.

## Scope

- For each server: gopls, Pyright, vtsls (TS and JS), rust-analyzer, Svelte,
  Intelephense, JDT LS, ruby-lsp. Check member completion after `.`,
  completion of a project symbol, an item that adds an import, a snippet
  item, item details, and filtering while typing on.
- CC-08's checks: with its options, ruby-lsp advertises `completionProvider`
  and suggests in a Ruby file, and while it indexes it shows nothing and no
  error. Pyright offers an auto-import item whose extra edit adds the import.
  A Ruby and a Python project approved before CC-08 are still approved.
- Measure the time from keystroke to popup on a local project and on an SSH
  host, with a large TS project to exercise the item cap.
- Check keyboard behaviour in the Go to File dialog: the shortcut (Cmd+I on
  macOS, Ctrl+Space elsewhere), Tab, Enter and Escape with and without a
  popup, and IME input (Vietnamese and Japanese) not
  being disturbed by the popup.
- Native GUI checks on macOS, Windows and Linux only where they actually
  run; list the rest as not checked.

## Done when

- `## Evidence` lists each server and check with its result, the measured
  latencies, and what was not checked. Problems found become new CC tasks.

## Done

- `internal/engine/code_diagnostics_completion_qa_test.go` (new),
  `TestLocalLiveRealCompletionQA`. It goes through the production local
  route: discovery (`DiscoverLocalLive`), approval for this session, an
  opened draft, then `ChangeCodeDiagnosticDocument` and `CompleteCode` the
  way the editor sends them (CC-05), and `ResolveCodeCompletion`. Each
  probe is a draft with a caret, a trigger and the item looked for. The
  test retries until the server has indexed, then resolves the item and
  times five warm asks. Finally it checks that no file on disk changed.
  Each case is a throwaway project, or an existing one opened as a draft
  only (`AGENT_SESSIONS_COMPLETION_QA_PROJECT`). It is opt-in
  (`AGENT_SESSIONS_COMPLETION_QA=1`) and never installs anything.
  `AGENT_SESSIONS_COMPLETION_QA_DIRS` adds directories to search, such as
  the app's managed tools, and `AGENT_SESSIONS_COMPLETION_QA_ONLY` picks
  cases. A probe for a known gap names its task and is logged, not failed.
  Once the gap's item is found, the test fails until the marker is removed.
- Two problems found became tasks:
  [CC-10](CC-10.md), where the vtsls import edit arrives only on resolve,
  and [CC-11](CC-11.md), where Pyright does not suggest names from project
  files that are not open.

## Evidence

`AGENT_SESSIONS_COMPLETION_QA=1`, the app's managed Pyright 1.1.414, vtsls
0.3.0, svelte-language-server 0.18.5 and Node 24.22.1 in
`AGENT_SESSIONS_COMPLETION_QA_DIRS`, and this repository's `frontend/` as
`AGENT_SESSIONS_COMPLETION_QA_PROJECT`. gopls v0.23.0 and ruby-lsp 0.26.11

and the two known gaps were logged.

counts the server's indexing after the document opened. "Warm" is the
median and maximum of five more asks, each a change plus a request. All

- CC-08's checks: ruby-lsp, run with the shipped options, answers
  completion. While it indexes, it gives one empty answer and no error, and
  the next ask has the item. Pyright gives an auto-import item whose extra
  edit adds the import (`DefaultDict`). Approval carries over for a Ruby and
  a Python project approved before CC-08: `TestCompletionSettingsKeepApproval`,
  recorded in [CC-08](CC-08.md).
- Pyright's cause was confirmed by a one-off run with
  `diagnosticMode: workspace` (reverted, never committed). It then gave
  `helper_value` with `from helpers import helper_value`. vtsls's cause was
  confirmed in its source: `completionEntryDetails` sets
  `additionalTextEdits` only on resolve.
- Pyright does not offer `collections.defaultdict`, because it imports only
  from modules it has loaded. That is upstream behaviour, so the probe uses
  `typing.DefaultDict`.
- No file on disk changed in any case. `git status` of `frontend/` was
  clean after the run.
- `go vet ./internal/engine/` is clean, and the test is gofmt-clean.
- Keyboard behaviour (the shortcut, Tab, Enter, Escape, with and without a
  popup) was checked with real key events in headless Chrome. That is
  `file-editor-chrome.test.mjs`, recorded in CC-01 and CC-07; it is not a
  native check.

Not checked:

- **SSH latency:** keystroke to popup on a real SSH host needs a host and
  the user's go-ahead.
- **Native GUI:** Cmd+I in the macOS web view (CC-01), popup timing in the
  app, and IME input (Vietnamese, Japanese) with the popup open.
- **Not installed here:** rust-analyzer (the rustup proxy is present, but
  the component is not, and the snapshot correctly says `missingTool`),
  Intelephense and JDT LS. Their cases are in the QA (Rust) or still to
  write (PHP, Java).
- **Platforms:** Windows and Linux, native.
