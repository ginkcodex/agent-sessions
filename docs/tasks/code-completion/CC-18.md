## Scope

- **One place for the suggestion shortcut.** Settings' label
  (`ManageSettingsDialog.svelte`) and the editor's binding
  (`completionKeys`) are written down twice and can drift apart. A small
  module, `editorKeys.ts`, holds both keys and the label. The editor is
  loaded lazily, so Settings must not import `fileEditor.ts`. The platform
  check is CodeMirror's own (`/Mac/` on `navigator.platform`, deprecated
  but what `@codemirror/view` 6 reads), so the label always names the key
  that is bound.
- **The mock checks positions** as the host does: integer, not negative,
  inside the document. One helper for `completeCode` and `navigateCode`.
- **Tests:**
  - `settings.test.mjs`: the store test added in CC-15 repeats one in
    `code-languages.test.mjs`, which covers more; it is removed. The
    checkbox's handler is checked by changing the rendered checkbox, not
    by matching its source text.
  - `live-documents.test.mjs`: the gate opens in `finally`, and the test
    with the timer that fires at once checks no timer is left; `const`
    for a gate never reassigned.
  - `file-editor-chrome.test.mjs`: one `withEditor(text, path, fn)` sets
    up and cleans up each test and gives the shared helpers (popup, text,
    keys, platform).

## Done

- `src/lib/editorKeys.ts` holds `SUGGEST_KEY_MAC` (`Cmd-i`), `SUGGEST_KEY`
  (`Ctrl-Space`), `macKeys(platform)` (CodeMirror's `/Mac/` check on
  `navigator.platform`) and `suggestShortcutLabel(platform)` (`⌘I` or
  `Ctrl+Space`). `completionKeys` binds the two keys from it, and Settings
  shows the label from it. Settings no longer matches `iPhone` or `iPad`,
  which CodeMirror's platform check does not match either.
- The mock's `lineAt` checks a position for `completeCode` and
  `navigateCode`: whole numbers, not negative, inside the text (the end of a
  line counts as inside). Anything else fails with `invalidArgument`.
- Tests:
  - New `settings-client.test.mjs` mounts the real Settings dialog in jsdom
    with stub sub-components and fixture stores. Clicking "Suggest code while
    typing" calls `setSuggestWhileTyping(false)`, and clicking again calls
    `setSuggestWhileTyping(true)`. The hint names the label. A second test
    ties the label to the keys: `macKeys` for several platforms, and both
    keys spelled as the label. `file-editor.test.mjs` checks that
    `completionKeys` binds the keys from `editorKeys.ts`.
  - `settings.test.mjs`: the duplicate store test and the source-regex check
    are removed. Its server-rendered dialog maps `editorKeys`.
  - `code-completion.test.mjs` and `code-navigation.test.mjs`: the mock
    refuses a negative, fractional or `NaN` character, a negative or
    fractional line, a character past the end of the line, and a line past
    the end of the text. The end of a line is accepted.
  - `live-documents.test.mjs`: the gate opens in `finally`. The
    fires-at-once test then checks that no timer is left and that the
    change was sent once. The pause case's gate is `const`.
  - `file-editor-chrome.test.mjs`: `withEditor(text, path, fn)` builds,
    serves and opens the page, and gives `evaluate`, `press`, `type`,
    `popup`, `text` and `isMac`. Afterwards it closes Chrome, closes the
    server (waiting for it now) and removes the directory.
