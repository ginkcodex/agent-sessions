# CC-05 — Send pending typing before completion

- **Status:** ✅ Done
- **Estimate:** 3 h
- **Depends on:** —
- **Plan:** [code-completion.md](../../plan/code-completion.md)

## Goal

A completion request must see the text the user just typed, without waiting
for the 300 ms draft debounce.

## Scope

- `LiveDocuments.flush(path, bound)` in `liveDocuments.ts`: when a change
  is waiting on its debounce timer, cancel the timer and queue it now. The
  call resolves with the basis once the server confirmed that version and it
  is synced, or `undefined` after `bound` ms, on failure, while paused or
  saving, or when the document is not live.
- Nothing changes for callers that do not flush: same debounce, same
  ordering of changes and saves, same recovery.
- A store helper in `stores/codeDiagnostics.svelte.ts`, such as
  `completionBasis(path)`, that flushes and checks the attachment is still
  current, for CC-06.
- Navigation keeps its polling wait. Moving it to `flush` is optional and
  stays out of this task unless it is a one-line change with tests.

## Done when

- A flush right after typing sends the change at once and resolves with the
  new version; a second flush with nothing pending resolves at once.
- A flush during a save waits for the save, as typing does today.
- A flush on a failed, paused or untracked document resolves `undefined`.

## Tests

- `liveDocuments` tests with fake timers: flush before the debounce, flush
  with a change in flight, during save, after failure, after pause, bound
  expiry, and that the debounce path is unchanged.
- `npm test`, `npm run check`.

## Done

- `LiveDocumentBridge.flush(path, bound)` (`frontend/src/lib/liveDocuments.ts`):
  when the document's typing waits on its debounce timer, the timer is
  canceled and the change queued at once, through the same `queueChange`
  the timer uses, so ordering, coalescing and recovery are unchanged. It
  resolves with the basis once the confirmed version is synced; with
  `undefined` after `bound` ms, when the document fails, is not tracked or
  not live, while paused, or when the attachment changes. Nothing pending
  resolves at once, with no timer and no call.
- Changed from the scope: a flush during a save waits for the save (as the
  "Done when" asks) instead of resolving `undefined`; once the save settles,
  the held typing is sent at once. Typing during the wait is flushed too. A
  lifecycle replaced by recovery is followed by path, so the basis may name
  a new document ID. The wait re-checks after each bridge change in a
  microtask, because recovery closes and reopens a path within one call.
- Store (`stores/codeDiagnostics.svelte.ts`): `completionEnabled`
  (`liveCodeDiagnostics` and the new `codeCompletion` capability, cleared on
  detach and disconnect), `setLiveFlush`, and
  `completionBasis(path, bound = COMPLETION_SYNC_WAIT)` (1 s), which returns
  `{ context, host, basis }` only while completion is enabled and the same
  attachment is current, and never throws. `liveDocumentsWiring.ts` connects
  it to the bridge.
- Navigation keeps its polling wait.
