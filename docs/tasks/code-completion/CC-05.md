# CC-05 — Send pending typing before completion

- **Status:** ⬜ Not started
- **Estimate:** 3 h
- **Depends on:** —
- **Plan:** [code-completion.md](../../plan/code-completion.md)

## Goal

A completion request must see the text the user just typed, without waiting
for the 300 ms draft debounce.

## Scope

- `LiveDocuments.flush(path, bound)` in `liveDocuments.ts`: when a change
  is waiting on its debounce timer, cancel the timer and queue it now. The
  call resolves with the basis once the server confirmed that version and it
  is synced, or `undefined` after `bound` ms, on failure, while paused or
  saving, or when the document is not live.
- Nothing changes for callers that do not flush: same debounce, same
  ordering of changes and saves, same recovery.
- A store helper in `stores/codeDiagnostics.svelte.ts`, such as
  `completionBasis(path)`, that flushes and checks the attachment is still
  current, for CC-06.
- Navigation keeps its polling wait. Moving it to `flush` is optional and
  stays out of this task unless it is a one-line change with tests.

## Done when

- A flush right after typing sends the change at once and resolves with the
  new version; a second flush with nothing pending resolves at once.
- A flush during a save waits for the save, as typing does today.
- A flush on a failed, paused or untracked document resolves `undefined`.

## Tests

- `liveDocuments` tests with fake timers: flush before the debounce, flush
  with a change in flight, during save, after failure, after pause, bound
  expiry, and that the debounce path is unchanged.
- `npm test`, `npm run check`.
