# CC-04 — Completion over the wire

- **Status:** ⬜ Not started
- **Estimate:** 3 h
- **Depends on:** CC-02, CC-03
- **Plan:** [code-completion.md](../../plan/code-completion.md)

## Goal

Make completion, resolve and cancel available to the frontend for local
projects and over SSH and WSL, as NAV-02 did for navigation.

## Scope

- `engine.CodeCompletionBackend`, its own interface so the diagnostics and
  navigation contracts do not change. The local engine and `rpc.Client`
  implement it.
- App bindings, routed through `liveRoute` with the host and epoch checks:
  - `CompleteCode(context, requestId, documentId, version, position, trigger, expectedHostId)`
  - `ResolveCodeCompletion(context, documentId, resultId, index, expectedHostId)`
  - `CancelCodeCompletion(context, requestId, expectedHostId)`: cancels the
    request's context; an unknown ID is a no-op.
- RPC: `completeCode`, `resolveCodeCompletion` and `cancelCodeCompletion` in
  the live method list with the ownership check. A `codeCompletion`
  capability is set only with `liveCodeDiagnostics`. The client refuses an
  older server before any work, and checks the answer matches the request.
- Frontend: types, `api.completeCode`, `api.resolveCodeCompletion` and
  `api.cancelCodeCompletion`; the mock backend in
  `frontend/src/lib/mock/codeDiagnostics.ts`; regenerated bindings.

## Done when

- A local and a fake remote request return the same normalized answer.
- Cancel stops an in-flight request on both paths.
- An older remote host reports no `codeCompletion`, and calls fail with
  `unsupported` without reaching it.

## Tests

- App, engine and RPC tests: routing, stale host or epoch, the capability
  flag, cancel, mismatched answers.
- Frontend API test for the bindings and the missing-binding case.
- `go test ./...`, `npm run check`, `npm test`.
