# CC-12 — Accepting an item adds the import it resolves to

- **Status:** ✅ Done
- **Estimate:** 3 h
- **Depends on:** CC-06, CC-10
- **Plan:** [code-completion.md](../../plan/code-completion.md)

## Goal

Accepting a TypeScript or JavaScript suggestion from another module adds its
import, as gopls and Pyright items already do, in the same undo step.

## Scope

- One resolve per item and answer, shared by the info panel and accept.
- Accepting a language-server item that came without extra edits, from an
  answer that can be resolved, first sends pending typing, then resolves
  the item at that version (CC-10).
  - The wait is bounded: about 500 ms, and more on SSH hosts if
    measurements call for it.
  - The popup closes at once.
  - The range being replaced is mapped through anything typed during the
    wait.
  - The resolved edits are in the current document's coordinates. They are
    applied with the main edit in one transaction, so one undo removes both.
    An edit touching the main edit or another one is dropped, as in CC-06.
- If the resolve fails, times out, or the document changed during the wait,
  only the main edit is applied, as today. Nothing typed is lost.
- Items with listed extra edits (gopls, Pyright) are applied at once,
  without waiting.

## Done when

- In a TS file, accepting `helperValue` from `./helper.js` adds
  `import { helperValue } from "./helper.js";` and the name, and one undo
  removes both.
- Typing during the wait keeps the typed text and still inserts the item.
- A slow or failing resolve inserts the item without the import.

## Tests

- Frontend (jsdom): accept waits for the resolve and applies its edits in
  one undo step; a cached resolve applies without waiting; timeout,
  failure, and typing during the wait; items with listed edits do not
  wait.
- Headless Chrome (`file-editor-chrome.test.mjs`): Enter on an item whose
  import comes from resolve.
- Real server: the CC-09 QA probe `typescript project symbol, imported`
  still passes. CC-10 removed its known marker; that probe checks the
  host side, and this task's Chrome test checks the editor side.

## Done

- `withExtraEdits` (`editorCompletion.ts`) adds resolved edits, given in the
  current text's coordinates, to an accepted item's changes. An edit
  outside the text, or touching the main edit or another, is dropped.
- The store (`codeDiagnostics.svelte.ts`) resolves each item of an answer
  once per version and shares it:
  - The info panel resolves at the confirmed version when the document is
    the answer's and synced, else at version 0. A refused version falls
    back to version 0.
  - `extraEdits(index, ask)` gives none for items with listed edits. It
    answers at once when the item was resolved at the version shown;
    otherwise it sends pending typing, resolves at that version, and gives
    the edits only if that version is still the one shown. Undefined when
    they cannot be known.
- `FileViewer.svelte` passes it to the editor as `resolveEdits`, only for
  the file still shown in its tab.
- The editor (`fileEditor.ts`), on accepting a server item without listed
  edits:
  - applies it with its import at once when it is known;
  - otherwise closes the popup and keeps the replaced range in a state
    field, mapped through typing (typed text at either end stays outside);
  - puts the item in once the import comes, or alone after
    `RESOLVE_ACCEPT_WAIT` (500 ms), a failure, an empty answer, or any
    change to the text meanwhile. When the user typed, their caret stays
    where it is and a snippet goes in as plain text;
  - puts in nothing when the editor shows another file or closed;
  - puts an awaited item in first when another item is accepted.
  All of it is one undo step, as before.
- The Chrome tests now wait until the editor has taken the caret before
  typing (`caretToEnd`). The CC-06 test failed about one run in five
  because typing began before the editor read the DOM selection.

## Evidence

Run on macOS arm64, 2026-11-18:

- Frontend: `npm test` (1593 pass, 4 skipped, 0 fail), `npm run check` (0
  errors), `npm run build`. New and changed tests:
  - `editor-completion.test.mjs`: `withExtraEdits` adds the import before
    the item with the caret after it, and drops edits inside the item,
    outside the text, or at the same place as another.
  - `file-editor.test.mjs` (jsdom): accept waits, then applies the item and
    import with the caret after the item, and one undo removes both; a known
    import, or a listed one, applies at once without waiting; a throw, a
    rejection, `undefined`, `[]` and the 500 ms timeout insert the item
    alone, and a late answer adds nothing; typing at the start and at the end
    during the wait stays, and one undo removes only the item; a second
    accept puts the first item in; another file in the editor gets nothing.
  - `live-lifecycle-integration.test.mjs`: details resolve once per item at
    the synced version, fall back to version 0 and then the listed details,
    and ask at version 0 while typing is unsent; `extraEdits` sends pending
    typing, resolves at that version, then answers at once and shares the
    resolve with the info panel. It gives nothing for an aborted, changed,
    failed or older-host answer.
