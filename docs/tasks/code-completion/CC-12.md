# CC-12 — Accepting an item adds the import it resolves to

- **Status:** ⬜ Not started
- **Estimate:** 3 h
- **Depends on:** CC-06, CC-10
- **Plan:** [code-completion.md](../../plan/code-completion.md)

## Goal

Accepting a TypeScript or JavaScript suggestion from another module adds its
import, as gopls and Pyright items already do, in the same undo step.

## Scope

- One resolve per item and answer, shared by the info panel and accept.
- Accepting a language-server item that came without extra edits, from an
  answer that can be resolved, first sends pending typing, then resolves
  the item at that version (CC-10).
  - The wait is bounded: about 500 ms, and more on SSH hosts if
    measurements call for it.
  - The popup closes at once.
  - The range being replaced is mapped through anything typed during the
    wait.
  - The resolved edits are in the current document's coordinates. They are
    applied with the main edit in one transaction, so one undo removes both.
    An edit touching the main edit or another one is dropped, as in CC-06.
- If the resolve fails, times out, or the document changed during the wait,
  only the main edit is applied, as today. Nothing typed is lost.
- Items with listed extra edits (gopls, Pyright) are applied at once,
  without waiting.

## Done when

- In a TS file, accepting `helperValue` from `./helper.js` adds
  `import { helperValue } from "./helper.js";` and the name, and one undo
  removes both.
- Typing during the wait keeps the typed text and still inserts the item.
- A slow or failing resolve inserts the item without the import.

## Tests

- Frontend (jsdom): accept waits for the resolve and applies its edits in
  one undo step; a cached resolve applies without waiting; timeout,
  failure, and typing during the wait; items with listed edits do not
  wait.
- Headless Chrome (`file-editor-chrome.test.mjs`): Enter on an item whose
  import comes from resolve.
- Real server: the CC-09 QA probe `typescript project symbol, imported`
  still passes. CC-10 removed its known marker; that probe checks the
  host side, and this task's Chrome test checks the editor side.
