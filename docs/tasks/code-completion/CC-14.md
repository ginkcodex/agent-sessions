## Scope

- **Extra edits are all or none in the editor too.** `completionChanges`
  and `withExtraEdits` drop all extra edits when one does not map or
  touches another edit, instead of that one alone, as part of an import
  can break the code. The main edit still applies.
- **Enter on a name typed in full keeps a possible import.** Enter
  breaks the line instead of accepting when the selected item would
  insert exactly the word typed (`plainInserts`). An item that may gain an
  import on resolve is no such no-op: vtsls names the module of its
  auto-import items in `labelDetails.description`. Items from an answer
  that resolves edits and that have a label description are not
  registered.
- **`liveDocuments.flush`** declares `off` and `timer` before `finish`, so
  a timer fake that runs at once cannot hit them uninitialised.
- **Store.** The cached path of `extraEdits` checks the abort signal and
  the store's lifetime, as the async path does.
- **`completionBlocker`** says "code suggestions" instead of "code
  navigation": `navigationBlocker` takes the feature's wording.
- **Mock.** Detaching drops the kept completion answers of the
  attachment's documents.
- **`languageLabels`** handles a language source's promise it does not
  wait for, so a rejection is not unhandled.
- **Readability.** The nested ternaries in `acceptOrBreakLine`,
  `serverBoosts` and the `plainInserts` line become small helpers.
- **Code checks text.** The notes for Ruff, RuboCop, Rust, PHP and
  languages that are off say what they do for suggestions.

## Done when

- The items above are in, with tests where behaviour changed.
