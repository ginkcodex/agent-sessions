# CC-14 — Review fixes: editor, store and texts

- **Status:** ✅ Done
- **Estimate:** 3 h
- **Depends on:** CC-06, CC-12
- **Plan:** [code-completion.md](../../plan/code-completion.md)

## Found by

A code review of the `feature/code-completion` branch.

## Scope

- **Extra edits are all or none in the editor too.** `completionChanges`
  and `withExtraEdits` drop all extra edits when one does not map or
  touches another edit, instead of that one alone, as part of an import
  can break the code. The main edit still applies.
- **Enter on a name typed in full keeps a possible import.** Enter
  breaks the line instead of accepting when the selected item would
  insert exactly the word typed (`plainInserts`). An item that may gain an
  import on resolve is no such no-op: vtsls names the module of its
  auto-import items in `labelDetails.description`. Items from an answer
  that resolves edits and that have a label description are not
  registered.
- **`liveDocuments.flush`** declares `off` and `timer` before `finish`, so
  a timer fake that runs at once cannot hit them uninitialised.
- **Store.** The cached path of `extraEdits` checks the abort signal and
  the store's lifetime, as the async path does.
- **`completionBlocker`** says "code suggestions" instead of "code
  navigation": `navigationBlocker` takes the feature's wording.
- **Mock.** Detaching drops the kept completion answers of the
  attachment's documents.
- **`languageLabels`** handles a language source's promise it does not
  wait for, so a rejection is not unhandled.
- **Readability.** The nested ternaries in `acceptOrBreakLine`,
  `serverBoosts` and the `plainInserts` line become small helpers.
- **Code checks text.** The notes for Ruff, RuboCop, Rust, PHP and
  languages that are off say what they do for suggestions.

## Done when

- The items above are in, with tests where behaviour changed.

## Tests

- `editor-completion.test.mjs`: one bad extra edit drops them all.
- `file-editor.test.mjs`: Enter on a fully typed item with a label
  description and resolvable edits accepts it; without, it breaks the line.
- Live documents: a synchronous timer fake settles `flush`.
- Store: an aborted ask gets nothing from the cache; `completionBlocker`
  wording.
- Mock: detach drops the answers.

## Done

- `editorCompletion.ts`: `completionChanges` and `withExtraEdits` share
  `withEdits`, which adds extra edits all or none. `serverBoosts` orders by
  `compareKeys`.
- `fileEditor.ts`:
  - `acceptOrBreakLine` reads `plainText(option)`;
  - `itemText(item, answer)` registers no plain text for an item with
    listed edits, or with a label description from an answer that resolves
    edits, so Enter accepts it even when typed in full;
  - `languageLabels` catches the promise of a language source it does not
    wait for.
- `liveDocuments.ts`: `flush` declares `off` and `timer` before `finish`.
- Store: `extraEdits` gives nothing for an aborted ask or an ended store,
  even when the edits are known.
- `navigationBlocker` takes `feature: 'suggestions'`, and
  `completionBlocker` uses it: "Code suggestions are not available for
  this host.", "…to use code suggestions.", and so on.
- Mock: a detach drops the kept answers of the attachment's documents.
- Code checks: the Ruff, RuboCop, Rust, PHP and languages-off notes say
  what they do for code suggestions. Intelephense's free tier includes
  completion.
