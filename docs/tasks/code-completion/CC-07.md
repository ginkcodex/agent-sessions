# CC-07 — Snippet completions

- **Status:** ✅ Done
- **Estimate:** 3 h
- **Depends on:** CC-06
- **Plan:** [code-completion.md](../../plan/code-completion.md)

## Goal

Completions such as functions with parameters insert placeholders the user
can Tab through, as in VS Code.

## Scope

- Turn on `completionItem.snippetSupport` in `initializeParams` (a client
  capability, not in the approval policy; the golden policy test stays
  green).
- Convert LSP snippet syntax to a CodeMirror `snippet()` template:
  `$1`, `${1}`, `${1:default}`, nested placeholders, `$0`, escapes
  (`\$`, `\}`, `\\`). Choices (`${1|a,b|}`) use their first choice;
  variables (`$TM_FILENAME` and others) insert their default or nothing.
  Anything that does not parse is inserted as plain text without the
  syntax.
- Snippet items apply through the same edit mapping as CC-06; extra edits
  still apply in the same undo step.

## Done when

- A gopls or vtsls function item inserts its parameters as tab stops and
  ends at `$0`.
- Malformed snippets insert readable plain text and never throw.

## Tests

- Unit tests for the converter: every syntax form, nesting, escapes,
  choices, variables, malformed input, UTF-16 text.
- Editor test: accepting a snippet item, Tab through stops, undo.
- Go test that `initializeParams` declares snippet support and the policy
  is unchanged.

## Done

- Host: `initializeParams` declares `completionItem.snippetSupport: true`.
  Client capabilities are not part of the approval policy, so the
  fingerprint does not change.
- `editorCompletion.ts`: one lenient parser for LSP snippets, shared by
  `snippetText` (plain text, caret at the first stop) and the new
  `snippetTemplate`, which builds a CodeMirror `snippet()` template:
  - Stops become fields. Mirrors (`$1` again) show the placeholder's
    text and are selected together.
  - A choice gives its first option. A variable gives its default, or
    nothing. A transform gives nothing.
  - `$0` is the last stop. When a snippet has none, `$0` goes at the end, as
    in VS Code.
  - A field cannot hold some placeholder text: braces, several lines, a
    trailing backslash, or nested stops. In that case the stop sits before
    the text, and nested stops keep their own fields.
  - `${name` with nothing valid after it is text.
- CodeMirror's template syntax has two traps:
  - It reads `${` and `#{` as fields and drops a backslash before a
    brace. The template escapes a brace only after `$`, `#` or `\`.
  - Its escape handling (6.20.4) puts fields at the wrong offset after the
    third escape on one line. Such a snippet has no template and goes in as
    plain text with the caret at its first stop.
- `fileEditor.ts`: a snippet item's main edit goes through `snippet()`, with
  a stand-in `dispatch` that keeps the transaction. Its change, field
  selection and effects are merged with the extra edits into one
  transaction, so accepting is still one undo step. Text that only the label
  fits still goes in as plain text.
- Mirrors need several selections, which the editor does not otherwise
  allow (Mod-click is Go to Definition). A `mirrors` compartment allows
  them just before such a snippet goes in. A transaction filter turns
  them off and keeps only the main selection once the snippet ends: at
  `$0`, on Escape, or when the caret leaves the fields.
- The mock backend offers declared functions as snippets with their
  parameters as tab stops, so dev mode shows them.
