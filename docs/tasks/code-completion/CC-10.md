# CC-10 — Import edits that arrive on resolve (vtsls)

- **Status:** ⬜ Not started
- **Estimate:** 4 h
- **Depends on:** CC-03, CC-06
- **Plan:** [code-completion.md](../../plan/code-completion.md)

## Goal

Accepting a TypeScript or JavaScript suggestion from another module adds its
import, as it already does for gopls and Pyright.

## Found by

CC-09's real-server QA. vtsls 0.3.0 offers `helperValue` from
`./helper.js` (label description `./helper.js`) with no
`additionalTextEdits` in the completion answer. It computes the import only
in `completionItem/resolve`: it asks tsserver for `completionEntryDetails`
and sets `additionalTextEdits` from the entry's code actions
(`@vtsls/language-service/dist/index.js`). It does this whatever
`resolveSupport.properties` the client advertises. Our resolve keeps only
`detail` and `documentation` (`lsp_completion_resolve.go`), and the editor
applies only the edits the answer carried. So accepting the item inserts
`helperValue` without the import, and the file then fails to compile.

## Scope

- Backend: `CompletionDetails` carries `ExtraEdits` from the resolved item,
  normalized and bounded like the answer's (UTF-16 ranges, at most 100
  edits, the 16 KiB text bound), against the document version the answer
  was computed for. The wire and RPC carry the field. Older hosts leave it
  empty.
- Editor: accepting a language-server item that came without extra edits,
  from a server with `resolveProvider`, resolves it first, using the
  resolve the info panel already started if there is one. The resolved extra
  edits are mapped through what was typed since and applied with the main
  edit in one undo step, as CC-06 does. The wait is bounded (about 500 ms
  locally). If it times out or fails, only the main edit is applied, and
  nothing is lost.
- Decide whether `resolveSupport.properties` should list
  `additionalTextEdits`. Listing it is honest once the editor resolves on
  accept, but it lets other servers move their import edits to resolve too.
  Check gopls and Pyright again if it changes.
- Commands stay ignored. vtsls's `_typescript.applyCompletionCodeAction`
  command, used for edits it cannot express as text edits, is not run.

## Done when

- Accepting `helperValue` in a TS file adds
  `import { helperValue } from "./helper.js";`, and the whole change is
  undone in one step.
- An item with eager extra edits (gopls, Pyright) is applied without waiting
  on resolve.
- A slow or failing resolve applies only the main edit.

## Tests

- Go: resolve normalizes and bounds extra edits, and rejects edits outside
  the document; RPC round trip.
- Frontend: accept waits for resolve, maps and applies its edits in one undo
  step, and falls back on timeout.
- Real server: CC-09's QA probe `typescript project symbol, imported`
  (`internal/engine/code_diagnostics_completion_qa_test.go`) finds the
  item's import after resolve. Remove its `CC-10` known marker; the QA fails
  until then if the item is found.
