# CC-06 — Language server completion in the editor

- **Status:** ✅ Done
- **Estimate:** 4 h
- **Depends on:** CC-01, CC-04, CC-05
- **Plan:** [code-completion.md](../../plan/code-completion.md)

## Goal

The editor popup shows the language server's suggestions together with
CC-01's, and accepting one inserts exactly what the server meant.

## Scope

- `EditorSymbols` gains `complete(position, trigger, current)` and
  `resolve(resultId, index)`, wired in `FileViewer.svelte` to the
  diagnostics store. The editor never holds a store.
- A completion source in `fileEditor.ts`:
  - Runs on the shortcut (CC-01), after a word character, or right after one of the
    server's trigger characters (from the CC-02 capability, passed with the
    answer or the file's server view).
  - Flushes (CC-05), asks, and cancels the previous request when a new one
    starts or the popup closes (CodeMirror's abort signal →
    `cancelCodeCompletion`).
  - Returns nothing, silently, when navigation's blocker
    (`navigationBlocker`) says the server cannot answer, the host lacks
    `codeCompletion`, or the request fails.
  - A complete answer sets `validFor`, so CodeMirror filters it locally; an
    incomplete one asks again on the next keystroke.
- Items map to CodeMirror completions: kind to `type` (icons), label
  details and detail, deprecated struck through, `filterText` used for
  matching, `sortText` order kept through `boost`.
- Merge: server items rank above words and language items; a word the
  server already offers is not repeated.
- Apply: the main edit and the extra edits, converted to offsets on the text
  of the asked version and mapped through the changes typed since, in one
  transaction and one undo step. Extra edits whose range changed since are
  dropped.
- Details: the info panel calls `resolve` for the selected item and shows
  its documentation with the hover's Markdown renderer
  (`documentMarkdown.ts`).

## Done when

- In an approved Go project, `fmt.` offers `Println` with its signature,
  and accepting an unimported package adds the import as gopls answers.
- Typing on after a complete answer filters without new requests; after an
  incomplete one, it asks again and the old request is cancelled.
- An unapproved project shows CC-01's suggestions only, with no message.

## Done

- `editorCompletion.ts` (new) holds the pure parts: kinds to icons, the
  one-line detail, boosts that keep the server's `sortText` order above
  words, where the answer filters from (the edits' shared start, else the
  identifier, sigils such as `@ivar` included), snippets as plain text with
  the caret at the first tab stop (tab stops come in CC-07), and the edits
  for accepting an item.
- `fileEditor.ts`: `codeSuggestions` replaces `documentWords` as the
  language-data source. It asks after a word character, the shortcut, or a
  trigger character. Until the first answer names the server's own
  characters, the likely ones are asked (`` .:>/@<#"'`$( ``). Server items come
  first; words follow with the same start and are skipped when the server
  offers the label. A slow answer (1.5 s) is aborted and the words show; a
  missing, failed or slow answer leaves no `validFor`, so the next keystroke
  asks again, as does an incomplete one. CodeMirror's abort signal cancels
  the request on the host.
- Accepting applies the main edit and the extra edits in one transaction,
  one undo step (`isolateHistory`). The edits are mapped from the asked text
  only when the text before the filter text and after the caret is unchanged
  (`Text.eq`); otherwise only the item's text replaces the filter text.
  Extra edits that touch the main edit or each other, or fall outside the
  document, are dropped.
- Details: the info panel shows the detail line and the documentation
  rendered like hover. Instead of a separate `resolve` on `EditorSymbols`,
  each answer carries `details(index)`; the store resolves while the answer
  is the document's last one and falls back to the listed detail and
  documentation otherwise.
- Store: `codeDiagnostics.complete` flushes pending typing (CC-05), checks
  `completionBlocker` (no `codeCompletion` or navigation's blocker), uses a
  `completion-N` request ID, cancels on abort, and drops answers for another
  lifetime, context, document or version. Every failure is silent.
- `FileViewer.svelte` wires `editorSymbols.complete` only when editing a
  project file on its own host, at the current revision.
- Host: a trigger character the server did not name is answered with no
  items and the server's `triggerCharacters`, without asking the server; the
  answer always carries them.
