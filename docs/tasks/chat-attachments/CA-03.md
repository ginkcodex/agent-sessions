# CA-03 — Engine and RPC take attachments

- **Status:** ✅ Done
- **Estimate:** 3 h
- **Depends on:** CA-02
- **Plan:** [chat-attachments.md](../../plan/chat-attachments.md)

## Scope

- `ChatManager.Prompt(chatID, text, attachments)`: checks them
  (`chatattach.Check`), builds the blocks with the agent's
  `promptCapabilities`, and refuses an empty prompt with no attachments.
- `ChatState.PromptCapabilities` from the agent's `initialize`.
- RPC: `ChatPromptParams.Attachments`; `Capabilities.ChatAttachments`; the
  server checks the limits; the client refuses attachments for a host
  without the capability.
- `chatService.ChatPrompt` and the local and remote services pass them on.

## Likely files

- `internal/engine/chat.go`, `internal/engine/chat_test.go`
- `internal/rpc/chat.go`, `internal/rpc/types.go`, `internal/rpc/server.go`,
  their tests
- `internal/app/chat.go` (service plumbing only)

## Acceptance criteria

- The fake agent receives the text block and one block per attachment.
- An agent without `image` refuses an image with a clear error; the turn
  does not start.
- `ChatState` carries `promptCapabilities` locally and over RPC.
- An old host (no `ChatAttachments`) gets a text-only prompt sent as before,
  and a prompt with attachments is refused before it is sent.

## Tests

- `go test -race ./internal/engine/... ./internal/rpc/... ./internal/app/...`

## Evidence

- Done:
  - `ChatManager.Prompt(chatID, text, attachments)` checks the attachments,
    refuses a prompt with neither text nor attachments (`ErrEmptyPrompt`),
    and builds the blocks from the agent's `promptCapabilities` before the
    turn starts, so a refused prompt sends no events and leaves the chat
    idle.
  - `ChatState.promptCapabilities` comes from the agent's `initialize`.
  - RPC: `ChatPromptParams.attachments`, `Capabilities.chatAttachments`
    (set with `acpChat`), the server passes them to the engine, which checks
    them; the client returns `ErrNoChatAttachments` for a host without the
    capability and still sends text-only prompts there.
  - The app's chat services pass attachments on; `App.ChatPrompt` sends none
    until CA-04.
  - The fake ACP agent advertises image and embedded context (or neither,
    with `ACPTEST_TEXT_ONLY=1`) and describes the blocks it got.
- Tests (`go test -race -count=1 ./internal/engine/... ./internal/rpc/...
  ./internal/app/... ./internal/acp/... ./internal/chatattach/...`: all ok):
  - engine: text, a text file and an image reach the agent in order;
    attachments alone; empty prompt; a malformed attachment refused with no
    events; a text-only agent refuses images (`ErrNoImages`, chat not left
    working) and gets a text file as fenced text;
  - RPC: the capability, `promptCapabilities` over the wire, a text file
    round trip, a malformed attachment refused by the server, and an old
    host refusing attachments while text still goes.
- `go vet ./...`: clean. `gofumpt -l` and `golangci-lint` report nothing in
  the changed files.
- Not checked: a real remote host (CA-06).
