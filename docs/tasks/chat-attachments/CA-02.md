# CA-02 — Prepare attachments

- **Status:** ✅ Done

- **Plan:** [chat-attachments.md](../../plan/chat-attachments.md)

## Scope

New package `internal/chatattach`:

- `Attachment {name, mimeType, size, data | text, uri}`.
- `FromFile(path)`: reads up to 20 MiB, then an image (by its bytes) or a
  UTF-8 text file without NUL bytes up to 512 KiB; anything else is refused
  with a message that names the file.
- `FromImage(name, data)`: a pasted image's bytes.
- Images over 3.75 MiB or 2000 px on the long edge are scaled to fit 2000 px
  (area averaging, standard library only) and encoded as PNG when it fits,
  else JPEG quality 85. A GIF keeps its first frame. WebP over the limit is
  refused.
- `Check(attachments)`: at most 10, at most 24 MiB in total, each one well
  formed (an image's data decodes and its bytes match its type; a text
  attachment has text).
- `Blocks(text, attachments, caps)`: the text block, then an `image` or
  embedded `resource` block per attachment; without `embeddedContext` a text
  file becomes a fenced text block; without `image` an image is an error.
- `acp`: `ImageBlock`, `ResourceBlock` helpers.

## Likely files

- `internal/chatattach/chatattach.go`, `scale.go`, tests
- `internal/acp/types.go`

## Acceptance criteria

- The limits and messages above, each with a test.
- Scaled images keep their aspect ratio and fit both limits.
- `Blocks` keeps the attachments' order.

## Tests

- `go test -race ./internal/chatattach/... ./internal/acp/...`
- Images are generated in the tests; no real files from the user.

## Evidence

- Done:
  - `internal/chatattach`: `Attachment` (`kind` image or text), `FromFile`,
    `FromImage`, `Check`, `Blocks`, and `*Error` with the file's name and the
    reason.
  - Images are recognised by their first bytes. One over 3.75 MiB or
    2000 px is scaled by area averaging (`scale.go`), then encoded as PNG
    when it fits, else JPEG at quality 85, 70, then 55, on white. Images over
    40 million pixels are refused from their header, before decoding.
  - `acp.ImageBlock`, `acp.TextResource` and `acp.ResourceBlock`; an empty
    text file still sends `"text": ""`.
- Tests (`go test -race -count=1 ./internal/chatattach/ ./internal/acp/`: ok):
  - small images unchanged; type by bytes, not name; a 3000×1500 PNG scaled
    to 2000×1000 PNG; a 1500×1500 noise PNG (over the size) sent as JPEG; a
    large JPEG stays JPEG; a GIF's first frame as PNG; WebP as is or
    refused; transparency kept and flattened on white;
  - huge header refused unread, broken and non-image bytes refused;
  - text files, empty files, MIME types, folder, missing file, binary,
    Latin-1, text over 512 KiB, file over 20 MiB (sparse), escaped URIs;
  - `Check`: count, total size, and ten malformed attachments;
  - `Blocks`: order, no text, the URI fallback, the fence without embedded
    context, `ErrNoImages`.
  - All test images are generated in the tests.
- `go tool golangci-lint run ./internal/chatattach/... ./internal/acp/...`:
  0 issues; `gofumpt -l`: clean.
- Not checked: images from real cameras or screenshots (EXIF orientation is
  not applied when scaling), and how agents treat the blocks (CA-06).
