# PF-08 — Source-aware engine and FTS callers

- **Status:** ➖ Superseded
- **Estimate:** 4 h
- **Depends on:** PF-05, PF-07
- **Plan:** [performance.md](../../plan/performance.md)

**Status notes:** superseded 2026-10-25 by Milestone 2; not counted complete. Its goal was to remove Codex resolution work from page, Blob and indexing loads. That is now met without the PF-07 fast paths:

- Codex `Load`, `Blob` and `LoadIncremental` resolve through the IT-06
  incremental resolver. A warm resolution reads 0 bytes of unchanged rollouts,
  and `TestResolverMatchesColdScan` covers duplicate and removed sources and
  index overlay and edge changes
  ([IT-06](../../perf.md#it-06--incremental-codex-resolution-2026-10-25)).
- FTS loads through the engine (IT-09). Its result is never older than the
  queued scan revision, background jobs never evict foreground entries, and
  providers without incremental support keep plain `Load`
  ([IT-09](../../perf.md#it-09--shared-fts-loading-2026-10-25)).

Not met, and not planned: callers passing catalog metadata to
`LoadFromSource`/`BlobFromSource`. Production declines those calls (PF-07C), so
wiring them would change nothing. Reopen only if PF-07 activation is ever
justified.

**Goal:** activate the fast path across interactive and indexing calls.

**Likely files:** `internal/engine/service.go`, `internal/index/worker.go`, engine
cache/FTS tests; optional interface fakes from PF-06.

- Engine supplies resolved catalog metadata, while unknown providers retain Load/Blob.
- FTS loads metadata consistent with its queued revision and retains transactional
  current-revision checks before replacing indexed documents.
- Do not couple FTS to the UI cache or introduce index → engine imports. This task
  removes resolution work, not full transcript parsing or FTS queue idle time.

**Done when:** tests cover providers with/without optional support, disappeared
sources, metadata updates/deletion during indexing and invalidation during load.
Benchmarks show fewer scans for both page and Blob/indexing paths, with identical output.
