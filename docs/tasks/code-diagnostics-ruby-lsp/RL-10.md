# RL-10 — Saved-file watching for projects without Go

- **Status:** ✅ Done
- **Estimate:** 4 h
- **Depends on:** RL-04
- **Plan:** [code-diagnostics-ruby-lsp.md](../../plan/code-diagnostics-ruby-lsp.md)

Found in RL-04. The plan says saved `.rb` transitions "from the approved
project watcher" reach ruby-lsp, but that watcher is the built-in Go syntax
check's (`project_watch.go`): the engine starts it only when the project has
Go sources and `go-syntax` is approved (`internal/engine/code_diagnostics_watch.go`),
and it reports only `.go` transitions. In a Ruby-only project, nothing tells
ruby-lsp that a closed file changed on disk (an agent's edit, a `git pull`),
so Go to Definition into that file uses the index from startup until the file
is opened (RL-04 then re-indexes it) or ruby-lsp restarts.

**Goal.** Saved Ruby file transitions reach a running ruby-lsp in any
approved project, also without Go sources.

- A saved-file tracker for the live providers that take watched files
  (`watchedFileProviders` in `live_owner.go`): walk and fsnotify the project
  with the same skips, bounds and containment as `ProjectWatcher`, track
  size/mtime of owned files only, keep no file contents, and report created,
  changed and deleted files through `LiveDocuments.WatchedFiles`.
- Started by the engine for an attachment whose live proposal is approved and
  has such a provider; stopped on revoke, detach and Ruby being disabled.
  In a project with Go sources, one watcher serves both (no second fsnotify
  instance on the same tree).
- The watcher degrades as the Go one does (limits, unavailable fsnotify) and
  never starts a language server.

**Likely files.** `internal/codediagnostics/project_watch.go` (or a new
`live_watch.go`), `internal/engine/code_diagnostics_watch.go`, tests.

**Done when.** Synthetic tests with fake fsnotify events: a Ruby-only
approved project forwards `.rb` saves to ruby-lsp and nothing to RuboCop; no
watcher runs before approval or after revoke; a Go + Ruby project still runs
one watcher and forwards both; the limits mark coverage partial.

## Outcome

The project watcher is no longer the Go syntax check's alone. One watcher per
attachment serves go-syntax and the live servers that take watched files
(gopls for `.go`, ruby-lsp for Ruby files); no second fsnotify instance runs
on the same tree.

- `Manager.LiveWatched` / `liveWatch` (`manager_inprocess.go`): the live
  providers to feed are those in `watchedFileProviders` that are approved,
  available and cover opened documents. gopls is left out when go-syntax
  already reports `.go` transitions.
- `newProjectScan` (`go_syntax.go`): the walk analyses `.go` files only when
  go-syntax is approved, and tracks other owned files by size and
  modification time, never reading them. Skips, bounds and containment are
  the go-syntax walk's. A walk cut short by the entry limit does not report
  the files it did not reach as deleted. Metadata-only events and unchanged
  files report nothing.
- `ProjectWatcher` (`project_watch.go`): starts when go-syntax is approved or
  when there is a live provider to feed and a consumer (`OnChanges`). Without
  go-syntax it publishes no result set. Each batch re-checks the approval;
  after revoke it reports nothing and ends. Unavailable fsnotify, watch or
  entry limits and a stopped watcher add a note to the live provider's notice
  (once) and mark its coverage partial; RuboCop is untouched.
- Engine (`code_diagnostics_watch.go`): the watcher is started for go-syntax
  or `LiveWatched`, and stopped on revoke, detach and when Ruby is off. It
  forwards batches through `LiveDocuments.WatchedFiles`, which reaches running
  sessions only and never starts a server.
- The plan's Index freshness bullet now says the watcher also runs without Go
  sources.

Not handled:

- Providers that change without a new context (rediscovery after
  preparation) do not refresh a running watcher's live list.
- Tracked files are bounded by the walk's entry limit (50000), not by the
  go-syntax file limit.
- Once a document is opened, the live session replaces the provider's notice
  with its own; a watch note added before that can be overwritten.
