# RL-11 — Long definition lists

- **Status:** ✅ Done
- **Estimate:** 2 h
- **Depends on:** RL-05, RL-06
- **Plan:** [code-diagnostics-ruby-lsp.md](../../plan/code-diagnostics-ruby-lsp.md)

Found in manual testing on 2026-11-07. Go to Definition on `ActiveJob` in
`class ApplicationJob < ActiveJob::Base` (a Rails app) opened a "Definitions"
picker with about 40 places, every one under
`~/.local/share/mise/installs/ruby/4.0.9/lib/ruby/gems/4.0.0/gems/activejob-8.1.4.1/lib/`.
The answer is right: activejob reopens `module ActiveJob` in each of those
files, and ruby-lsp returns each reopening. The picker was not ready for it:

- the menu had no height limit, so it ran past the bottom of the window and
  the lower places could not be reached;
- every row repeated the gem's long path and wrapped onto two or three lines.

## Scope

- `locationList` (`frontend/src/lib/sourceNavigation.ts`): when every place
  is outside the project and they share a folder deeper than a root (`/`,
  `C:\`), the folder is the list's heading and each row reads from there
  (`active_job/base.rb:17:3`). Folders are split at `/` or `\`, never inside a
  name. A list with a project place, a single place, or places on different
  drives keeps the full labels as before. Each row's tooltip still gives the
  full path.
- `ContextMenu.svelte`: an optional `heading`, drawn above the items, sticky
  while the list scrolls and outside the `menuitem` roles; the menu is at most
  the window's height and scrolls inside it; scrolling inside the menu no
  longer closes it (scrolling anything else still does).
- `FileViewer.svelte` `askSymbol` uses `locationList` and passes the heading.

Not changed: how many places ruby-lsp returns. Filtering reopenings out would
hide real definitions (a method may be defined in any of those files).

## Acceptance criteria

- The ActiveJob case reads as one heading naming the gem's `lib` folder and
  short rows, and every row can be reached by scrolling or the arrow keys.
- Lists that mix project and outside places, or have one place, read as
  before.

## Evidence

- `frontend/test/source-navigation.test.mjs`:
  - "a list of places in one outside folder names the folder once": the gem
    heading and short labels; a shared name prefix (`/g/activejob-8`,
    `/g/activerecord-8`) gives the heading `/g`, not `/g/active`; a Windows
    folder (`C:\Ruby\lib`); no heading for only a root in common, different
    drives, `C:\` only, a single place, or a mix with a project place.
  - The viewer's picker test: two gem places give `symbolPicker.heading` with
    short labels and full-path tooltips, and choosing one opens that file.
  - "a long context menu scrolls inside the window and shows its heading":
    server render of `ContextMenu.svelte` with and without `heading`, two
    `menuitem`s only; the source keeps the height cap and the scroll rule.
- Mutations (backups in `/private/tmp/picker-mut1`, restored and compared
  after): the viewer dropping the heading, no height cap, scrolling inside the
  menu closing it, the heading not drawn. Each fails a test.
- From `frontend/`: `npm test` 1079 tests, 1078 pass, 0 fail, 1 skipped (the
  existing Chrome-only layout test); `npx svelte-check --threshold error`
  0 errors, 0 warnings.
- Not checked: the scrolling and sticky heading in a real window (the tests
  render on the server and read the CSS; no browser layout ran). The user's
  Rails project was not rerun.
