# RL-12 — Likely Ruby definition first

- **Status:** ✅ Done
- **Estimate:** 2 h
- **Depends on:** RL-11
- **Plan:** [code-diagnostics-ruby-lsp.md](../../plan/code-diagnostics-ruby-lsp.md)

Found after RL-11. A Ruby module or class is reopened in many files, and
ruby-lsp answers Go to Definition with every reopening in index order:
`ActiveJob` gives 53 places in activejob 8.1.4.1, and the file that
defines it (`active_job.rb`) is somewhere in the list. Ruby projects and gems
follow the Zeitwerk naming rule (`ActiveJob::Base` lives in
`active_job/base.rb`), so the likely file can be named from the constant.

## Scope

- `rankDefinitions` (`frontend/src/lib/sourceNavigation.ts`): given the
  places, the word and the text before it on the line, order the places for a
  Ruby constant (a word starting with a capital letter):
  1. the file whose path, without its extension, ends with the constant's
     path: `ActiveJob` → `…/active_job`, `ActiveJob::Base` →
     `…/active_job/base` (the qualifier is the `A::B::` written before the
     word; a leading `::` is ignored);
  2. then files named after the word alone (`…/base.rb`);
  3. then the rest, in the server's order.
  Names follow ActiveSupport's `underscore` (`HTTPClient` → `http_client`,
  `URI` → `uri`). `.rb` and `.rbs` places both count.
- `FileViewer.svelte` `askSymbol`: Ruby source files only (by
  `languageOfPath`), definitions only; references keep the server's order.
  Nothing is dropped, and a single place still opens directly.

## Acceptance criteria

- `ActiveJob` in `class ApplicationJob < ActiveJob::Base` lists
  `active_job.rb` first; `Base` there still opens `active_job/base.rb`.
- Lowercase words (methods), other languages and references are unchanged.

## Tests

- Unit tests for the ranking and the name conversion, including a name that
  only shares a prefix (`active_job_extra.rb` is not `active_job.rb`).
- The viewer's picker test: a Ruby file gets the ranked order; a TypeScript
  file and references keep the server's order.

## Evidence

- `frontend/test/source-navigation.test.mjs`:
  - "Ruby constants name their files the way ActiveSupport underscores them":
    `ActiveJob`, `HTTPClient`, `URI`, `JSONParser2`, `Base64`, `String`,
    `ID3Tag`.
  - "a reopened Ruby constant lists its own file first": whole path, then the
    word alone, then the rest in the server's order; the qualifier picks
    between two `base.rb`; `active_job_extra.rb` and `inactive_job.rb` are not
    `active_job.rb`; a leading `::` is ignored and `xActiveJob::` is no
    qualifier; relative project paths, `.rbs` and Windows paths; lowercase
    words keep the order (the same array comes back).
  - The viewer's picker test: in a Ruby file `ActiveJob` lists
    `active_job.rb` first and choosing that row opens it; `Base` (with `::`
    before it) lists `active_job/base.rb` first; a lowercase word, a
    TypeScript file and references keep the server's order.
- Mutations (backups in `/private/tmp/rank-mut1` and `rank-mut2`, restored
  and compared after): no Ruby check, the items built from the unranked list,
  no qualifier, no folder boundary, no lookbehind, `.rb` only, no `\`
  handling, no word-alone tier. Each fails a test. The items mutation
  survived at first (the labels were ranked but a row opened another place);
  the test now chooses a row. Dropping the index tie-break also survived: it
