# RL-05 — External locations into Ruby, gems and RBS

- **Status:** ✅ Done
- **Estimate:** 3 h
- **Depends on:** RL-03
- **Plan:** [code-diagnostics-ruby-lsp.md](../../plan/code-diagnostics-ruby-lsp.md)

**Goal.** Definitions outside the project open read-only.

- Grant locations under the resolved Ruby library directory, the gem
  directories in `GEM_PATH` and `BUNDLE_PATH`, through `grantExternal` as for
  other languages' dependencies.
- `.rbs` targets (core types inside the `rbs` gem) open as read-only text.
- Locations outside those roots are dropped as for other providers.

**Likely files.** `internal/codediagnostics/ruby_lsp.go`, the navigation
grant code, `frontend/src/lib/codeNavigation.ts` if `.rbs` needs a language
entry, tests.

**Done when.** Synthetic tests with the evidence answers (stdlib, gem, RBS)
grant each location and drop one outside the roots.

**Outcome (2026-11-07).** A new `ServerConfig.ExternalRoots` (`json:"-"`)
lists the only host directories a navigation answer may point into outside
the project. ruby-lsp sets `<prefix>/lib/ruby` (standard library, default
and bundled gems) and the `GEM_PATH` directories, which already include an
absolute `BUNDLE_PATH`; a `BUNDLE_PATH` inside the project gives project
paths. `locationResult` drops external places outside those roots before
`grantExternal` sees them. Not in the policy: the roots come from the
interpreter and `GEM_PATH`, which the policy already binds. Differences from
the brief:

- **No other provider restricts external places.** "Dropped as for other
  providers" was wrong: gopls, vtsls, Pyright and rust-analyzer keep every
  absolute place outside the project (`TestNavigationAgainstFakeServer`
  still checks that). An empty `ExternalRoots` keeps that behavior; only
  ruby-lsp sets it.
- **No frontend change for `.rbs`.** `fileLanguage` returns `null` for an
  unknown extension, which the viewer shows as plain text without
  highlighting, and `files.ReadExternal` reads any regular text file. So RBS
  core types already open read-only as text.
- Root containment uses `filepath.Rel` (`within`), so `lib/ruby-other` is not
  inside `lib/ruby`.
- Not changed: links in hover Markdown (ruby-lsp's `**Definitions**:` lines
  point to `.rbs` files) are not granted; only definition and references
  answers grant.
