# RL-13 — Ruby discovery tests on Windows CI

- **Status:** ✅ Done
- **Estimate:** 1 h
- **Depends on:** RL-01
- **Plan:** [code-diagnostics-ruby-lsp.md](../../plan/code-diagnostics-ruby-lsp.md)

Found in CI after `3e5808e` and `dbe7e1f` were pushed. The pushed commits
also carried RuboCop's `7f74842`. CI run
[42336882871](https://github.com/ginkcodex/agent-sessions/actions/runs/42336882871):
macOS, Linux and `test` passed, while `windows-test-build` failed in "Go vet
and tests". 28 tests in `internal/codediagnostics` failed: RuboCop's and
ruby-lsp's discovery tests, and the Ruby interpreter tests. The job stopped
there, so its frontend and Windows build steps did not run.

**Cause.** The fake interpreter `<prefix>/bin/ruby` is found by its
executable bit, and on Windows `isExecutable` accepts only `.exe` and
`.com`. Every fake Ruby came out `foreign` or `notInstalled`. One RuboCop
case also makes a directory named `r:b`, which Windows does not allow. The
product code is right: Ruby is served only by local live providers, and
`localLiveSupported` (`internal/engine/code_diagnostics_local_live.go`) is
darwin and linux only. A Windows project is checked through WSL. The other
host-tool discovery tests (gopls, Python, Rust) already skip on Windows
through `unixTools`. The Ruby helpers did not.

## Scope

- `rubyHost` and `writeRuby` (`internal/codediagnostics/ruby_runtime_test.go`)
  call `unixTools(t)`. Every Ruby host helper (`rubocopHost`, `rubyLspHost`,
  `rubyLspUser` and the live environments) goes through `rubyHost`. The
  `r:b` case calls `rubyHost` before it makes the directory.
- Tests on fake language servers (the evidence replay, external locations,
  freshness) do not use these helpers and still run on Windows.

## Evidence

- The failing test names come from the job log (`--- FAIL` lines, 28 tests).
- Skip simulation: with `unixTools` temporarily skipping on every OS (backup
  in `/private/tmp/win-skip-sim1`, restored and compared after), those 28
  tests ran with `-v`. Each skipped (`TestRubyVersionManagers` through its
  subtests) and none failed.
- `go vet ./...` with `GOOS=windows` and `GOOS=linux`, plus a Windows build
  of the `internal/codediagnostics` test binary: clean. `go test ./internal/...`
  on darwin: all pass.
- Not checked: a native Windows run. The Windows CI job is the check, and
  its frontend and build steps have not run on this change yet.
