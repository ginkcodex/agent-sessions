# RL-00 — ruby-lsp server spike

- **Status:** ✅ Done
- **Estimate:** 4 h
- **Depends on:** —
- **Plan:** [code-diagnostics-ruby-lsp.md](../../plan/code-diagnostics-ruby-lsp.md)

**Goal.** Facts about the real server before an adapter depends on them.

Install the latest ruby-lsp into a disposable gem directory under
`/private/tmp` (the only network use; nothing goes into the user's Ruby).
Run it on disposable synthetic projects with an empty temp `HOME`, through a
small stdio driver that sends this app's `initialize` parameters. Record:

- `initialize` result: `serverInfo`, position encoding, sync kind, the
  navigation and diagnostic capabilities.
- Files written to the project, `HOME` and caches, and network use, in a
  project without a `Gemfile`, with a `Gemfile`, and with `BUNDLE_GEMFILE`
  set so the composed bundle is skipped.
- Definition, references and hover: within a file, across project files, into
  a gem and into Ruby's core (RBS); before and after indexing ends; on an
  unsaved draft.
- Server-to-client requests and notifications during startup and indexing.
- Whether `initializationOptions` turn off diagnostics, formatting and
  add-ons, and what an add-on in the bundle does.
- `shutdown`/`exit` behavior.

**Done when.** `internal/codediagnostics/testdata/ruby-lsp/evidence.json`
holds the observed payloads with the ruby-lsp, Ruby and Bundler versions and
the host platform; the plan's design, risks and the remaining tasks are
written from them.

**Outcome (2026-11-07).** Four runs of ruby-lsp 0.26.11 (mise Ruby 4.0.9,
Bundler 4.0.20, darwin/arm64), summarized in the plan's "Observed behavior"
section:

- **A1**, the default `exe/ruby-lsp` launch in a project without a
  `Gemfile`: composed `.ruby-lsp/` in the project, ran `bundle install`
  against rubygems.org, wrote 248 cache files under `HOME/.bundle`;
  `initialize` after 44 s. Ruled out.
- **A2**, `exe/ruby-lsp` with `BUNDLE_GEMFILE` naming a missing
  `<workspace>/Gemfile`: 0.15 s, nothing written; definition, references and
  hover into the project, the standard library and core RBS.
- **B1**, `exe/ruby-lsp` in a Bundler project: a project add-on ran (wrote a
  marker file) and RuboCop's add-on activated; lockfile gems are indexed
  except the `development` group.
- **C1**, the app-owned wrapper (no add-ons) with every non-navigation feature
  off: no add-on, no RuboCop, nothing written, empty stderr, the same answers.

Source reading (not runs) added: add-ons load unconditionally on
`initialized`; open documents are re-indexed only by `documentSymbol` and the
other combined requests; `workspace/didChangeWatchedFiles` is handled without
a client capability; `Bundler.definition` evaluates the `Gemfile`.
