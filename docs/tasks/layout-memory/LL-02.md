# LL-02 — Fit layout at open and resize

- **Status:** ⬜ Not started
- **Estimate:** 2 h
- **Depends on:** LL-01
- **Plan:** [layout-memory.md](../../plan/layout-memory.md)

## Scope

Wire `layoutSizes` into the running app. The sidebar and session list keep
their current sizing; the transcript floor becomes content-based:

- Compute `transcriptNeed` from the visible transcript header rows (measure
  the always-visible items at their computed fonts; the cwd item is shrinkable
  with its 140 px minimum) and use `max(LIMITS.transcriptMin, need)` as the
  transcript floor in `fitToWidth`.
- Recompute at open and at window resize only — never per session selection,
  so the layout cannot jump while browsing. With nothing loaded the hard
  floors apply.
- Replace the proportional `ensureTranscriptVisible` shrink with
  `fitToWidth`: the pane further above its floor gives up width first and
  nothing drops below its floor while another has slack.
- Pane widths persist on drag end instead of every animation frame; the
  `agent-sessions:pane-widths` JSON format stays unchanged. Equalize
  (double-click/Enter) stays as it is.

## Acceptance criteria

- With the default window and panes, the transcript header shows its meta row
  (cwd, branch, message count, token chips, created/updated) unwrapped; a
  narrower window wraps it gracefully but never pushes a pane below its floor
  while another has slack.
- Selecting different sessions never resizes panes; resizing the window
  smaller then larger restores usable widths (no permanent over-shrink).
- Dragging still persists exactly as today and survives a restart.
