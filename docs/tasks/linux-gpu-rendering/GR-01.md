# GR-01 — Leave DMA-BUF to Wails' NVIDIA check

- **Status:** ✅ Done
- **Estimate:** 1 h
- **Depends on:** —
- **Plan:** [linux-gpu-rendering.md](../../plan/linux-gpu-rendering.md)

## Scope

Remove the `init()` in `cmd/agent-sessions/main.go` that set
`WEBKIT_DISABLE_DMABUF_RENDERER=1` everywhere. Wails v3's own `init()` still
sets it where WebKit renders on NVIDIA, and a value the user exports wins.
Record it in TECH-NOTES.

## Likely files

`cmd/agent-sessions/main.go`, `TECH-NOTES.md`.

## Acceptance criteria and tests

- With the variable unset on a non-NVIDIA machine, the app's environment
  has no `WEBKIT_DISABLE_DMABUF_RENDERER`, and the idle main thread is no
  longer pinned.
- `go vet` and `go test` pass, with and without the desktop tags.

## Evidence

- Found while checking the swipe on Linux (1.3.1, then 1.2.8): the GTK main
  thread of the installed app sat at ~100 % idle. That was 2.5 s user + 0.5 s
  system CPU in 3 s, with 18 voluntary context switches.
- `gdb`, on a copy started by `gdb` (attach needs root here), sampled the
  main thread 5 times. 3 samples were in software compositing:
  `cairo_paint` → `pixman_image_composite32`, and WebKit's
  `cairo_surface_flush` → `memcpy`. 2 were idle in `ppoll`.
- Copies of 1.3.1, idle for 5 s after 20 s of start-up, on a 1.5× GNOME
  Wayland session with an AMD HawkPoint GPU:
  - `WEBKIT_DISABLE_DMABUF_RENDERER=1`: main thread 100 %.
  - `=0`: 8 %.
  - A build of this change (`go build -tags desktop,production`), variable
    unset: not set in the process, main thread 10 %.
- `go vet` (with and without `desktop,production`) and `go test -tags
  desktop,production ./cmd/agent-sessions/` pass.
- Not checked: NVIDIA, where Wails' check must still turn DMA-BUF off; X11
  (GR-02).
