## Scope

The local monitor in `mousenav_darwin.m` also watches scroll events and
always passes them on. Only scrolls with a gesture phase count, and momentum
is ignored. Each gesture's sideways and vertical distance add up. Once it is
at least `SWIPE_DISTANCE` sideways and more than twice the vertical, and
the system's two-finger *Swipe between pages* is on, it calls
`goSwipeNavigate` once, with the direction the fingers moved. Go sends
`nav:swipe` to that window as it sends `nav:mouse`. TECH-NOTES:
two-finger swipes, and the three-finger note corrected.

## Evidence

- `mousenav_darwin.m`: the local monitor also takes
  `NSEventMaskScrollWheel` and returns every scroll event unchanged.
  `track_swipe` ignores events without a phase (wheels, momentum), starts a
  gesture on `MayBegin`/`Began`, and adds up the fingers' sideways movement
  (sign by `isDirectionInvertedFromDevice`, so right is back) and the
  vertical. Once `SWIPE_DISTANCE` (80 points) is reached, more than twice
  the vertical, with `isSwipeTrackingFromScrollEventsEnabled`, it calls
  `goSwipeNavigate` once per gesture. Buttons and `NSEventTypeSwipe` are
  unchanged.
- `mousenav_native.go`: `goSwipeNavigate` sends `nav:swipe`
  (`swipeNavigateEvent` in `mousenav.go`) through the same
  `navigateWindow` as `nav:mouse`.
- `TECH-NOTES.md`: two-finger swipes; the three-finger note now says it
  needs the three-finger setting.
- Linux: `go vet ./cmd/...`, `go test ./cmd/agent-sessions/` and
  `go build -tags desktop,production ./cmd/agent-sessions` pass.
- Missing: the ObjC has not been compiled. Linux has no Cocoa headers.
  The macOS CI job's desktop build or a build on a Mac will check it.
