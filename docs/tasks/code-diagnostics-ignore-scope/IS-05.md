# IS-05 — Files, Changes and History: Git without `core.fsmonitor`

- **Status:** ⬜ Not started
- **Estimate:** 2 h
- **Depends on:** —
- **Plan:** [code-diagnostics-ignore-scope.md](../../plan/code-diagnostics-ignore-scope.md)

Found while planning IS-01: `gitOutputEnv` in `internal/files` runs Git
without `-c core.fsmonitor=false`. A repository's own `.git/config` can set
`core.fsmonitor` to a program, and `git status` / `ls-files` start it, so
opening a project's file tree can run a program the project chose.

## Scope

- Decide whether every Files, Changes and History Git call passes
  `-c core.fsmonitor=false`, or only the read-only listing calls. Turning it
  off loses the built-in fsmonitor daemon's speed-up in repositories that
  use it; record the measured cost.
- Apply it, with a test that a configured fsmonitor script does not run for
  the listing, status and history calls.

## Likely files

`internal/files/files.go`, `git_history_*.go`, tests.

## Acceptance criteria

- A repository with `core.fsmonitor` set to a script: opening the file tree,
  Changes and History does not run it.
