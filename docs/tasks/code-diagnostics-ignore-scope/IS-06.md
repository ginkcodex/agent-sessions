# IS-06 — Git reads without repository filter programs

- **Status:** ⬜ Not started
- **Estimate:** 3 h
- **Depends on:** IS-05
- **Plan:** [code-diagnostics-ignore-scope.md](../../plan/code-diagnostics-ignore-scope.md)

Found during IS-05: with `*.txt filter=x` in `.gitattributes` and
`filter.x.clean` set in the repository's `.git/config`, `git -c
core.fsmonitor=false status` runs the clean command for a tracked file whose
modification time changed (checked with Git 2.53.0 on Linux). The file tree
and Changes run `git status`, so opening a project can still run a program
its own config chose. Diff and History reads may do the same through
`filter.<name>.process` and `diff.<name>.textconv` where those runners do
not pass `--no-textconv`.

## Scope

- List the repository-configurable programs the Files, Changes and History
  reads can start (clean/process filters, textconv, any others) and which
  call starts each.
- Decide how to turn them off for reads (for example, read the configured
  filter names with `git config --get-regexp` and override each with `-c`,
  or a `GIT_CONFIG_*` environment), and what Changes shows when content is
  then compared without the filter (a file may look modified).
- Keep user-initiated writes (stage, commit) as Git normally runs them, or
  record why not.

## Likely files

`internal/files/files.go`, `repo_status.go`, `git_diff.go`,
`git_history_*.go`, tests.

## Acceptance criteria

- A repository whose config sets a clean filter, process filter or textconv
  to a script: opening the file tree, Changes and History does not run it.
- What Changes and diffs show for a filtered file is stated and tested.

## Tests

Real temporary repositories with marker-writing scripts, as in
`fsmonitor_test.go` (skipped without `git`, and on Windows).
