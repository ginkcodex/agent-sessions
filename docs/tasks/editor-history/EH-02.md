# EH-02 — Viewer places, preview-aware steps, one record per jump

- **Status:** ✅ Done
- **Estimate:** 3 h
- **Depends on:** EH-01
- **Plan:** [editor-history.md](../../plan/editor-history.md)

## Scope

`FileViewer.svelte` uses the store's history instead of its own and
installs `currentLocation` as the place reader: preview first, then caret
or selection, then the last landing, else the file as shown. Go to
Definition and references record their own place and open inside
`withoutHistory`; history steps too. A step to a place with a range
reveals it as today; one without a range opens the tab and sets the
preview from `preview` for Markdown and SVG files. Invalid paths are
skipped. The ← / → buttons and their titles speak of places, not only code
navigation.

## Likely files

`frontend/src/lib/components/common/go-to-file/FileViewer.svelte`,
`frontend/test/source-navigation.test.mjs`.

## Acceptance criteria and tests

- Leaving a Markdown file in preview records `preview: true`; going back
  to it turns the preview on.
- Going to a definition in another file records one place, not two.
- A step records nothing new; Back then Forward returns to the same place.
- The existing history tests (live caret/selection over the landing,
  blocked steps keep the stacks) still pass, adapted.

## Evidence

- `FileViewer.svelte`: the viewer's own `SourceHistory`, its version and
  the clearing effect are gone; `canGoBack` / `canGoForward` come from the
  files store, and an effect installs the place reader (only for the tab
  being left, so a reader never describes another file).
  `currentLocation` returns `{ path, preview: true }` while the preview is
  shown, else the caret or source selection, else the last landing in this
  file, else `{ path }` (the tab's scroll memory restores the view).
  `openLocation` records the place asked from with `files.visit` and opens
  inside `withoutHistory`. The new `openPlace` reveals a range as before,
  or opens the file (read-only when external) and, for Markdown and SVG,
  sets the preview from `preview`. `goHistory` steps the store and drops
  places no longer in the project, going on past them. The ← / → titles
  now say "the previous / next file or place".
- Tests (`source-navigation.test.mjs`, replacing the old viewer history
  test): `history reads the preview, the live editor/source selection, an
  old landing, else the file` and `a definition records where it came
  from once; steps go back and forward, preview and skipped paths
  included` (one place per definition, the open runs inside
  `withoutHistory`, blocked steps keep the stacks, Back to a Markdown file
  left in preview turns the preview on, Forward reveals the range again,
  a removed path is skipped, external and source-view places).
- `npm test`: 1137 pass, 0 fail (1 skipped, as before). `npm run check`:
