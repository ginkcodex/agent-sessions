# EH-03 — Mouse side buttons in Go to File

- **Status:** ✅ Done
- **Estimate:** 2 h
- **Depends on:** EH-02
- **Plan:** [editor-history.md](../../plan/editor-history.md)

## Scope

`GoToFileDialog.svelte` steps the viewer's history on the DOM's side
buttons (`mouseup`, buttons 3/4, via `navigationButton`) and on the native
`nav:mouse` event (`subscribeMouseNavigate`), only while Go to File is the
one open modal and no prompt or file operation holds it. App's own
handling stays: it cancels the webview's navigation and ignores the
buttons while a modal is open. TECH-NOTES' mouse section says the editor
uses them too.

## Likely files

`frontend/src/lib/components/common/GoToFileDialog.svelte`,
`frontend/src/lib/search.ts` (a helper for "only this modal is open"),
`TECH-NOTES.md`, a test in `frontend/test/go-to-file.test.mjs` or
`navigation.test.mjs`.

## Acceptance criteria and tests

- The helper is true for Go to File alone, false with another modal over
  it or hidden.
- Side buttons and `nav:mouse` reach `goHistory` once per press; the
  session list does not also move.

## Evidence

- `frontend/src/lib/search.ts`: `onlyOpenModal(dialog)`, true while that
  dialog is open and no other modal is (hidden ones do not count);
  `hasOpenModal` shares the lookup.
- `GoToFileDialog.svelte`: `sideButton` steps `viewer.goHistory` unless
  the dialog is closed, a file operation is busy or quitting, a rename or
  new-entry prompt is open, or another modal is open with it. A `mouseup`
  listener (`navigationButton`, buttons 3/4) and `subscribeMouseNavigate`
  call it; the dialog element is bound for the check. App is unchanged: it
  still cancels the webview's navigation and does not move the session
  list while a modal is open.
- `TECH-NOTES.md`: the mouse section says Go to File uses the buttons too.
- Tests: `search.test.mjs` (the modal test, extended for
  `onlyOpenModal`: alone, with a hidden modal, with another over it, hidden
  itself) and `go-to-file.test.mjs` `mouse side buttons step the viewer
  only while Go to File is the one open modal` (runs `sideButton` from the
  dialog's source: steps alone, nothing with another modal, closed, busy
  or prompting; the wiring on `mouseup` and `nav:mouse`, no `mousedown`;
  App's `hasOpenModal` guards). The dialog loaders in `go-to-file.test.mjs`
