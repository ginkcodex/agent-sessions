# SN-07 — Linux: skip replayed scrolls

- **Status:** ✅ Done
- **Estimate:** 2 h
- **Depends on:** SN-06
- **Plan:** [swipe-navigation-windows-linux.md](../../plan/swipe-navigation-windows-linux.md)

## Scope

Found after SN-06 on Linux (GNOME Wayland, 1.5× scale): one two-finger
swipe still went several steps through the history now and then.

A trace of real swipes showed that the swipe's `GtkEventControllerScroll`
gets every scroll twice, both copies with the same event time and deltas.
The copies come later, sometimes after the swipe's `scroll-end`, probably
from WebKit handing back the scrolls the page did not use. GTK then emits
`scroll-begin` for the copies, and they run up another 80 px. That made
one swipe send `nav:swipe` twice. The more the page has to draw after a
step, the later the copies come, so in real use it happened more often
than in the trace.

The fix: a scroll, `scroll-begin` or `scroll-end` no newer than the newest
one seen is a copy. Copies neither move the swipe nor begin a gesture.
Times wrap, so the times are compared by signed difference. GTK's timed end
(fingers resting and lifting without scrolling) has time 0 and still ends
the gesture.

Also: `AGENT_SESSIONS_TRACE_NAV=1` prints each gesture's begin, end,
scrolls and sends to stderr, plus each event Go sends to a window, to
debug touchpads without a rebuild.

## Acceptance criteria and tests

- In a real trace of seven back swipes that sent eight times, the new rule
  sends seven times.
- `go vet` and `go test` (desktop tags) pass; the desktop app builds on
  Linux with GTK 4.

## Evidence

- Trace (GNOME Wayland, GTK 4.22.4, WebKitGTK 2.52.6, 8 sessions opened,
  then 7 back swipes): 32 `scroll-begin` and 32 `scroll-end`, and 8
  dispatches. The swipe at 2524 s sent at 2524071 ms, ended at 2524140,
  then GTK began again on a copy from 2524094 and sent again at 2524125.
  Every scroll in it appears twice, e.g. `2524057 dx -13.58` back to back,
  and `2524087` once in order and again eight events later.
- Replaying that trace through the new rule (a throwaway script, not
  checked in) gives 7 sends, one per swipe. Each now sends after about
  85–115 px of real movement. Before, each delta counted twice, so a swipe
  sent after about 40 px.
- `go vet` and `go test -tags desktop,production ./cmd/agent-sessions/`
  pass; `go build -tags desktop,production` succeeds on Linux.
- On the same touchpad, the user ran the fixed build (`58a6f7f`) and
  reported that swipes step one at a time now.
- Not checked: X11, and
  whether the copies also reach other WebKitGTK versions. Swipes now need
  the full 80 px; if that feels too stiff, `SWIPE_DISTANCE` is the knob.
