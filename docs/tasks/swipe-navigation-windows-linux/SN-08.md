# SN-08 — Windows: one swipe, one step, no strokes

- **Status:** ➖ Superseded (by SN-09 and SN-10: on a real touchpad it still missed swipes and stepped several times)
- **Estimate:** 2 h
- **Depends on:** SN-06
- **Plan:** [swipe-navigation-windows-linux.md](../../plan/swipe-navigation-windows-linux.md)

## Scope

Found after SN-06 on Windows: one two-finger swipe still went several steps
through the history. Linux was fixed natively (SN-06, SN-07); on Windows the
page's wheel stream was still split into strokes, each swiping once. Real
streams from a Precision Touchpad dip and rise in ways the let-go rule
(SN-06) cannot tell from a new swipe. The user's call: swiping again in a
row (SN-05) was a bad trade; one swipe must be exactly one step.

The fix:

- No more strokes. A wheel gesture ends only after a 200 ms pause
  (`SWIPE_GESTURE_GAP`) and swipes once at most, whatever its speed does.
  A swipe that starts in the last one's momentum joins it and does not
  step: wait for the momentum to stop, or stop it, and swipe again.
- After a swipe, the detector does not swipe again for 500 ms
  (`SWIPE_COOLDOWN`). A gesture that reaches the distance in that time
  counts as the same swipe for the rest of its stream: the fingers paused
  long enough for the events to stop, then moved on.
- The scrolled flag is per gesture again, as before SN-05. On macOS and
  Linux, `nav:swipe` is dropped while a gesture that scrolled goes on.

## Acceptance criteria and tests

- Unit test: one stream steps once, through wobbles, dips to nothing and
  back, a speed-up, coalesced spikes, a reversal and long momentum; a pause
  of 250 ms mid-swipe does not step again; after the stream stops and the
  cooldown is over, the next swipe steps. A gesture that scrolled code does
  not swipe over the page in the same stream. It fails on the SN-06 rule.
- `npm test` and `npm run check` pass.
- On Windows, one swipe goes one step (SN-03).

## Evidence

- `swipeNavigation.ts`: `risesAgain`, `startStroke` and the `STROKE_*`
  constants are gone. A gap over `SWIPE_GESTURE_GAP` resets the gesture;
  `track` sets `swiped` at the distance and fires only when nothing
  scrolled and `SWIPE_COOLDOWN` has passed since the last swipe.
- Test (`search.test.mjs`): `one swipe is one step: a wheel stream swipes
  once at most, and not again right after`. It replaces the SN-05 and
  SN-06 tests, which expected several steps per stream. With the SN-06
  guard it fails: the swipe whose speed drops to 2–3 px and comes back
  steps three times instead of once.
- `npm test`: 1142 pass, 0 fail (1 skipped, as before). `npm run check`:
  0 errors, 0 warnings.
- The user on Windows with `launch16` (this code, uncommitted): no swipe
  navigated for the first minutes after start; after that some swipes
  navigated, some did not, and some went several steps. The wheel stream
  itself is the problem (see SN-09), so the page's detector was replaced by
  a native one. What stays of this task is the guard without strokes: its
  scrolled flag is per gesture (SN-10).
