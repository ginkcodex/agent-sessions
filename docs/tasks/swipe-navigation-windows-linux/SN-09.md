# SN-09 — Windows: native swipe from the touchpad's contacts

- **Status:** ✅ Done
- **Estimate:** 4 h
- **Depends on:** SN-08
- **Plan:** [swipe-navigation-windows-linux.md](../../plan/swipe-navigation-windows-linux.md)

## Scope

Found after SN-08 on Windows: for the first minutes after start no swipe
navigated, then swipes worked at random, sometimes not, sometimes several
steps. The page's wheel events change shape with the renderer's load: a
busy page gets them merged into a few large deltas (taken for a mouse
wheel, or too few events) and with gaps in the stream (a new gesture, and
another step). The user chose to read the touchpad natively.

- `internal/touchswipe`: pure Go, unit-tested on any OS. `Frames` joins a
  Precision Touchpad's reports into frames (hybrid mode: the contact count
  is only in a frame's first report). `Tracker` turns frames into at most
  one swipe per touch: two fingers, 10 mm sideways, more than twice the
  vertical; three or more fingers never swipe; a touch ends on an empty
  frame or after a second without frames.
- `cmd/agent-sessions/mousenav_windows.go`: a message-only window on a
  locked thread registers Raw Input for usage page `0x0D`, usage `0x05`
  with `RIDEV_INPUTSINK`; `WM_INPUT` reports are read with `HidP_*` from
  `hid.dll` (per device: finger link collections, contact ID, tip switch,
  X, Y, the X and Y size). A swipe goes as `nav:swipe` to the app window
  under the cursor, or nowhere.
- `navigateWindow` and the trace move to a file every desktop build
  shares. On Windows `AGENT_SESSIONS_TRACE_NAV=1` writes the trace to
  `%TEMP%\agent-sessions-nav-trace.log`.

## Likely files

`internal/touchswipe/`, `cmd/agent-sessions/mousenav*.go`, `TECH-NOTES.md`,

## Acceptance criteria and tests

- Unit tests: one swipe sends once, however long it goes on, both ways;
  short, vertical, one-finger and three-finger touches never send; a
  touch that lifts and comes back sends again; hybrid frames join; a lost
  lift ends the touch after a second; sizes from HID units (cm, inch, none).
- `go vet` and `go test ./internal/touchswipe/`; the Windows desktop app
  cross-compiles (`make windows-app`); the Linux desktop build still
  compiles.
- The layout reader reads the real touchpads of a Windows machine.

Real swipes on Windows, also while the app is busy, are checked in SN-03.

## Evidence

- `internal/touchswipe`: `Frames` and `Tracker` as above, plus `Scales`
  (mm per HID unit from cm or inch units and the unit exponent; a size
  outside 20–400 mm, or none, is taken as 100 mm wide). Besides the scope:
  a touch that first moves 10 mm up or down is a scroll and never swipes,
  so scrolling down and up with a little drift does not navigate.
- `mousenav_windows.go`: reader thread, `WM_INPUT` parsing, device cache
  (cleared on `WM_INPUT_DEVICE_CHANGE` removal), dispatch to the window
  under the cursor (`WindowFromPoint`, then `GetAncestor(GA_ROOT)`, matched
  against the app windows' `NativeWindow()`). Compile-time checks keep
  `HIDP_CAPS` at 64 bytes and `HIDP_VALUE_CAPS` at 72.
- `mousenav.go` now holds `traceNavigation`, `traceNav` and
  `dispatchNavigation` for every desktop build; `navigateWindow` stays in
  `mousenav_native.go` for Linux and macOS.
- `go test ./internal/touchswipe/`: 5 tests pass (one swipe, one step;
  touches that never swipe; touch ends; hybrid frames; scales).
- `mousenav_windows_test.go`, cross-compiled and run on this Windows
  machine through WSL: `TestTouchpadLayouts` reads both Precision
  Touchpads, an ELAN `04f3:3293` (5 finger slots, contact count, X
  0..4151, Y 0..2416, 132 x 77 mm) and a Logitech `046d:c548` (5 slots,
  117 x 75.5 mm). `TestTouchpadListen` registers for touchpad Raw Input.
- `go vet` for Windows amd64 and Linux (desktop tags); `go build` for
  Windows arm64; `go test -tags desktop,production ./cmd/agent-sessions/`
  on Linux; the Linux desktop app builds with GTK 4. `go vet ./...` passes;
  `go test ./...` passes except `internal/launch`'s
  `TestPanelPowerShellPromptCwd`, which fails the same way on the commit
  before this change (PowerShell given a WSL path).
- 2026-11-08, the user on Windows with `launch17`: real swipes work, one
  step per swipe (SN-03).
- Not checked: which report mode (hybrid or parallel) the user's pad used,
  and no trace was taken.
