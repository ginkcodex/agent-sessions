# KD-06 — Turn off spellcheck, autocorrect and text substitutions in every field

- **Status:** 🟡 Partial — built and tested; the desktop app check (last criterion) has not run
- **Estimate:** 3 h
- **Depends on:** KD-04
- **Plan:** [keyboard-diagnostics.md](../../plan/keyboard-diagnostics.md)

## Scope

The user asked that autocorrect and spellcheck be off in every text input.
Do it in the two layers described in the plan (section "Text checking off
everywhere"):

- `frontend/src/lib/textInputDefaults.ts`: inherited `spellcheck` and
  `writingsuggestions` on `<html>`, plus a capture `focusin` listener that sets
  `spellcheck`, `autocorrect`, `autocapitalize` and `writingsuggestions` on
  each text field. Install it in `main.ts` on every platform.
  `keyOrderGuard.ts` shares the same text field check.
- `cmd/agent-sessions/textcheck_darwin.go` and `.m`: register `NO` for
  WebKit's text-checking defaults in an `init`, before any web view exists.
  Add a no-op for other platforms if the build needs one (it does not: the
  only caller is the darwin file's own `init`).

## Acceptance criteria and tests

- jsdom tests: `<html>` has the inherited attributes; a focused textarea,
  text input and contenteditable get all four; checkboxes, buttons and
  non-text inputs are untouched; a field that asked for `spellcheck="true"`
  is turned off; removing the listener stops it.
- A darwin desktop Go test reads the registered defaults back as `NO`.
- Go tests, frontend tests, `npm run check` and `npm run build` pass.
- In the desktop app, no red spelling underline appears in the chat composer
  or the file editor, and macOS text replacement (for example `omw`) does
  not fire.
