# KD-05 — Keep OpenKey's Backspaces before its replacement text

- **Status:** 🟡 Partial (built and verified with unit tests and a WKWebView replay; not yet confirmed in the desktop app while the fault is present)
- **Estimate:** 4 h
- **Depends on:** KD-04
- **Plan:** [keyboard-diagnostics.md](../../plan/keyboard-diagnostics.md)

## Scope

KD-04 found that, while the fault is present, WebKit gives the page some of
OpenKey's Backspace keydowns after the replacement keydown, and their
`deleteContentBackward` removes the replacement. The Backspace keyups still
arrive first.

Build the key order guard described in the plan (section "Fix: key order
guard"):

- `frontend/src/lib/keyOrderGuard.ts`: a pure state machine that pairs
  Backspace keydowns and keyups and returns pass, drop, or repair (deletes
  plus text), with a 100 ms expiry. Plus a DOM layer: a capture listener on
  the window that applies repairs to text fields with `execCommand` and to
  registered terminals as DELs plus the text, and resets on blur.
- `frontend/src/main.ts`: install it in the macOS desktop app.
- `TerminalView.svelte`: register each terminal's helper textarea.
- `keyboardDiagnostics.ts`: record the guard's `keyorderguard` events.

The option of a native input context reset stays open if the guard is not
enough.

## Acceptance criteria and tests

- A unit test replays the page key order from the KD-04 log through the guard
  and a simulated text field and gets
  `cộng hòa xã hội chủ nghĩa Việt Nam, độc lập tự do hạnh phúc`. Without the
  guard, the same replay gives the broken text.
- The same burst through a registered terminal sends DELs before the text.
- Normal typing, held Backspace, OpenKey bursts in the normal order, a stray
  early keyup older than 100 ms, and Backspace keydowns that come late but
  before the text are all unchanged.
- The user confirms in the desktop app, ideally with a fault log that shows
  the guard's repairs.

## Evidence

- What was done:
  - `keyOrderGuard.ts`: `createKeyOrderGuard` (the state machine),
    `typedText`, `registerKeyOrderTerminal` and `installKeyOrderGuard` (the
    window capture listener, `execCommand` for text fields, DELs plus text
    for terminals, reset on window blur, and a `keyorderguard` event for
    each repair or drop).
  - `main.ts` installs it in the macOS desktop app only.
    `TerminalView.svelte` registers each terminal's helper textarea on
    macOS.
  - `keyboardDiagnostics.ts` records `keyorderguard` events with their
    action and delete count, so a log shows each correction.
- Tests:
  - `test/key-order-guard.test.mjs` (10 tests). Replaying the page order
    from the KD-04 log
    (`test/fixtures/openkey-reordered.json`, keydown and keyup only) through a
    simulated text field gives the broken text without the guard and
    `cộng hòa xã hội chủ nghĩa Việt Nam, độc lập tự do hạnh phúc` with it. The
    other tests cover:
    - one burst, and late keydowns that still come before the text;
    - normal typing, held Backspace, and a burst in the normal order;
    - expiry of an early keyup and of an owed keydown, and reset;
    - the spacer, shortcuts and named keys;
    - the terminal path (DELs before the text, late keydowns cancelled) and
      the text field path (`execCommand`);
    - read-only fields and non-text targets, which are left alone, and
      window blur.
  - `test/keyboard-diagnostics.test.mjs` adds a test for the recorded
    `keyorderguard` record.
  - `npm test`: 1534 tests, 1533 pass, 1 skipped, 0 fail. `npm run check`:
    0 errors, 0 warnings. `npm run build` passes.
- WKWebView replay. A Swift harness sent NSEvents for `cong`, then OpenKey's
  burst, to a page with a textarea and real xterm 6. It ran once in
  OpenKey's order and once in the order from the fault log (spacer, 4
  Backspace keyups, `ông`, then 4 Backspace keydowns):

  | Target | Order | Without guard | With guard |
  |---|---|---|---|
  | textarea | OpenKey's | `công` | `công` |
  | textarea | fault log | `cong` | `công` (1 repair, 4 drops; `input` fired for each edit) |
  | xterm | OpenKey's | `công` | `công` |
  | xterm | fault log | `cong` | `công` (1 repair, 4 drops) |

- Not checked:
  - The desktop app while the fault is present; the fault cannot be caused
    on demand.
  - CodeMirror and other contenteditable editors (the guard uses
    `execCommand` there too, untested). Undo after a repair.
  - Other tools (EVKey, GoTiengViet) that use the same Backspace-then-text
    pattern.
