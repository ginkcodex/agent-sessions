# FS-06 — Editor and viewer font family and size

- **Status:** ✅ Done
- **Estimate:** 4 h
- **Depends on:** FS-03
- **Plan:** [font-settings.md](../../plan/font-settings.md)

## Scope

- `SourceView.svelte`: `font-family: var(--editor-font-family, var(--font-mono))`
  and `font-size: var(--editor-font-size, 0.78rem)`; presentation mode's inline
  size still overrides.
- `fileEditor.ts` theme: the same two properties on `.cm-scroller` / `&`, so
  the viewer and the editor match.
- Re-measure on change: CodeMirror `requestMeasure()` (or move the font into a
  `Compartment` and reconfigure) when the editor font or size changes while a
  file is open; check line numbers, cursor, selection and click positions.
- `FileViewer.svelte`: add the editor size and font to the dependencies that
  today list `presentationFontSize` (change-navigation lines, overview-ruler
  measurer, find highlights, saved scroll position).
- Line-number gutter width (`--digits` in `ch`) follows the font.

`components/common/go-to-file/SourceView.svelte`, `fileEditor.ts`,

## Acceptance criteria

- With defaults, computed size and family are unchanged (0.78rem,
  `--font-mono`).
- With a chosen font and size, the viewer, diffs and editor all use them,
  and switching between viewing and editing does not move the text.
- Changing the setting while a file is open in the editor re-measures it.
- Presentation mode still overrides and returns to the saved size on exit.

## Tests

Theme test on `fileEditor.ts` (the CSS uses the variables with today's
fallbacks); a test that a preference change requests a CodeMirror measure;
SSR check of `SourceView` styles. Manual layout checks go to FS-09.

## Outcome

- `SourceView.svelte`: the source text uses
  `var(--editor-font-family, var(--font-mono))` and
  `var(--editor-font-size, 0.78rem)`. Presentation mode's inline size still
  wins. The `--digits` gutter is in `ch`, so it follows the font.
- `fileEditor.ts`: `EDITOR_FONT_SIZE` and `EDITOR_FONT_FAMILY` (the same two
  values) move from the main theme into a `font` compartment. That
  compartment holds one of two identical font themes. The new controller
  method `remeasure()` swaps it for the other one. CodeMirror measures its
  text again only when its theme facet changes, and the facet is the themes'
  class names, so the swap is enough. Reusing two themes means a font change
  mounts no new styles.
- `FileEditor.svelte`: an effect calls `remeasure()` when
  `preferences.editorFont` or `editorFontSize` changes while the editor is
  mounted. It does not run on mount.
- `FileViewer.svelte`: the change-navigation lines are gathered again when the
  editor font or size changes. `createFileFind` gets an optional
  `getEditorFont` getter (renamed `getFontSetting` in FS-07), so find gathers its lines and repaints after a
  change.
- The overview ruler needed no change: its `ResizeObserver` on the scroller's
  children already sees the new content height. Saved viewer and editor
  positions are stored as a line plus an offset, so they need no change
  either.

## Evidence

- `test/file-editor.test.mjs`, 3 new tests:
  - The real themes' CSS has `font-size: var(--editor-font-size, 0.78rem)`
    and `font-family: var(--editor-font-family, var(--font-mono))`, with no
    fixed 0.78rem left, and SourceView's `.code` has the same two values and
    line height 1.5.
  - `remeasure()` changes the theme modules and a second call returns to the
    first. The document, selection and history are kept, and the call does
    nothing after destroy.
  - FileEditor remeasures only when the setting changes, and FileViewer and
    find depend on the setting (both source checks).
- `test/go-to-file.test.mjs`: SourceView has no inline size outside
  presentation mode, and presentation mode still renders 22px.
- `npm test`: 1115 tests, 1114 pass, 0 fail, 1 skipped. `npm run check`:
  0 errors, 0 warnings. `npm run build`: passes. `git diff --check`: clean.
- Browser check (Vite dev server, Chromium, mock `main.go`):
  - Defaults: the viewer and the editor are both 14.04px JetBrains Mono, and
    line 6 starts 113.2px down in the viewer and 113.3px down in the editor.
  - Editor at 20px with DejaVu Sans Mono, set while the file is open in the
    editor: lines are 30px, and line 6, its line number and the cursor all
    sit at 158px (cursor 161px, 24px tall). A click after the first
    character of line 1 puts typed text there.
  - The viewer at the same setting puts line 6 at 158px too, so switching
    modes does not move the text.
  - With the swap turned off as a check, the text grew but the line numbers
    and cursor stayed at 113px and 18px. So the remeasure is needed.
  - Presentation mode with the editor at 16px shows 20px, and exiting returns
    to 16px.
- Not checked here: diffs, history tabs and wrapped long lines at other
  sizes, and the Windows app. Those go to the FS-09 manual pass.
