- **Status:** ✅ Done
- **Estimate:** 4 h
- **Depends on:** FS-01
- **Plan:** [font-settings.md](../../plan/font-settings.md)

## Scope

- Convert every text size in the rest of the session content to
  `calc(var(--session-font-size, 14.5px) * var(--type-…))`, using the token
  the plan's table assigns to today's px value:
  - 13.7 px reasoning text, 12.8 px tool name → `--type-code`;
  - 12.48 px and 12 px → `--type-small`;
  - 11.52 px and 11.2 px → `--type-label`;
  - 10.88 px and 10.4 px → `--type-tag`.
  Files: `MessageBubble.svelte`, `parts/ToolPart.svelte`, `PatchPart.svelte`,
  `ReasoningPart.svelte`, `CompactionPart.svelte`, `NoticePart.svelte`,
  `ImagePart.svelte`, `SubagentLink.svelte`, and any other component rendered
  inside `.messages-scroll-area` found by the scan. No component keeps its own
  size.
- Leave unscaled, and list in the scan test's exceptions with a reason, only
  non-text items: icons and icon glyphs (role icon, the 14 px reset glyph),
  images, and the view controls in the scroll area (Load earlier,
  end-of-transcript marker, empty notice) that follow the app size.
- Audit fixed `height`/`line-height` in px on text containers (badges, tool
  headers, pills, one-line summaries) and switch them to unitless line
  heights or `min-height`, so larger text is not clipped.
- Scan test: reads the `<style>` blocks of the session-content components
  and `MarkdownDoc`, and fails on a `font-size` that is not body × one of the
  eight tokens, `em` × `--type-inline-code`, or a listed exception.

- The scan test passes; its exceptions are non-text items only, each with a
  reason.
- At a 14.5 px body each converted size is its token's size, within 0.55 px
  of today's (the tool name moves +0.54 px, 12.8 → 13.34 px).
- No fixed-px line height or height remains on a text container.

## Tests

The scan test and the mapping test (old px → token) for every converted
rule; existing transcript tests pass.

## Outcome

- 32 sizes converted to `calc(var(--session-font-size, 14.5px) * var(--type-…))`
  by the mapping above: `MessageBubble` 5, `ToolPart` 11, `PatchPart` 5,
  `ReasoningPart` 2, `CompactionPart` 4, `NoticePart` 2, `ImagePart` 2,
  `SubagentLink` 1. The notice pill's ℹ️ sits inline with its text, so it
  scales with it (`--type-small`).
- One exception: `.reset-level` in `MessageBubble`, the ↻ glyph in a fixed
  20 px button, commented in the source and listed in the test with its
  reason. The other components rendered in the scroll area are popups or view
  controls (`SelectionTranslation`, `ContextMenu`, the loading, empty and
  error states, `TranscriptView`'s Load earlier and end-of-transcript marker)
  and follow the app size, as planned; they are not in the scan.
- Clipping audit: no px `line-height` in the session parts. Fixed heights are
  on non-text items only (role icon and reset button 20 px, the compaction
  divider's 1 px rule) and the image placeholder box (160 × 100 px, one line
  of text, ≤ 20 px at the largest size). `max-height`s are scrolling areas
  (tool output 350 px, diff 400 px, image 240 px). Nothing changed.
- The plan said the largest move was 0.5 px; the tool name moves 0.54 px. The
  plan, README and FS-01 now say 0.55 px; the test allows the same.
- `frontend/test/type-scale.test.mjs` scans the eight session files too, with
  the exception list, a stale-exception check, and a mapping test: each
  converted rule's old px (recorded per selector) gets the planned token and
  stays within 0.55 px, and every scaled rule in a file is accounted for.
