# FS-04 — Shared monospace font picker

- **Status:** ⬜ Not started
- **Estimate:** 2 h
- **Depends on:** —
- **Plan:** [font-settings.md](../../plan/font-settings.md)

## Scope

- Extract the dropdown, Refresh button, "(unavailable)" handling, error and
  sample from `TerminalFontSetting.svelte` into a shared component
  (`MonoFontSetting.svelte`) with props for the heading, ARIA label, value,
  `onChange`, hint and sample text.
- Fetch the installed-font list once per Settings opening and share it
  between pickers (a small store or module-level cache with Refresh), so the
  terminal and editor pickers do not call `TerminalFonts()` twice.
- `TerminalFontSetting` becomes a thin wrapper; its look and text stay the
  same.

## Likely files

`components/common/TerminalFontSetting.svelte`,
`components/common/MonoFontSetting.svelte` (new), a font-list store or
helper, `frontend/test/terminal-font-settings.test.mjs`,
`frontend/test/settings.test.mjs`.

## Acceptance criteria

- The terminal font picker renders and behaves as before (existing tests
  pass unchanged or with only import-path updates).
- Two pickers on one page make one backend call; Refresh refetches for both.

## Tests

SSR test of the shared component (default label, unavailable font, sample);
a test that two consumers share one fetch.
