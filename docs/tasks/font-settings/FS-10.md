# FS-10 — Keep the viewer's place when the editor or docs size changes

- **Status:** ✅ Done
- **Estimate:** 1 h
- **Depends on:** FS-06, FS-07
- **Plan:** [font-settings.md](../../plan/font-settings.md)

Found in FS-09. FS-07 relied on Chromium's CSS scroll anchoring to keep the
docs preview in place when its text size changes. WebKit (the Linux and
macOS apps) has none, and the Go to File viewer keeps a pixel `scrollTop`.
So a new size there slides other text under the reader. In Chromium with
`overflow-anchor: none`, a docs preview scrolled to Section 19 showed
Section 11 at 28px and Section 23 at 11px. The source view did the same
with the editor size: line 144 became line 84 at 24px and line 183 at 11px.

## Scope

- Move the row logic from `transcriptAnchor.ts` into a shared
  `scrollAnchor.ts` (`rowAnchor`, `firstVisibleRow`, `restoreRow`), and
  build the transcript's message anchor on it.
- `FileViewer.svelte`: when the editor font, the editor size or the docs
  size changes, take the first visible row before the new size lays out, and
  put it back after the update:
  - the first visible top-level Markdown block in the preview;
  - the first visible source line (`data-source-line`) in the source view.

  The editor is skipped, because CodeMirror keeps its own place.

## Acceptance criteria

- With CSS scroll anchoring off, the first visible block or line stays first
  at the smallest and largest sizes, and the default size returns to the
  same `scrollTop`.
- The transcript tests still pass.

## Outcome

- New `src/lib/scrollAnchor.ts`. `transcriptAnchor.ts` keeps its API and
  finds messages by index, as before, using the shared helpers.
- `FileViewer.svelte` has a new `$effect.pre` on the three settings. It
  restores the row after `tick()`, not in a plain `$effect`. The root
  properties are set by an `$effect` in App, and the order of App's and
  FileViewer's effects is not something to rely on. `tick()` resolves after
  the whole update, before the next paint.
- The test loader in `test/file-viewer-edit.test.mjs` maps the new module.

## Evidence

- New `test/scroll-anchor.test.mjs` (3 tests):
  - picking the first visible row and its anchor;
  - a row that started in view, or half above it, keeping its place when
    every row is scaled ×2 and ×0.5;
  - a source check of the FileViewer effect: it skips the editor, covers
    `.markdown-doc` blocks and `data-source-line`, and restores after
    `tick()`.
- `test/transcript-font-size.test.mjs`: its 6 tests pass on the shared
  helpers.
- `npm test`: 1125 tests, 1124 pass, 0 fail, 1 skipped. `npm run check`:
  0 errors, 0 warnings. `npm run build`: passes. `git diff --check`: clean.
- Browser check (Vite dev server, Chromium, a 40-section Markdown file saved
  over the mock README), with `overflow-anchor` on and off:
  - Docs preview halfway down: Section 19 stayed the first heading at 28px,
    11px and the default, and the default came back to `scrollTop` 2591.
  - Source view halfway down: line 144 stayed the first line at 24px, 11px
    and the default, and the default came back to `scrollTop` 3027.
  - With the restore turned off as a check, and anchoring off, the numbers
    were the jumps listed above. So the restore is needed.
- Not checked: the real WebKitGTK and WebView2 apps, and diffs and history
  tabs. Chromium with anchoring off stands in for WebKit here.
