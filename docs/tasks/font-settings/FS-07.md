# FS-07 — Project docs preview size

- **Status:** ✅ Done
- **Estimate:** 1 h
- **Depends on:** FS-01, FS-03
- **Plan:** [font-settings.md](../../plan/font-settings.md)

## Scope

- `FileViewer.svelte`: the Markdown preview sets `--markdown-font-size` to
  the presentation size when presenting, else
  `var(--docs-font-size, 14.5px)`. Since FS-01 sizes every role from that
  body, headings, tables, code and tags follow with their ratios.
- Find highlights and the saved preview scroll position repaint on change.
- The import and handoff dialogs keep their 13 px body.

## Likely files

`components/common/go-to-file/FileViewer.svelte`,
`frontend/test/go-to-file.test.mjs`.

## Acceptance criteria

- Default: the preview body is 14.5 px as today.
- A set size applies to the preview only, and the heading-to-body and
  code-to-body ratios are the same at 11, 14.5 and 28 px.

## Tests

SSR check of the preview's style attribute with and without the setting and
in presentation mode.

## Outcome

- `FileViewer.svelte`: the Markdown preview sets `--markdown-font-size` to
  `var(--docs-font-size, 14.5px)`. While presenting it uses the presentation
  size. The value is a variable, so a change in Settings applies without a
  new render.
- Find: FS-06's getter became `getFontSetting`, and it now includes the docs
  size too. Find gathers its lines and repaints when the size changes.
- The saved preview scroll position is a pixel `scrollTop`, as before. While
  the preview is open, Chromium's scroll anchoring keeps the visible text in
  place when the text grows.
- The import and handoff dialogs do not set `--markdown-font-size`, so they
  keep MarkdownDoc's 13px fallback.

## Evidence

- `test/file-viewer-edit.test.mjs`: a new SSR test checks the preview's
  `style` attribute:
  - with the preview on, it is
    `--markdown-font-size: var(--docs-font-size, 14.5px);`;
  - while presenting at 26px, it is `26px`;
  - with the preview off, there is no preview.

  For this, the test's loader can start with the preview toggle on.
- `test/file-editor.test.mjs`: the find dependency check now matches the
  renamed getter.
- `npm test`: 1116 tests, 1115 pass, 0 fail, 1 skipped. `npm run check`:
  0 errors, 0 warnings. `npm run build`: passes. `git diff --check`: clean.
- Browser check (Vite dev server, Chromium). The mock README was edited to
  hold h1–h3, inline code, a table and a code block, then saved and
  previewed. The docs size was set live to 14.5, 11 and 28px:
  - the body was 14.5, 11 and 28px;
  - the ratios to the body were the same at every size: h1 1.43, h2 1.25,
    h3 1.08, code block 0.92, table cell 0.92 and inline code 0.85.

  With the docs size at 28px, the source view stays at the editor's 14.04px.
  I also looked at a screenshot at 28px.
- Not checked: the import and handoff dialogs in the browser (the reason
  above comes from reading the code), and scroll anchoring after a change.
  Both go to FS-09.
