# RF-30 — Keep recovered language sessions healthy during status refresh

- **Status:** ✅ Done
- **Estimate:** 1 h
- **Depends on:** RF-20
- **Plan:** [review-fixes.md](../../plan/review-fixes.md)

## Scope

Found during RF-20 integration review on 2026-11-15: Refresh samples a failed
session, schedules recovery, then publishes the sampled failure. Recovery can
finish first, leaving the healthy provider falsely failed indefinitely.
Serialize current-session status sampling and failure publication with recovery,
preserving multi-context partial-coverage behavior.

## Likely files

- `internal/codediagnostics/live_owner.go`
- `internal/codediagnostics/live_status.go`
- `internal/codediagnostics/live_retry_test.go`

## Acceptance criteria and tests

- A deterministic regression forces recovery between an old failure sample and
  status publication; the recovered provider stays healthy.
- Concurrent refresh and explicit/automatic recovery do not restore stale failure.
- Existing multi-context and recovery tests pass, including race checks.

## Evidence

Fix: `Refresh` now recovers every config first, then `refreshStatus` takes
`Manager.mu` (the lock recovery and its status reset already hold), re-samples
each session's current info, tallies per provider and publishes through the new
`liveFailureLocked` / `liveNoticeLocked`. `LiveFailure` / `LiveNotice` are thin
locking wrappers, so external callers are unchanged. Multi-context behavior
(failed only when no context runs, otherwise a partial-coverage notice) is kept.

Tests (all run):

- `TestLiveRefreshDoesNotRestoreRecoveredFailure` (automatic and manual
  subtests) forces failure sample, then recovery, then status publication, and
  asserts the provider stays `idle` with no Failure; it repeats after 4
  concurrent Refresh loops plus a current-generation publish.
- Without the fix (status loop made to publish a stale failed sample) both
  subtests fail with "recovered provider falsely failed"; fix restored after.
- `go test -race ./internal/codediagnostics -run 'TestLiveRefreshDoesNotRestore|TestLiveAutomatic|TestLiveRetry|TestLiveOwner|TestDocumentsMulti|Test.*Context.*Fail' -count=5`: ok.
- `go vet ./internal/codediagnostics`: clean.
- `go test -race ./internal/codediagnostics -count=1`: ok (79 s).
- `go test ./internal/engine -run 'CodeDiagnostics|Live'`: ok.
- `GOOS=windows go test -c ./internal/codediagnostics`: compiles.
