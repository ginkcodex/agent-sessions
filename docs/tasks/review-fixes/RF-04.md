# RF-04 — Git blame and submodule diff never run a repository's textconv

- **Status:** ⬜ Not started
- **Estimate:** 2 h
- **Depends on:** None
- **Plan:** [review-fixes.md](../../plan/review-fixes.md)

## Scope

`internal/files/blame.go:87` runs `git blame --line-porcelain` without
`--no-textconv`, and Git honours `diff.<driver>.textconv` in blame. A
repository's `.gitattributes` plus its config can therefore run a program
when the user hovers blame. A reviewer reproduced this with git 2.53.
`git_submodule.go:52` has the same gap. Checked: the blame call has no
`--no-textconv`.

- Add `--no-textconv` to blame and to the submodule diff.
- Audit the other `git` calls in `internal/files` for textconv, external
  diff and filter drivers.
- `git status` clean and process filters stay with
  [IS-06](../code-diagnostics-ignore-scope/IS-06.md); link it from here.

## Likely files

`internal/files/blame.go`, `git_submodule.go`, tests next to
`fsmonitor_test.go`.

## Acceptance criteria and tests

- A test repo with `*.bin diff=evil` and a `diff.evil.textconv` that writes a
  marker file: blame, and the submodule diff, never create the marker.
