# RF-04 — Git blame and submodule diff never run a repository's textconv

- **Status:** ✅ Done
- **Estimate:** 2 h
- **Depends on:** None
- **Plan:** [review-fixes.md](../../plan/review-fixes.md)

## Scope

`internal/files/blame.go:87` runs `git blame --line-porcelain` without
`--no-textconv`, and Git honours `diff.<driver>.textconv` in blame. A
repository's `.gitattributes` plus its config can therefore run a program
when the user hovers blame. A reviewer reproduced this with git 2.53.
`git_submodule.go:52` has the same gap. Checked: the blame call has no
`--no-textconv`.

- Add `--no-textconv` to blame and to the submodule diff.
- Audit the other `git` calls in `internal/files` for textconv, external
  diff and filter drivers.
- `git status` clean and process filters stay with
  [IS-06](../code-diagnostics-ignore-scope/IS-06.md); link it from here.

## Likely files

`internal/files/blame.go`, `git_submodule.go`, tests next to
`fsmonitor_test.go`.

## Acceptance criteria and tests

- A test repo with `*.bin diff=evil` and a `diff.evil.textconv` that writes a
  marker file: blame, and the submodule diff, never create the marker.

## Evidence

Done on 2026-11-14 at `df9b94c`, with Git 2.53.0 on Linux.

- `blame.go`: `git blame` now passes `--no-textconv`.
- `git_submodule.go`: the submodule diff now passes `--no-textconv`. With
  `--submodule=short`, Git did not run the textconv for a gitlink even
  before the change. The flag keeps that true if the diff options change.
- `files.go`: the comment on `gitNoFsmonitor` now states the rule. Every
  `blame` and `diff` (`diff-tree` included) passes `--no-textconv`, and
  every diff also passes `--no-ext-diff`.
- Audit of `internal/files`: every other `diff` and `diff-tree` call
  already passed `--no-textconv`:
  - `files.go:430`
  - `git_diff.go:150`
  - `git_history_diff.go:88`
  - `git_history_compare.go:111` and `:430`
  - `git_history_commit.go:39`
  - `git_history_actions.go:281`
  - `git_history_list.go:243`

  The `cat-file` reads don't apply textconv. No other package runs
  `git blame` or `git diff`.
- New `textconv_test.go`, `TestGitReadsDoNotRunRepositoryTextconv`:
  - The test builds three repositories: the workspace's own, a nested one,
    and one recorded as a gitlink.
  - Each has `* diff=evil` in `.gitattributes`, a `diff.evil.textconv`
    script that writes a marker file, and a modified `data.dat`.
  - It calls `BlameFile` in each repository, `ReadGitDiff` on the files, the
    submodule diff (index, HEAD and staged), and `GitHistoryList`. None may
    create the marker.
  - Before the fix the test failed on all three `BlameFile` cases. After it,
    the test passes.
- `go test -count=1 ./internal/files/...`, `go vet ./internal/files/` and
  `gofmt -l internal/files`: all clean.

Found along the way, and left to IS-06: `git blame` of a modified file still
runs the repository's `filter.<name>.clean`. Checked by hand: a clean filter
that writes a marker ran under
`git -c core.fsmonitor=false blame --no-textconv`. This is a filter, not a
textconv, so it falls under
[IS-06](../code-diagnostics-ignore-scope/IS-06.md), which now lists blame.

Not checked: Windows. The test skips there because its textconv is a shell
script. The flags do not depend on the platform.
