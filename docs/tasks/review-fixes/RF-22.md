# RF-22 — Port forwarding on OpenSSH before 8.7

- **Status:** ✅ Done
- **Estimate:** 2 h
- **Depends on:** None
- **Plan:** [review-fixes.md](../../plan/review-fixes.md)

## Scope

`internal/remote/forward.go:53` passes `-o ForkAfterAuthentication=no`, which
OpenSSH before 8.7 rejects ("Bad configuration option"). That includes
Windows 10's built-in 8.1, Ubuntu 20.04 (8.2) and RHEL 8 (8.0). Reviewer
finding, not tested.

- Omit the option, since it is the default, or add it only when `ssh -V`
  reports 8.7 or later.

## Acceptance criteria and tests

- A test of the argument list per `ssh -V` version.
- One forward through an OpenSSH 8.x client, if one is at hand.

## Evidence

- Verified `BuildForwardCmd` unconditionally emitted `ForkAfterAuthentication=no`;
  its only production caller is the desktop forward lifecycle in
  `internal/app/port_forwards.go`. Removed that option; foreground operation is
  the default, so no SSH version probe or version-specific branch is needed.
- `TestForwardCommand` now rejects any generated `ForkAfterAuthentication=` or
  `-f` argument and still checks loopback binding, independent mux settings,
  forwarding failure detection, disabled local/remote commands and no TTY.
  The same version-independent argv is used for OpenSSH 8.0/8.1/8.2 and newer.
- Passed `go test -count=1 ./internal/remote ./internal/app` and
  `go test -race -count=1 ./internal/remote ./internal/app` (as part of the
  affected-package runs for RF-22/RF-23/RF-27).
- Limitation: no OpenSSH 8.x client was available; the installed client reports
  OpenSSH 10.2p1. No real pre-8.7 forwarding connection was run. Explicit
  user-supplied SSH options/configuration remain unchanged.
