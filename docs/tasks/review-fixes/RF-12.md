# RF-12 — A missing watch root never watches `$HOME` recursively

- **Status:** ✅ Done
- **Estimate:** 2.5 h
- **Depends on:** None
- **Plan:** [review-fixes.md](../../plan/review-fixes.md)

## Scope

`internal/watch/watch.go:390-398`: when a root doesn't exist, the watcher
watches `nearestExistingDir`, which for a user without Codex is `$HOME`.
`anchor` is never set. Directories later created directly in `$HOME` match
the owner check (`ownersLocked` looks at the parent), so `addTreeLocked`
walks them recursively while holding `w.mu`. Each change in `$HOME` also
queues a full Codex rescan. Checked.

- Set `anchor` per provider (for example `~/.codex`; skip if that is missing
  too), or watch the anchor only for the creation of the next path component
  of the root.
- An event under an anchor is only a candidate root creation, never a tree
  to add.

## Acceptance criteria and tests

- A test: with `sessions` missing, creating `$HOME/proj/a/b` adds no watches
  and schedules no rescan. Creating the real root installs its watches.

## Evidence

Done on 2026-11-14, in `internal/watch/watch.go`.

Design (the scope's second option):

- When a root is missing, its nearest existing directory is watched as an
  **anchor**. Each provider keeps its anchors in its own `anchors` set, apart
  from `watched`.
- An event in an anchor counts only if it creates a directory on the root's
  path. That root is then installed again: either it now exists and is
  watched and rescanned in full, or the deeper directory becomes the
  anchor. Any other event under an anchor is dropped, with no watch and no
  rescan.
- When a root, or a directory above it, is removed, the root is installed
  again, so it gets an anchor and is found when it comes back. Before, a
  deleted `sessions` directory was never watched again.
- The unused `watchRoot.anchor` field is gone.

Found along the way, and fixed in the same change, because it is the same
fault: in a **non-recursive** root, a new directory was also added as a
recursive tree and queued a full rescan. The non-recursive roots are the
folders of Codex's index database and of OpenCode's `opencode.db`, so an
OpenCode `snapshot/` directory was walked in full. Now only a directory
inside a recursive root is added as a tree. A new directory anywhere else
matters only if it lies on the path to a missing root.

Tests, in the new `anchor_test.go` (an internal test that records every
`fsnotify` Add):

- `TestMissingRootWatchesOnlyForItsCreation`, with `~/.codex/sessions`
  missing:
  - The only watch is `$HOME`.
  - Creating `$HOME/proj/a/b`, a `rollout-x.jsonl` inside it and
    `$HOME/notes.txt` adds no watches and causes no rescan.
  - `~/.codex` becomes the anchor, and `~/.codex/log/deep` is ignored.
  - Creating `sessions/2026/11` watches the tree and rescans in full, and a
    rollout written in it is reported.
  - Removing `sessions` and creating it again rescans again.
- `TestNonRecursiveRootIgnoresNewDirectories`: a new `snapshot/a/b` beside
  `opencode.db` adds no watches and causes no rescan. A database write still
  rescans.
- Against the old `watch.go`, both tests fail:
  `proj`, `proj/a` and `proj/a/b` were watched, and `snapshot/a/b` was
  watched and rescanned once. With the fix they pass.
- `go test -race ./internal/watch/` and `go test ./internal/engine/`: pass.
  `go vet ./internal/watch/`: clean for linux, windows and darwin.

Not checked: Windows and macOS runs. `fsnotify` reports directory creation
differently there; the tests use the real watcher, but only ran on Linux.
