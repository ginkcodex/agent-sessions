# RF-05 — Terminal pastes cannot end bracketed paste early

- **Status:** ✅ Done
- **Estimate:** 2 h
- **Depends on:** None
- **Plan:** [review-fixes.md](../../plan/review-fixes.md)

## Scope

`terminalClipboard.ts` accepts any OSC 52 write from terminal output. xterm's
`paste()` passes ESC through, so text containing `\e[201~` can end
bracketed paste early and run what follows. `runCommand.ts` already strips
controls for the Run button. Checked.

- Before paste (the menu item and Ctrl/Cmd+V), strip C0 and C1 controls
  except tab and newline, as `runCommand.ts` does.
- Cap OSC 52 payloads (for example 1 MiB) and drop control characters in
  them.
- Strip zero-width and bidi characters from Run-button commands too
  (U+200B–200F, U+202A–202E, U+2066–2069).

## Likely files

`frontend/src/lib/terminalClipboard.ts`, `runCommand.ts`,
`components/terminal/TerminalView.svelte`, `frontend/test/terminal*.test.mjs`.

## Acceptance criteria and tests

- A test: an OSC 52 payload with `\x1b[201~curl x|sh\r` pastes without ESC.
- A test for oversize OSC 52 payloads and for the bidi stripping.

## Evidence

Done on 2026-11-14.

- `terminalClipboard.ts`:
  - `pasteSafe` turns CR and CRLF into LF. It drops C0 controls except tab
    and newline, and DEL and C1.
  - `pasteInto` is the one way the panel pastes into xterm.
  - `installTerminalPaste` catches the browser's `paste` event on the
    terminal's host element in the capture phase, so the event never reaches
    xterm's own listeners on its textarea and element. Those listeners would
    paste the text unfiltered. This covers Shift+Insert, middle click and the
    macOS Edit menu.
  - `parseOsc52` drops payloads over 1,398,104 base64 characters (1 MiB
    decoded). It applies `pasteSafe` to the text it decodes.
- `TerminalView.svelte`: the context menu's Paste, Ctrl/Cmd+V, and the store's
  pastes (Run and dropped paths) all go through `pasteInto`. The native-paste
  listener is installed with the terminal and disposed with it.
- `runCommand.ts`: uses `pasteSafe`, and also strips zero-width and bidi
  format characters: U+200B–200F, U+202A–202E, U+2060–2064, U+2066–2069
  and U+FEFF. Right-to-left letters stay.
- Tests:
  - `test/terminal-clipboard.test.mjs`:
    - an OSC 52 payload of `ls\x1b[201~curl x|sh\r` decodes with no ESC;
    - a payload of exactly 1 MiB is kept, and one group over is dropped;
    - `pasteSafe` drops control characters but keeps tab, line breaks and
      Unicode text;
    - `pasteInto` pastes nothing when no text is left;
    - the native paste event is captured, prevented, stopped and pasted
      safely, and the listener is removed when disposed;
    - a source check confirms `TerminalView` makes no direct `.paste(` call.
  - `test/code-block-run.test.mjs`: RLO, zero-width, isolate, BOM and
    word-joiner cases, and Hebrew text kept.
- `npm test`: 1474 of 1475 pass, 1 skipped (as before). `npm run check`:
  0 errors, 0 warnings.

Not checked: a paste in the running app (WebKitGTK, WebView2, WKWebView).
The capture-phase ordering is standard DOM behaviour, and the unit test uses
a fake host element, not a real webview.
