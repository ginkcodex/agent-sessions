# RF-18 — `turn_end` and open questions: one event order

- **Status:** ⬜ Not started
- **Estimate:** 3 h
- **Depends on:** None
- **Plan:** [review-fixes.md](../../plan/review-fixes.md)

## Scope

`internal/engine/chat.go:979-991` emits `turn_end` only after every question
has resolved. If an adapter returns `session/prompt` and never withdraws an
async question, the chat shows "working" forever. The store comment
(`chats.svelte.ts:528-531`) and the test "a question still open at turn_end
stays until its resolution" (`test/chats-store.test.mjs:681`) assume
`turn_end` can come first. Reviewer finding; see also
[CQ-08](../chat-questions/CQ-08.md).

- Pick one order. The likely choice: when the prompt returns, open questions
  turn late and `turn_end` is emitted.
- Add a Go test for a question that outlives the prompt reply, and make the
  store test match what the engine emits.

## Acceptance criteria and tests

- The Go and frontend tests describe the same event sequence.
