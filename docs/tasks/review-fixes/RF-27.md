# RF-27 — Run the fish panel startup test in a terminal

- **Status:** ✅ Done
- **Estimate:** 2 h
- **Depends on:** None
- **Plan:** [review-fixes.md](../../plan/review-fixes.md)

## Scope

`internal/launch/panel_agent_test.go` `TestRemotePanelAgentStartup` runs
each shell with `CombinedOutput`, so there is no terminal. Without one,
fish (3.7.1 in the `make test-ssh` image) reads EOF from stdin and exits 0
without firing `fish_prompt`, so the agent never runs. All three fish cases
fail on any machine with fish installed. This machine and CI don't have it,
so the cases always skipped. Found during RF-26. With `docker run -t`, fish
does fire `fish_prompt`, so real panel tabs, which have a pty, aren't
affected.

- Run the shells under a pty (`github.com/aymanbagabas/go-pty` is already a
  dependency) and keep the result file and exit status checks.
- Consider installing zsh, fish and tcsh in the CI test job, so these cases
  run somewhere.

## Acceptance criteria and tests

- With fish installed, the fish cases pass; bash, zsh and tcsh still pass.

## Evidence

- Reproduced all three original fish cases failing with exit 0/no agent result
  using fish 3.7.1 in the existing `agent-sessions-sshd:test` image. The same
  baseline passed zsh/tcsh; bash is absent from that image.
- The startup matrix now runs under the existing go-pty dependency, drains
  terminal output, closes the parent's slave handle, and bounds process/output
  lifetime with the existing timeout. It keeps result/exit/status-message checks
  and adds an assertion that agent stdin/stdout/stderr are terminals. Cleanup
  checks target app integration files, not fish's own `fish.<user>` temp directory.
- The PTY reproduction exposed a real fish 3.7.1 prompt issue within this task's
  exit-status acceptance: running the payload then `exit $status` in fish_prompt
  returned 0, and a bare `exec` inherited fish's captured prompt pipe (SIGPIPE
  141). The fish hook now execs the payload with all standard streams attached
  to `/dev/tty`, preserving interactive I/O and exit 7 after activation hooks.
- Considered installing all shells in Linux CI, but a full launch-suite run in
  the shell image exposed the same existing non-PTY problem in
  `TestPanelShellPromptCwd/fish/{scalar,array}`. Tracked and subsequently fixed
  separately in [RF-29](RF-29.md), reusing the startup test's PTY helper.
  CI shell installation remains outside these test fixes.
- Passed host `go test -count=1 ./internal/launch` (all three bash cases ran;
  other shells absent locally), and a statically built launch test binary in
  `agent-sessions-sshd:test`: all three zsh, all three fish and both tcsh cases
  passed. Repeated that container matrix 10 times successfully.
- Passed affected-package runs, both normal and `-race -count=1`, for
  `./internal/configfile ./internal/remote ./internal/launch ./internal/app
  ./internal/manage ./internal/translate`; `git diff --check` passed.
- After RF-29, the full launch suite passes in the shell container and the
  combined startup/cwd matrix passes ten repetitions (see RF-29 evidence).
- Limitations: CI still skips unavailable shells. No native macOS/Windows run
  or interactive desktop/SSH tab smoke test was performed. Bash ran on the
  host, not in the Alpine image; fish coverage used version 3.7.1.
