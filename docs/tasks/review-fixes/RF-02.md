# RF-02 — Keep cached apt packages out of the signing jobs

- **Status:** ⬜ Not started
- **Estimate:** 2 h
- **Depends on:** None
- **Plan:** [review-fixes.md](../../plan/review-fixes.md)

## Scope

`.github/actions/apt-install` restores the newest cache that matches a
predictable prefix and installs its `.deb` files as root with no apt
signature check (`install.sh:41-46`). The `release` and `artifacts` jobs use
it in the same job as the signing keys. A job that runs npm or Go code could
save a trojaned package under that prefix.

- The jobs in the `release` environment install with plain
  `apt-get install`, from signed apt metadata, and never restore the cache.
  Alternatively, check every cached `.deb` against the signed `Packages`
  index before installing it.
- Other jobs keep the cache.

## Likely files

`.github/actions/apt-install/{action.yml,install.sh}`,
`.github/workflows/release.yml`.

## Acceptance criteria and tests

- No job in the `release` environment restores `actions/cache` content that
  another job can write.
- A release run, or a dispatch on `main`, passes.
