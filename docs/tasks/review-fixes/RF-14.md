# RF-14 — Coalesce watcher refreshes; close the engine safely

- **Status:** ✅ Done
- **Estimate:** 3.5 h
- **Depends on:** None
- **Plan:** [review-fixes.md](../../plan/review-fixes.md)

## Scope

`internal/engine/engine.go:304-344, 436-445`: each change starts
`go e.refreshProvider` with no coalescing, and these goroutines are not in
`e.bg`. `Close` closes the DB without `Refresher.Retire()`, while
`LoadState`, `LoadCatalog`, `pendingFTSJobs` and `maintainFTS` read `d.db`
without `writeMu` (`index/db.go:248-258, 358`). Reviewer finding.

- Coalesce in `Refresher`: at most one running and one pending scan per
  provider.
- Track refreshes in `e.bg`; `Close` retires the refresher, waits, then
  closes the DB.
- Guard `d.db` reads, or make `Close` wait for readers.

## Acceptance criteria and tests

- `go test -race`: a test that fires changes while closing.
- A test: 50 changes during one slow scan run at most two scans.

## Evidence

Verified and implemented 2026-11-15:

- Confirmed watcher/chat refreshes spawned untracked goroutines and serialized every request into a separate scan. `Refresher.Refresh` now shares a flight per provider and folds concurrent requests into one pending scan; waiting callers can cancel.
- Engine refresh registration is synchronized with shutdown and tracked in `e.bg`. Shutdown cancels work, retires the refresher, waits for background jobs, then closes the indexer/database. Refresher close also retires it.
- The SQL handle is now immutable after construction. `database/sql` safely synchronizes its own `Close` and concurrent queries, removing the pointer mutation that raced LoadCatalog, LoadState and FTS readers without serializing all reads behind writes.
- Added regressions for 50 requests during a blocked scan (exactly two scans), no scans after retirement, concurrent database reads/close, and changes arriving during engine close.
- `go test -race ./internal/index ./internal/engine`: passed.
- Not checked: native Windows runtime; `golangci-lint` is not installed.
