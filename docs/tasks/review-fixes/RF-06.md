# RF-06 — Dropped paths on Windows cannot expand in PowerShell

- **Status:** ✅ Done
- **Estimate:** 1.5 h
- **Depends on:** None
- **Plan:** [review-fixes.md](../../plan/review-fixes.md)

## Scope

`typedPath` (`internal/app/panel.go:324`) wraps unsafe Windows names in
`"…"`, and PowerShell expands `$(…)` and backtick escapes inside double
quotes. A file named `$(calc).txt` runs `calc` when the user presses Enter.
The POSIX branch doesn't strip control characters either. Checked.

- PowerShell panels: single quotes, with `'` doubled (`PowerShellQuote` in
  `internal/launch` already does this).
- cmd panels: handle `%` and `^`, or refuse.
- POSIX: refuse or strip control characters.

## Acceptance criteria and tests

- `panel_test.go` cases for `$(calc).txt`, `` a`b ``, `%PATH%.txt` and a
  name with a newline, on each shell.

## Evidence

Done on 2026-11-14.

Decisions:

- A local Windows tab always runs Windows PowerShell, either as a shell
  (`PanelShellArgv`) or around an agent (`PanelArgv`). There is no cmd
  panel, so the cmd case reduces to a user who starts `cmd` in a shell tab
  by hand.
- A dropped path usually goes to an agent running in the tab, not to the
  shell. Double quotes stay for names they keep literal, because that is
  what Windows Terminal types and what agents recognise.
- A name with `$`, a backtick, or a curly double quote (U+201C–201E, which
  PowerShell treats as `"`) now gets `launch.PowerShellQuote`'s verbatim
  single quotes, with every single-quote form doubled. A curly double quote
  in a name could otherwise end the string and run what follows: for example
  `a”; calc; “b.png`.
- cmd: `%VAR%` inside double quotes still expands. The expansion changes the
  path but cannot end the quotes, because `"` is not allowed in Windows
  names. Nothing runs, so the name is not refused.
- Every platform: a path with a control character (`unicode.IsControl`: C0,
  DEL and C1) is refused with an error naming it. No quoting keeps a newline
  or CR from ending the line, and the RF-05 paste filter would drop it, which
  types the name of a different file. The check runs on the dropped paths,
  and on an SSH host's copies, before anything is typed.

Changes and tests:

- `internal/app/panel.go`: `typeablePaths` and `powerShellExpands`;
  `typedPath` uses `launch.PowerShellQuote` for names PowerShell would
  expand.
- `TestTypedPath`, new cases:
  - single-quoted: `$(calc).txt`, `$env:USERNAME.png`, `` a`b.png ``,
    `a”; calc; “b.png`, `it’s $x.png` (its `’` doubled) and `it's $x.png`;
  - still in double quotes: `%PATH%.txt` and `it's.png`;
  - POSIX: `` $(id)`id` `` and `%PATH%.txt`.
- `TestTerminalDropFiles`: names with LF, CR, ESC and U+0085 are refused,
  even with a valid path dropped alongside. An SSH copy whose path has a
  newline is refused too.
- `go test ./internal/app/ ./internal/launch/`: pass. `go vet
  ./internal/app/`: clean for linux and for `GOOS=windows`.

Not checked:

- A drop in the running app on Windows.
- Whether each agent (Claude Code, Codex, OpenCode) recognises a
  single-quoted Windows path as an attachment. Only names with `$`, a
  backtick or a curly double quote are affected.
- SSH and WSL hosts whose shell is fish, where a backslash before `'` is an
  escape even inside single quotes. That belongs with RF-21, which covers
  non-POSIX login shells.
