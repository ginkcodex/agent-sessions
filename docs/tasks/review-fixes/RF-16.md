# RF-16 — A chat ends when its ACP connection fails

- **Status:** ✅ Done
- **Estimate:** 2 h
- **Depends on:** None
- **Plan:** [review-fixes.md](../../plan/review-fixes.md)

## Scope

`internal/acp/conn.go:264-274`: when a line is over 64 MiB or a read fails,
`readLoop` calls `finish` and returns. `finish` fails the pending calls but
doesn't stop the agent. `Client.Done()` follows the process exit only
(`client.go:192`), so the chat stays live and never emits `chat:exit`.
Checked.

- In `Client`, watch `conn.Done()`. If the client didn't close the
  connection itself, kill the process tree and report the connection's
  error as the exit reason.

## Acceptance criteria and tests

- `acptest`: an agent that writes a frame over the limit ends the chat with
  `chat:exit` carrying that error, and its process is gone.

## Evidence

Done on 2026-11-14 at `932b96b`.

- `internal/acp/client.go`: a new `watchConn` waits for the connection to
  end:
  - Ended by `Close` (`ErrClosed`): nothing to do, since `Close` stops the
    agent.
  - The agent closed its output (`ErrAgentGone`): it usually exits with
    it. It gets the grace period to exit first.
  - Any other end (`ErrFrameTooLarge`, a read error), or an agent still
    running after that grace period: the client keeps the error and kills
    the process tree. `Done` then follows.
- `ExitErr` returns the kept connection error in place of the kill's
  `signal: killed`. The engine's `chat:exit` therefore reports
  `crashed` with the frame-limit error. Calls that fail meanwhile get an
  `ExitError` whose `Exit` is the same error.
- `acptest`: a new prompt word `flood` writes one line over
  `acp.DefaultMaxFrameBytes`. The fake agent then keeps running and ignores
  a closed stdin.
- New tests:
  - `acp`, `TestOversizedMessageStopsAgent`: the prompt fails with an
    `ExitError` for the frame limit, `Done` closes (the process has been
    reaped), and `ExitErr` is `ErrFrameTooLarge`.
  - `engine`, `TestChatOversizedMessageEndsChat`: the turn ends with an
    error, `chat:exit` has reason `crashed` and the frame-limit error, the
    event sequence is whole, and the session is released.
- Run against the old `client.go`, both tests failed. The acp test got an
  `ExitError` with no exit status, since the agent still ran. The engine
  test saw no `chat:exit` in 24 s.
- `go test -race ./internal/acp/... ./internal/engine/` passed.
- `go vet ./internal/acp/...` is clean for Linux, Windows and darwin, and
  `go vet ./internal/engine/` and `gofmt -l` are clean.

Not checked: a read error other than the frame limit. It takes the same
path. Windows: the kill goes through the same `proctree` call as `Close`,
but the test did not run there.
