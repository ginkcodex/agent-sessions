# RF-16 — A chat ends when its ACP connection fails

- **Status:** ⬜ Not started
- **Estimate:** 2 h
- **Depends on:** None
- **Plan:** [review-fixes.md](../../plan/review-fixes.md)

## Scope

`internal/acp/conn.go:264-274`: when a line is over 64 MiB or a read fails,
`readLoop` calls `finish` and returns. `finish` fails the pending calls but
doesn't stop the agent. `Client.Done()` follows the process exit only
(`client.go:192`), so the chat stays live and never emits `chat:exit`.
Checked.

- In `Client`, watch `conn.Done()`. If the client didn't close the
  connection itself, kill the process tree and report the connection's
  error as the exit reason.

## Acceptance criteria and tests

- `acptest`: an agent that writes a frame over the limit ends the chat with
  `chat:exit` carrying that error, and its process is gone.
