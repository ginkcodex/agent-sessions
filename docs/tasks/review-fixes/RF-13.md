# RF-13 — The watcher recovers from transient errors

- **Status:** ⬜ Not started
- **Estimate:** 3 h
- **Depends on:** RF-12
- **Plan:** [review-fixes.md](../../plan/review-fixes.md)

## Scope

`watch.go:289-296, 472-490`: any fsnotify error calls `failAll`, which moves
every provider to 10 s polling for the rest of the process. `isWatchLimit`
(`:708`) is dead code. Reviewer finding.

- On `ErrEventOverflow`, rescan and keep the watches.
- Keep the fallback per provider, and try to re-install watches with backoff.
- Use or remove `isWatchLimit`.

## Acceptance criteria and tests

- Tests with a fake fs watcher: an overflow keeps watching, and an error
  falls back and later recovers.
