# RF-21 — Remote connect works with a fish, csh or tcsh login shell

- **Status:** ✅ Done
- **Estimate:** 3 h
- **Depends on:** None
- **Plan:** [review-fixes.md](../../plan/review-fixes.md)

## Scope

`internal/remote/probe.go:276-285`, `session.go:184` and `deploy.go:186` run
POSIX scripts through `"$SHELL" -lc`. fish, csh and tcsh can't parse them.
`docs/plan/M7.md:76` says a direct-exec fallback exists; it doesn't.
`internal/launch` already uses an octal bootstrap through `/bin/sh` for
panels. Reviewer finding.

- Share that bootstrap. The login environment still comes from the user's
  shell where the code needs it.
- Correct `M7.md`.

## Acceptance criteria and tests

- `make test-ssh`, with a container user whose login shell is fish: probe,
  deploy and serve pass.

## Evidence

Done on 2026-11-14.

- Checked first in the `make test-ssh` container (Alpine): with the old
  `"$SHELL" -lc <script>` line, fish fails with "Missing end to balance this
  while loop" and tcsh with "Unknown option: `-lc'". zsh, bash and dash
  parse it, which is why a zsh Mac works. tcsh takes `-l` only as its sole
  flag, so `-l -c` and `-ilc` fail the same way.
- `internal/launch`: a new `PosixLoginArgv(script)` runs script with
  `/bin/sh` in the login shell's environment. `/bin/sh` decodes a small
  wrapper, which starts `$SHELL` (else `/bin/sh`) with `-lc`, or `-c` for
  csh and tcsh. That shell sees only a line that hands the script, still in
  `OctalEscape` form, to `/bin/sh` again. `WSLLoginExecArgs` is the same for
  `wsl.exe --exec`.
- `internal/remote`: probe, deploy and serve build their command with
  `LoginCommand(script)`. Over SSH it becomes the quoted `PosixLoginArgv`;
  for WSL, `WSLLoginExecArgs`. `wslLoginShell` is gone.
- `docs/plan/M7.md`: the false "direct-exec fallback" line now describes
  this path.
- Tests:
  - `TestBuildSSHArgs_LoginCommandUnderEveryShell` runs the SSH remote line
    under each login shell installed here (sh, dash, bash; zsh, fish, tcsh
    and csh when present). Each shell's startup file sets a variable the
    script must see, and quotes, `$(...)`, `%`, a backslash and non-ASCII
    text must come through unchanged.
  - `TestWSLArgsRunCommandExactly` checks the WSL argv with a fake login
    shell, and with `SHELL` unset.
  - `sshtest`: the container now has users with sh, zsh, fish and tcsh login
    shells, each with a startup file setting `AS_TEST_LOGIN`.
    `TestSSHD_DeployReuseAndBrowse` runs probe, deploy, serve and browse for
    each, and checks that a deploy-path script runs under `/bin/sh` and sees
    the login variable.
  - `TestSSHD_NoServerLeftBehind` starts its server by hand with `exec`, as
    the real serve script does. Without it the decoding `/bin/sh` stays as
    the parent, and its command line matched the process count.
  - The fake ssh in `fakes_test.go` decodes the script out of a login
    command.
- `make test-ssh` passed (remote and app). `go test -race ./internal/remote/...
  ./internal/launch/ ./internal/app/` passed. `go vet` on those packages is
  clean for Linux, Windows and darwin, and the changed files are
  `gofmt`-clean.

Not checked: csh itself (the container has tcsh only), a macOS host with a
fish or tcsh login shell, and a WSL distro whose login shell is fish. The
WSL path shares `PosixLoginArgv` and is covered by the unit test only.

Found along the way: agent panel tabs on a csh or tcsh host fail the same
way; see [RF-26](RF-26.md).
