# RF-28 — Remote connect reads `.login` for csh and tcsh

- **Status:** ✅ Done
- **Estimate:** 1 h
- **Depends on:** [RF-21](RF-21.md)
- **Plan:** [review-fixes.md](../../plan/review-fixes.md)

## Scope

RF-21 runs probe, deploy and serve under csh and tcsh with `-c`, since
they take `-l` only as their sole flag. `-c` reads the rc file but not
`/etc/csh.login` or `~/.login`. A tcsh user who sets PATH in `~/.login`
then has agents that remote connect can't find. RF-26's agent panel tabs
read the login files, so the two paths disagreed. Found while doing RF-26.

- Read the login files in RF-21's csh and tcsh line, with the same
  snippet as the panel.

## Acceptance criteria and tests

- With the login variable set only in `.login`, the tcsh and csh cases of
  `TestBuildSSHArgs_LoginCommandUnderEveryShell` pass.
- `make test-ssh`: the tcsh user's login variable lives in `.login` and
  reaches probe, deploy and serve.

## Evidence

Done on 2026-11-14.

- `internal/launch/panel.go`: a new `cshLoginFiles` csh snippet:
  - remembers `$cwd`;
  - sources `/etc/csh.login` and `~/.login` when readable;
  - goes back to `$cwd`, since Gentoo's and Alpine's `csh.login` end with
    `cd`.
  The csh/tcsh case of `loginWrapper` runs it before execing the
  `/bin/sh` line. The panel's csh case (RF-26) now uses the same constant.
- `TestBuildSSHArgs_LoginCommandUnderEveryShell`:
  - the tcsh and csh startup files are `.login`;
  - output is matched as a suffix, since a system login file may print
    first: Alpine's `csh.login` prints the MOTD outside ssh;
  - the zsh case now sets `ZDOTDIR` to the test home. It was empty, so zsh
    looked for `/.zprofile`. That bug came in with RF-21, and the case had
    only skipped before, as zsh isn't installed here.
- `sshtest`: the tcsh user's banner and `AS_TEST_LOGIN` moved from
  `.tcshrc` to `.login`.
- In the `make test-ssh` image (`CGO_ENABLED=0 go test -c`), the test
  passes for sh, zsh, fish, tcsh and csh. With the old `panel.go` it fails
  for tcsh and csh (`none` in place of the login variable).
  `TestRemotePanelAgentStartup` still passes there for zsh and tcsh.
- Here: `go test -race ./internal/launch/ ./internal/remote/ ./internal/rpc/`
  passed. `go vet` on launch and remote is clean for Linux, Windows and
  darwin, and the changed files are `gofmt`-clean.
- `make test-ssh` passed (remote and app). The tcsh user's banner and
  `AS_TEST_LOGIN` are now only in `.login`, and
  `TestSSHD_DeployReuseAndBrowse` saw `[tuser|sh]` after the probe.

Risk: a login file with an error ends the line, so connect fails, where a
login shell would print the error and go on to its prompt. Not checked:
real csh (the image links csh to tcsh) and a macOS host.
