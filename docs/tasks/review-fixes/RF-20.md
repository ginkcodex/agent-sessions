# RF-20 — A language server restarts after a crash

- **Status:** ✅ Done
- **Estimate:** 3 h
- **Depends on:** None
- **Plan:** [review-fixes.md](../../plan/review-fixes.md)

## Scope

`internal/codediagnostics/lsp_session.go:461`: `attach` on a failed session
returns the old error. `SessionManager.Retry` (`:641`) has no production
caller, and the frontend `canRetry` (`codeDiagnostics.svelte.ts:208`) is
limited to `savedProject`. After an OOM kill, or a reply over 8 MiB, live
diagnostics stay dead until the app restarts. The comment at `:639`
contradicts the code. Reviewer finding.

- Restart automatically with backoff and a cap, then offer Retry in the UI.
- Count an attempt only after `Preflight` passes.

## Acceptance criteria and tests

- A test with a fake server that crashes once: the session recovers without
  an app restart.

## Evidence

- Verified the defect: failed Attach returns the previous failure and Retry
  had test callers only. The production Refresh pump now schedules retries
  using the existing timer seam, with 1 s exponential backoff and the existing
  MaxRestarts cap (default three attempts).
- Recovery only starts for approved attachments with displayed documents.
  It serializes with document changes, detach and revocation, rechecks trust
  before launch, and replays acknowledged displayed text into the new generation
  (never disk contents). Old generations cannot publish. Ambiguous/broken
  document synchronization still requires the existing fresh-lifecycle recovery.
- Attempts are counted only after successful Preflight and ownership of a new
  generation. A failed preflight is not repeatedly polled by the recovery pump.
- Failed live providers expose scoped Retry through the existing single-provider
  Run API; explicit Retry resets a bounded recovery series without new RPCs.
  Updated the CodeChecks control and obsolete no-restart copy/test.
- New fake-server tests recover from an oversized (>8 MiB) frame and a process
  crash, verify draft replay/publication, delayed backoff, cap/manual recovery,
  no attempt consumed by refused preflight, and close/detach/revoke/trust gates.
- Passed `go test ./internal/codediagnostics ./internal/engine ./internal/files`;
  passed `go test -race ./internal/files ./internal/codediagnostics`.
- Passed final repeated targeted race run:
  `go test -race ./internal/codediagnostics -run 'TestLiveAutomatic|TestLiveRetry|TestSessionRetryPreflight|TestSessionCrash' -count=5`.
- Passed frontend full `npm --prefix frontend test` invocation (1498 passed,
  one skipped, zero failed) and `npm --prefix frontend run check`. The test
  invocation included a trailing name-pattern argument but Node ran all suites.
- Windows amd64 test binary cross-compilation passed for `internal/files`,
  `internal/codediagnostics` and `internal/engine` (output under `/tmp`).
- Not checked: a real language-server OOM kill or desktop/Windows runtime;
  process exits and transport-limit failures were exercised with fake servers.
