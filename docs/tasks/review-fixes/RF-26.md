# RF-26 — Agent panel tabs work with a csh or tcsh login shell

- **Status:** ✅ Done
- **Estimate:** 2 h
- **Depends on:** None
- **Plan:** [review-fixes.md](../../plan/review-fixes.md)

## Scope

`internal/launch/panel_shell.go` `panelPosixStartupScript`: shells other
than bash, zsh and fish take the fallback `exec "$__as_shell" -ilc …` when a
tab runs an agent. tcsh (and csh) take `-l` only as their sole flag, so the
tab fails with "Unknown option: `-ilc'". Found while doing RF-21 and checked
in the `make test-ssh` container. A plain shell tab uses `-l` alone and
works.

- Give csh and tcsh their own case: an interactive shell running the
  bootstrap line (as RF-21's `PosixLoginArgv` does, `-c` after the rc file),
  or a login shell whose startup runs it.
- Keep `-ilc` for the other POSIX shells.

## Acceptance criteria and tests

- A unit test runs the panel agent script with `SHELL` set to tcsh, when
  installed, and the agent runs in the project directory.
- Planned, then replaced: `make test-ssh` with an agent panel tab for the
  tcsh user. The sshd tests have no terminal to run a tab in. The unit test
  was run instead in the same container image, under the same tcsh, and
  RF-21's sshd tests already cover tcsh as the ssh server's shell.

## Evidence

Done on 2026-11-14.

- Confirmed with the old code: in the `make test-ssh` image (Alpine,
  tcsh 6.24.12) both tcsh cases of `TestRemotePanelAgentStartup` fail
  with "Unknown option: `-lc'".
- `internal/launch/panel_shell.go`: when a tab runs an agent, csh and tcsh
  get their own case, `exec "$__as_shell" -ic <script>`. Interactive, so an
  rc file guarded by `$?prompt` still runs; `-c`, since tcsh takes `-l`
  only alone. The csh script:
  - reads `/etc/csh.login` and `~/.login`, as a login shell would after the
    rc files;
  - returns to the project directory, since Gentoo's and Alpine's
    `csh.login` end with `cd`;
  - runs a `precmd` alias if one is set (direnv's tcsh hook, say), as the
    first prompt would. A one-line `if` would not expand the alias, so it
    uses `if … then … endif`;
  - then execs the same `/bin/sh` bootstrap line as the other shells.
  A plain shell tab is unchanged: `tcsh -l` works.
- `TestRemotePanelAgentStartup` has tcsh cases: the activation is set in
  `.tcshrc` or in `.login`, with a `precmd` alias recording `$cwd`. Each
  checks that activation ran once, `precmd` ran in the project, and the
  agent got its directory, arguments and exit status 7. For tcsh the outer
  command is `/bin/sh`, because an ssh server's tcsh also reads `.tcshrc`
  and the count would be 2.
- Built with `CGO_ENABLED=0 go test -c` and run in the container: zsh and
  tcsh pass. fish fails there with the old code too; see [RF-27](RF-27.md).
  bash is not in the image.
- Here: `go test -race ./internal/launch/ ./internal/rpc/ ./internal/remote/`
  passed. bash passes and the other shells skip, since they aren't
  installed. `go vet ./internal/launch/` is clean for Linux, Windows and
  darwin, and `gofmt -l` is clean.

Not checked: csh itself (the image links csh to tcsh), a macOS host (its
`/bin/csh` is tcsh too, with a different `csh.login`), and a real panel tab
over ssh. CI has no tcsh, so there the tcsh cases skip.
