# RF-08 — Linux channels check the minisign signature

- **Status:** ⬜ Not started
- **Estimate:** 3 h
- **Depends on:** None
- **Plan:** [review-fixes.md](../../plan/review-fixes.md)

## Scope

The website Worker (`web/worker/release.ts:262`, cron `cron.ts:44-59`) and
the AUR job (`Makefile:207`) trust the unsigned `SHA256SUMS`, then sign apt
and dnf metadata with the project's own key. Anyone who can replace release
assets reaches those channels. Reviewer finding.

- The Worker verifies `SHA256SUMS.minisig` with the public keys the app has
  built in before ingesting.
- `make aur-package` verifies it too (`minisign -V`, or `release-sign`
  verify mode).

## Acceptance criteria and tests

- Worker test: a release whose `SHA256SUMS` doesn't match its signature is
  not ingested.
- AUR: a bad signature fails `make aur-package`.
