# RF-17 — Chat start can be cancelled and times out

- **Status:** ✅ Done
- **Estimate:** 3 h
- **Depends on:** RF-16
- **Plan:** [review-fixes.md](../../plan/review-fixes.md)

## Scope

`internal/app/chat.go:194` passes `a.appCtx()`, which has no deadline, into
`initialize` and `session/new|load|resume`. Until the start returns the
frontend has no `chatId`, so it can't close the chat, and `ChatOpener.run`
(`chatOpen.svelte.ts:232`) refuses every other open while one is starting.
Checked: the context has no deadline.

- A fixed 60-second start timeout and a `ChatStartCancel`
  keyed by a client-chosen start token.
- LiveTail shows Cancel while a chat starts.

## Acceptance criteria and tests

- `acptest`: an agent that never answers `initialize` fails the start at the
  timeout and is killed. Cancel stops the start at once.
- Frontend test: a failed or cancelled start frees the opener.

## Evidence

- Confirmed the finding: the app passed its lifetime context to initialize
  and session setup; the frontend's opener stays busy until that call returns.
- Starts now use a 60-second deadline and a per-window client token, with
  `ChatStartCancel` and a chat-specific registry using the existing mutex/
  context pattern without changing search behavior. Early cancellations are
  remembered for one minute, capped at 128 tokens per window; completed
  starts unregister normally. No settings UI or dependency was added. Existing
  RPC context cancellation already forwards cancellation to the host.
- The store creates a UUID before starting, and LiveTail offers Cancel.
  A successful reply racing cancellation is closed rather than orphaned.
  A failed cancellation API call resets that intent, preserving a later
  successful start. Tests cover both races, cancel-before-registration,
  unknown-token bounds/expiry, and normal registry cleanup.
- `TestChatStartDeadlineAndCancel` passed all eight combinations of timeout
  and explicit cancellation during initialize/new/load/resume. It also
  checks unrelated/completed tokens, registry cleanup, and on Linux that
  the fake agent PID no longer exists. The scripted agent ignores request
  cancellation and never replies, exercising process cleanup.
- `go test ./internal/app -run 'TestChatStartDeadlineAndCancel|Test.*Binding' -count=1`: passed.
- `go test -race ./internal/app ./internal/acp ./internal/engine ./internal/rpc -run 'Chat|Client|Conn' -count=1`: all four packages passed.
- `node --loader ./test/resolver.mjs --test test/chat-ui.test.mjs test/chats-store.test.mjs`: 82 passed, 0 failed. Includes start-token cancellation, raced success cleanup, opener release after cancel/deadline, and Cancel rendering.
- After the cancellation-race follow-ups: `go test -race ./internal/app ./internal/engine ./internal/acp ./internal/rpc -run 'Chat' -count=1`: app, engine and RPC passed (ACP has no matching tests). Focused frontend chat/question suites: 102 passed, 0 failed.
- `npm run check`: 642 files, 0 errors, 0 warnings.
- Not checked: interactive desktop/Windows execution or an actual SSH host.
  Timeout is a fixed production default; the internal override is only for
