# AU-14 — Check for updates by hand in Settings

- **Status:** ✅ Done
- **Estimate:** 3 h
- **Depends on:** AU-05
- **Plan:** [auto-update.md](../../plan/auto-update.md)

## Scope

- `startUpdateChecks` returns `{ stop, checkNow }`. `checkNow` checks at
  once, shares a check already running, moves the shared due time a day
  ahead on success, leaves it alone on failure, reschedules this window's
  timer, and reports through the same `checked` and `notify` callbacks.
- `UpdatesStore`: `canCheck`, `checking`, `checkResult` and `checkNow()`;
  App wires the scheduler's `checkNow` in. A status that is not idle clears
  the result, so it never contradicts the update state.
- Settings › General › Updates: **Check for updates** (Checking… while it
  runs, disabled during a download), the result in the status line, and the
  error below it.

## Acceptance criteria and tests

- A manual check runs at once, and the next scheduled check is a day later
  in every window.
- A manual check during a scheduled one calls the backend once.
- A failed manual check keeps the due time and reports the failure.
- A found release is announced as the daily check does it.
- Settings shows the button only where checks run. It shows Checking…, then
  up to date with the version, the update state, a development build, or
  the error.
