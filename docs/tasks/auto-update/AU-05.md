# AU-05 — Frontend: ready toast, Later and fallback

- **Status:** ✅ Done
- **Estimate:** 3 h
- **Depends on:** AU-04
- **Plan:** [auto-update.md](../../plan/auto-update.md)

## Scope

- Ready: persistent toast "Agent Sessions X is ready" with **Restart now**
  and **Later**. Later hides it until the next launch.
- Manual and unsupported: today's toast with the release page.
- Restart now goes through the normal quit path, so close confirmations
  for running terminals still ask.
- Settings shows the toggle and the current state ("Up to date", "Ready:
  restart to install 1.6.0", "Last check failed").

## Likely files

`frontend/src/lib/update.ts`, `frontend/src/App.svelte`, the settings
component, `frontend/test/update.test.mjs`.

## Acceptance criteria and tests

- Tests for each state's toast, Later, and the toggle.
- `svelte-check` passes.

## Evidence

`lib/update.ts`: `readyToast` (persistent, **Restart now** / **Later**),
`pageToast`, `updateSummary` and `createUpdateAnnouncer`, which picks the toast
for a state: ready is shown once per launch and version (Later, or closing it,
keeps it hidden until the next launch, because the announcer remembers the
version and nothing stores it); downloading shows nothing; manual, unsupported
and a check that found a release the backend did not keep show today's release
page toast. `startUpdateChecks` reports each check's failure through
`checked`. `stores/updates.svelte.ts` reads `UpdateState`/`AutoUpdate`,
follows the `update:state` event (`subscribeUpdateState` in `api.ts`) and
wraps `setAutoUpdate`/`restartToUpdate`. `App.svelte` wires the announcer;
Restart now calls `RestartToUpdate`, which goes through the normal quit path
so close confirmations still ask. Settings › General has an **Updates**
section: the state line ("Up to date", "Ready: restart to install X",
"Downloading X…", "X is available", "Last check failed"), a Restart now button
when ready, and **Download updates automatically**, shown only where the
backend says the install can update itself (`Status.supported`, new in the Go
`update.Status`). The browser demo has no `updateState`, so the section and
the checks stay hidden there.

Ran: `npm test` (1436 tests pass, including new ones for each state's toast,
Later, once-per-version, the check-failure flag and the Settings section in
each state), `npm run check` (0 errors), `go test -race ./internal/update
./internal/app`.

Not checked: the toast and Settings in a running desktop app (no installer
exists yet, so `supported` is false in every build and only the release page
toast can appear); keyboard and screen-reader behaviour of the new section
beyond using the same markup as neighbouring settings.
