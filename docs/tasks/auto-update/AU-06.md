# AU-06 — macOS: check, mount and stage the new app

- **Status:** ✅ Done
- **Estimate:** 3.5 h
- **Depends on:** AU-03
- **Plan:** [auto-update.md](../../plan/auto-update.md)

## Scope

- Possible only when the bundle's parent is writable, the bundle path is
  not under App Translocation or `/Volumes/`, and the build is a release.
  Otherwise `unsupported`, with the reason logged.
- Mount the `.dmg` with `hdiutil attach -readonly -nobrowse` at a
  temporary mount point; always detach.
- Check the `.app`: `codesign --verify --strict`, `spctl --assess --type
  execute`, Team ID equal to the running bundle's, bundle ID
  `com.wails.agent-sessions`, version equal to the update's.
- Copy it next to the installed bundle as
  `.Agent Sessions.app.update-<version>`, keeping signatures (`ditto`).

## Likely files

`internal/update/darwin.go`, tests with build tag `darwin`.

## Acceptance criteria and tests

- Tests for each eligibility case with temporary folders.
- On a Mac, a real release `.dmg` stages; one re-signed ad hoc is refused
  for its Team ID.

## Evidence

Built as `update.Mac` (`internal/update/macos.go`) with a `Runner` for the
system tools, so the checks run for real on a Mac and against a fake
elsewhere. `MacBundle(exe)` finds the `.app` around the executable.
`Eligible` refuses a bundle that is not a `.app`, runs from App
Translocation or `/Volumes/`, sits in a folder the user cannot write (tested
by creating a file there), is owned by another user, or is signed ad hoc or as
something other than `com.wails.agent-sessions` (the new version must match a
Team ID, so a running app without one cannot update). `Stage(ctx, Ready)`
mounts the `.dmg` (`hdiutil attach -readonly -nobrowse -noautoopen -noverify`
at a temporary mount point, always detached: retried, then forced, and not
tied to the context), takes the single real `.app` at its root (not the
`Applications` link), runs `codesign --verify --deep --strict`, compares the
signing identifier, Team ID, `CFBundleIdentifier` and
`CFBundleShortVersionString` with the running app and the update, copies it
with `ditto` to `.Agent Sessions.app.update-<version>.part`, repeats the checks
on the copy plus `spctl --assess --type execute`, and renames it into place. A
staged copy that still verifies is reused; one that does not is replaced.
`Cleanup(keep)` removes other staged copies and partials. The installed bundle
is never touched.

`Manager` gained a `Prepare(ctx, Ready)` hook that runs after the download and
before the version is called ready (also for a download an earlier run left,
in `Resume`); a version it refuses shows the release page (`manual`) and is not
tried again that run. Cancelling at quit stops it.

Ran: `go test -race ./internal/update ./internal/app`; `go vet` for darwin,
linux and windows. On this Mac (arm64, assessments enabled) the tests use the
real `hdiutil`, `codesign`, `plutil` and `ditto` on small ad hoc signed apps:
stage and reuse, a tampered staged copy replaced, no image left mounted, an
ad hoc signed app refused for its missing Team ID, another team, another app
ID and another version refused. A real release image was staged:
`AGENT_SESSIONS_TEST_DMG=<v1.5.5 dmg> AGENT_SESSIONS_TEST_DMG_VERSION=1.5.5
go test ./internal/update -run RealRelease` passed (Developer ID signature,
Team ID and Gatekeeper's verdict accepted, staged copy verifies).

Not checked: nothing calls `Mac` yet: `canSelfUpdate` and `Prepare` are wired
to it in AU-07 together with the apply step, so every build still reports
`unsupported`. A release image of a different version than the running app
(the real update path) is only exercised by AU-08. The Team ID tests that need
two different Developer ID teams spoof the `codesign -d` output.
