# AU-10 — Windows: apply on restart or quit

- **Status:** ✅ Done
- **Estimate:** 4 h
- **Depends on:** AU-04, AU-09
- **Plan:** [auto-update.md](../../plan/auto-update.md)

## Scope

- `--apply-update <ready folder>` as on macOS, from a copy in the updates folder (`<updates>\helper\`, not `%TEMP%`: a fixed folder of ours can be cleared by its exact path at the next update, since a running helper cannot delete itself).
- Wait until no process runs from the install folder (app, CLI, terminals
  started from it), up to a time limit.
- Remove the installed product, then install the new MSI, both `/quiet
  /norestart` with verbose logs in the updates folder (setup's arguments).
- If the install fails after the removal, install the rollback MSI. Start
  whichever version is installed.

## Likely files

`internal/update/apply_msi.go` (portable logic), `apply_windows.go` (helper, process waits, msiexec), `internal/app/update_windows.go`, tests.

## Acceptance criteria and tests

- Tests with a fake msiexec runner: success, install failure (rollback),
  rollback failure (logged, MSIs kept and named), processes never exiting.

## Evidence

- `MSIApply` (`apply_msi.go`) is portable and tested with a fake msiexec and
  a fake product registry (`apply_msi_test.go`): success; restart relaunches,
  quit does not; 3010 after install accepted; install failure (1603, 1618,
  1602) → rollback MSI installed and the old version launched; new version
  that does not register → rollback; rollback failure → error names both kept
  MSIs, nothing launched; removal failures (1618, 1603, 3010, 1641) → nothing
  installed, old version kept and opened; 1605 on removal accepted; app that
  never quits → `ErrStillRunning`, no msiexec call; either MSI altered on disk
  → refused before the removal; a second registration → refused; the lock is
  held during msiexec and released.
- `go test -race ./internal/update ./internal/winmsi ./packaging/windows/setup
  ./internal/app` pass. `GOOS=windows go vet` (also `-tags desktop,production`)
  and `GOOS=windows go test -c` for `internal/update` pass.
- A failed update calls `GiveUp`, so the next launch shows the release page
  instead of retrying (`recordApply`, shared with macOS).
- **Not checked:** nothing here ran on Windows. `apply_windows.go` (helper
  start with job breakaway, pid wait, folder-idle scan, the real msiexec) and
  `update_windows.go` are compiled and vetted only. AU-11 covers them.
