# AU-02 — Find an update and check its signature

- **Status:** ✅ Done
- **Estimate:** 3 h
- **Depends on:** AU-01
- **Plan:** [auto-update.md](../../plan/auto-update.md)

## Scope

In `internal/update`, replacing today's GitHub API call on every platform:

- Download `releases/latest/download/SHA256SUMS` and
  `SHA256SUMS.minisig`; verify with the built-in keys (`aead.dev/minisign`
  or an equivalent small library).
- Read the version from the installer's file name for this platform; check
  it is newer than the running one (`Newer`). Build the installer URL
  (`releases/download/v<version>/<file>`) and the release page URL.
- On Linux the result only feeds the toast; nothing is downloaded.
- `AGENT_SESSIONS_UPDATE_URL` replaces the `releases` base URL for QA.
  Extra public keys can be added only at build time (ldflags), for QA
  builds.

## Likely files

`internal/update/update.go`, `internal/update/feed.go`,
`internal/update/verify.go`, tests.

## Acceptance criteria and tests

With `httptest` servers:

- A signed `SHA256SUMS` for a newer release gives its version, installer
  and page URLs for macOS, Windows and Linux.
- Refused: bad signature, unknown key, no installer for this platform in
  `SHA256SUMS`, version not newer, `dev` build.
- No request goes to `api.github.com`.

## Evidence

Implemented in `internal/update/feed.go` (`Checker.Feed`), `keys.go` and
`update.go` (`Check` tries the feed first). `Info.Release` carries the
verified installer (file, URL, SHA256) for AU-03 and is not sent to the UI.

- `go test -race -count=1 ./internal/update ./internal/app`: pass.
  `go vet` clean for darwin, linux and windows.
- `TestFeedReturnsTheVerifiedInstallerForEachPlatform`: darwin amd64/arm64
  (`.dmg`), windows amd64 (`.msi`), linux amd64/arm64 (`.deb`) each get the
  right file, URL, page and the hash from the signed `SHA256SUMS`.
- `TestFeedRefusesWhatNothingVouchesFor`, each with no result: signed by an
  unknown key, sums changed after signing, garbage signature, a signature of
  an older release's sums (all `ErrBadSignature`); no signature published, no
  trusted key, no `SHA256SUMS`, two versions in one file (`ErrUnsigned`).
- `TestFeedHasNoInstallerForOtherPlatforms`: windows/arm64 and others make
  no request at all.
- `TestCheckUsesTheSignedFeedAndNeverTheAPI`: a signed feed makes 0 API
  requests; an up-to-date or newer build gets no `Release`.
- `TestCheckFallsBackToTheAPIOnlyWhenThereIsNoSignedFeed`: an unsigned
  release still gives today's notice; a bad signature is an error and does
  not fall back.
- The `dev` build case is the existing `TestCheckSkipsBuildsWithoutAVersion`.
- The version is taken from the installer name, and the signature is
  fetched from that exact release (`download/v<version>/`), so a release
  published between the two requests cannot pair mismatched files.

Not checked:

- `trustedKeys` is empty until AU-01 provides the public keys, so in a
  build today the feed always answers `ErrUnsigned` and the app behaves as
  before. Nothing is verified against a real release yet.
- The `AGENT_SESSIONS_UPDATE_URL` override is not covered by a test.
- `golangci-lint` is not installed here; `go vet` and `gofmt` are clean.
