# AU-15 — macOS app menu: Check for Updates…

- **Status:** ✅ Done
- **Estimate:** 2 h
- **Depends on:** AU-14
- **Plan:** [auto-update.md](../../plan/auto-update.md)

## Scope

- A **Check for Updates…** item below About in the macOS app menu.
- A click opens Settings › General in the front window and runs the
  check from AU-14 there, so the answer shows where the user looks. With no
  window open, a new window opens first.

## Likely files

`cmd/agent-sessions/about.go` (or a new `menu.go`), `internal/app`,
`frontend/src/App.svelte`, tests.

## Acceptance criteria and tests

- A Go test: the item sits right after About and calls its handler.
- A frontend test: the event opens Settings › General and starts a check.
- Not on Windows or Linux (no app menu).

## Evidence

- `cmd/agent-sessions/about.go`: `replaceAboutItem` now also adds **Check for
  Updates…** right after About. Its handler (`shell.checkForUpdates`) picks the
  focused app window (`updateWindow`; never the About window), raises it and
  sends `update:check` to it only. The frontend (`subscribeUpdateCheck` in
  `App.svelte`) opens Settings › General and runs `updates.checkNow()`.
- Go tests (`go test -tags desktop ./cmd/agent-sessions`, run on this Mac):
  About stays first, Check for Updates… is second, the rest of the app menu
  is intact; `updateWindow` for a focused app window, About focused, nothing
  focused, and only About open.
- Frontend tests: `subscribeUpdateCheck` subscribes and unsubscribes on the
  event name the Go side sends (the test also reads it from `about.go`);
  `App.svelte` opens Settings › General and starts the check. `npm test`
  (1445 pass, 0 fail), `svelte-check` (0 errors).
  `GOOS=windows go vet -tags desktop,production ./cmd/agent-sessions` passes.
- **Not checked:** the menu item in a running app (a hand test for AU-08).
  With only the About window open the click opens a new window and does not
  send the request; that window's own startup check follows. A Linux vet needs
  cgo and was not run here.
