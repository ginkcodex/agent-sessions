# AU-04 — Setting and update state for the frontend

- **Status:** ✅ Done
- **Estimate:** 2.5 h
- **Depends on:** AU-03
- **Plan:** [auto-update.md](../../plan/auto-update.md)

## Scope

- Setting **Download updates automatically**, on by default, stored with
  the other app settings.
- Bindings: `UpdateState()` returning `idle`, `downloading`, `ready`
  (version), `manual` (version, release page) or `unsupported`; an event when
  it changes; `RestartToUpdate()`; and install-on-quit when a version is
  ready.
- Linux and builds that cannot update answer `unsupported`/`manual`, so the
  frontend keeps today's toast there.

## Likely files

`internal/app/app.go`, `internal/app/update.go`, `internal/update/`,
`frontend/src/lib/api.ts`, `frontend/src/lib/appBinding.ts`.

## Acceptance criteria and tests

- Go tests for each state transition, including the setting turned off
  while downloading.
- The browser demo has no update bindings, as today.

## Evidence

Built as `update.Manager` (`internal/update/manager.go`), one per process and
shared by every window (`Windows.updater`, handed to each `App` in `Reserve`).
`Offer(Info)` takes the daily check's result: no newer release → idle (and
removes downloads); a release without a signed installer, an install that
cannot update itself, or no store → `unsupported` (release page); ready on disk
→ `ready`; setting off or three failed downloads → `manual` (release page);
otherwise a background `Store.Fetch` → `downloading`, then `ready` or back to
`idle` (retry at the next check). `SettingsChanged` redoes the last offer when
the setting flips (off stops the download). `Resume` makes a version left
ready by an earlier run install at the next quit. `Finish(relaunch)` runs from
`Windows.Shutdown` after all windows closed: it stops any download, re-hashes
the ready installer and calls `Apply`; if an installer took over, the normal
"start another copy" restart is skipped.

App bindings (`internal/app/update.go`): `AutoUpdate()`, `SetAutoUpdate(on)`
(`[update] auto` in `config.toml`, on by default, other keys kept),
`UpdateState()`, `RestartToUpdate()` (goes through the existing restart
request, so unsaved-file confirmation still applies) and the `update:state`
event. `CheckForUpdate` now feeds the manager. Frontend: the four methods are
in `appBinding.ts` and optional in `api.ts` (so the browser demo has none), with
`UpdateStatus` in `lib/update.ts` and `UPDATE_STATE_EVENT`.

No platform installer exists yet (`canSelfUpdate` is false everywhere, `Apply`
is a stub), so every build reports `unsupported` and keeps today's toast; AU-07
and AU-10 set them.

Ran: `go build ./...`, `go vet ./internal/app ./internal/update`,
`go test -race ./internal/app ./internal/update` (pass), `npm run check`
(0 errors). Tests: each state transition (offered, downloading, ready,
manual, unsupported, idle), the setting turned off while downloading, setting
persistence and defaults, events reaching the window and stopping on close,
quit installing the ready update without relaunch, restart-to-update
relaunching with no second copy, a refused close installing nothing, and a
failed install falling back to the normal restart.

Not checked: no UI yet (AU-05); no real installer (AU-07, AU-10); Windows
runtime.
