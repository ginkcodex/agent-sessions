# LR-10 — repo-meta.json for .rpm files

- **Status:** ✅ Done
- **Estimate:** 3 h
- **Depends on:** LR-09
- **Plan:** [linux-repos.md](../../plan/linux-repos.md)

## Scope

`repo-meta.sh` also fills `"rpm"`: for each `.rpm`, `createrepo_c` on a
folder holding only that file, and the `<package>` element for it from
`primary.xml`, `filelists.xml` and `other.xml`, with `location href` set to
`pool/<version>/<file name>`. Each entry has `arch`, `file`, `size`,
`sha256`, `primary`, `filelists`, `other`.

## Likely files

`packaging/linux/repo-meta.sh`, its test.

## Acceptance criteria and tests

- A repository assembled from these fragments (the LR-12 logic, done here
  with a small script) passes `dnf repoquery` in a Fedora container and
  lists both RPMs.
- The RPMs' signatures, when present, are unchanged by the script.

## Done

- `packaging/linux/repo-meta.sh` fills `"rpm"`.
  - Each `.rpm` is copied alone to `pool/<version>/` in a scratch folder,
    and `createrepo_c` (`--simple-md-filenames --general-compress-type=gz
    --checksum=sha256`) runs there, so `location href` comes out as
    `pool/<version>/<file>`.
  - The one `<package>` element of each of the three files is kept
    verbatim.
  - The run is done twice: the second time after setting the copy's mtime
    to the package's build time. createrepo_c records the mtime as
    `<time file>`, and a download sets it.
  - The script checks the location, checksum, size and pkgid against the
    file, and refuses a file createrepo_c cannot read.
  - `apt-ftparchive` is needed only for `.deb` files, `createrepo_c` only
    for `.rpm` files.
- `packaging/release-checksums.sh` also requires that the rpm list is the
  release's two `.rpm` files, and that each entry's location, checksum, size
  and pkgids match its file.
- `packaging/linux/assemble-rpm-repo.sh` (a test helper) assembles dnf
  repodata from the `"rpm"` entries of one or more `repo-meta.json` files.
  It puts them between createrepo_c's headers and writes a `repomd.xml`:
  the LR-12 logic.
- Tests:
  - `packaging/linux/test-repo-meta.sh` covers the `.rpm` entries.
  - `packaging/linux/test-repo-meta-fedora.sh` is new.
  - `make test-repo-meta` also downloads the v1.5.5 `.rpm` files, and runs
    both scripts, in Ubuntu 24.04 and Fedora 42.
- `.github/workflows/release.yml`: the `artifacts` and `release` jobs
  install `createrepo-c rpm-common` along with `apt-utils`. Without
  `rpm-common`, createrepo_c prints "Unable to open /usr/lib/rpm/rpmrc" for
  each package.

## Evidence

- `make test-repo-meta` passes all 49 checks. It uses the v1.5.5 packages,
  checked against their `SHA256SUMS`.
- Ubuntu 24.04, createrepo_c 0.17.3:
  - Each `.rpm`'s primary, filelists and other elements equal those
    createrepo_c writes for both files in one folder, apart from the
    location and `<time file>`.
  - The location is `pool/1.5.5/<file>`, and `<time file>` equals the build
    time.
  - Fields, arch, order, size and sha256 are right.
  - Touching the files and rerunning writes the same `repo-meta.json`.
  - The packages are unchanged.
  - repo-meta.sh refuses a broken `.rpm` and an empty folder.
  - release-checksums refuses:
    - a meta that leaves out an `.rpm`;
    - a wrong sha256;
    - a primary with another location or checksum;
    - an other.xml with another pkgid.
  - The LR-09 `.deb` checks still pass.
- Fedora 42, createrepo_c 1.2.0, dnf5:
  - `dnf repoquery --repofrompath` on the assembled repository lists both
    packages at `pool/1.5.5/<file>`.
  - `--files` lists `/usr/bin/agent-sessions`, from filelists.xml.
  - `--changelogs` prints the package's heading, so dnf reads other.xml.
    The packages have no changelog entries, so none were compared.
  - Fedora's createrepo_c writes the same `.rpm` entries as Ubuntu's, byte
    for byte.
  - Copies signed with a throwaway gpg key (`rpm --addsign`):
    - keep their bytes through repo-meta.sh;
    - pass `rpm --checksig`;
    - get entries whose sha256 is the signed file's, not the unsigned one's.
- Mutation check: with the mtime step removed, the "file time is the build
  time" and "same packages give the same file" checks fail, as they should.
- shellcheck 0.9.0 is clean on the five scripts. actionlint reports only the
  existing SC2046 note at line 242 (macOS job).
- Not checked:
  - the workflow steps in a real release run;
  - `dnf install` from a served repository, which needs LR-12 and LR-14;
  - RPMs signed by nfpm (LR-08); only `rpm --addsign` signing was tested.
