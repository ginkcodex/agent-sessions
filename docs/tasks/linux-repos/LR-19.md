## Scope

Needs the maintainer's Cloudflare account and Postgres:

- Create the Hyperdrive configuration and bind it; set `INGEST_TOKEN`,
  `GITHUB_TOKEN` (fine-grained, public repository read only) and
  `REPO_SIGNING_KEY`; set `LINUX_REPOS_TOKEN` here.
- `npm run db:migrate` against production and set the secrets before
  `main` gets the Worker: its hourly cron logs an error each run until the
  tables and `GITHUB_TOKEN` exist. Then deploy the website, then
  `npm run backfill`.
- Set `RPM_SIGNING_KEY` in this repository's `release` environment
  (LR-15). Then run the release workflow by hand (workflow_dispatch) and
  check its "Sign the .rpm packages" step signs both `.rpm` files (LR-08).
  Until the secret is set, a release fails at that step.
- Publish the first release with signed RPMs and `repo-meta.json`; check it
  reaches both repositories without manual steps.
- Add the repository key's and RPM key's fingerprints to README and the
  website's download notes (LR-18), next to the setup commands.
- Merge README's Linux section (LR-18) and deploy the website's download
  notes only once the steps above work: until then the commands fail.
- Run `verify-repo.sh` against production, and again after the next
  release. Pulling (a release marked as a pre-release) is checked on a
  preview bound to its own database, not with a real release.
