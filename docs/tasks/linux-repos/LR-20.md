# LR-20 — Website: theme menu test fails now and then

- **Status:** ✅ Done
- **Estimate:** 1 h
- **Depends on:** —
- **Plan:** [linux-repos.md](../../plan/linux-repos.md)

Found during [LR-01](LR-01.md). It is in `agent-sessions-web`, not caused by
the Worker: the live site, which has no Worker code, fails the same way.

## Scope

`test/theme.spec.ts`'s `setTheme` clicks a `menuitemradio` in the theme
menu, and about one run in twenty fails with "element is not stable …
element was detached from the DOM" (tests at lines 12 and 87). Seen against
the live site and the LR-01 preview, not yet against `vite preview`. Find
whether the menu re-renders its items after opening (the app's bug) or the
test clicks too early (the test's), and fix that one.

## Likely files

`web/test/theme.spec.ts`, the theme menu component in `web/src/lib/`.

## Acceptance criteria and tests

- `npx playwright test theme.spec.ts --repeat-each=20` passes against
  `vite preview` and against a remote URL with `PLAYWRIGHT_BASE_URL`.
- No retry or longer timeout hides the race.

## Done

The test's bug, twice over; the menu does not re-render its items.

1. **A navigation that ends after the menu opens.** The first test clicked
   the Guides link and opened the menu at once. When the client-side
   navigation finished, SvelteKit moved focus to the new page; the menu's
   `focusout` handler closed it, and the item Playwright was about to click
   was detached. The failure snapshot showed `/guides/` with the menu
   closed. A throwaway test that delayed every request after the first by
   1.5 s showed the same: the menu opened on `/`, then closed when the URL
   became `/guides/`, with focus on `BODY`. The test now waits for the URL
   and the guide's heading before opening the menu.
2. **A click before the page's scripts run.** With the first fixed, 1 in 20
   live runs failed at the first `setTheme`: the button was focused, no
   menu. The button is the server-rendered one until hydration, so a click
   then does nothing. A throwaway test that delayed `/_app/` scripts by 2 s
   reproduced it. `setTheme` now clicks again until the menu is open
   (`expect(...).toPass()`, a 1 s check per try; it does not click while
   `aria-expanded` is `true`, so it cannot close a menu it opened). The
   keyboard test does the same once before its first key press.

A real user's first click before hydration also does nothing. That is the
site's ordinary hydration window, not changed here.

## Evidence

- Before the fix, against the live site: 11 of 20 runs of the first test
  failed (`--repeat-each=20`).
- After the first fix: 19 of 20 passed; the failure was the hydration case.
- After both, `PLAYWRIGHT_BASE_URL=https://agent-sessions.ginklab.cv npx
  playwright test theme.spec.ts --repeat-each=30`: 120 passed.
- Against `vite preview`: `--repeat-each=20`, 80 passed; the full suite, 32
  passed.
- No timeout was raised and no Playwright retry added. The `toPass` loop
  only repeats the click that opens the menu; the rest of each test runs
  once.
- Not checked against an LR-01-style preview with the Worker; the live site
  fails the same way without it.
