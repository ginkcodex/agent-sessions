# LR-14 — Worker: generations, rebuild and serving

- **Status:** ⬜ Not started
- **Estimate:** 3.5 h
- **Depends on:** LR-05, LR-11, LR-12, LR-13
- **Plan:** [linux-repos.md](../../plan/linux-repos.md)

## Scope

- The rebuild hook for ingest: build apt and dnf files from every stable
  release with `repo-meta.json`, sign, write a new generation in one
  transaction, then point `current` at it. Prune generations beyond the
  newest five and older than 14 days.
- Routes as in the plan's serving table, with its cache headers. Pool paths
  redirect only to assets in the `assets` table.

## Likely files

`web/src/server/repo/generation.ts`, `web/src/server/repo/routes.ts`, tests.

## Acceptance criteria and tests

Against the local Postgres:

- After two ingests, a hash-named file from the first generation is still
  served.
- A rebuild that fails during signing leaves `current` unchanged.
- An unknown pool path is 404; a known one is a 302 to its GitHub URL.
- A release turned into a pre-release drops out of the next `Packages` and
  `primary`.
