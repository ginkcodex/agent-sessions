# LR-04 — GitHub release reader and checks

- **Status:** ✅ Done
- **Estimate:** 3 h
- **Depends on:** LR-03
- **Plan:** [linux-repos.md](../../plan/linux-repos.md)

## Scope

Pure functions plus a small GitHub client:

- Read a release by tag (`/repos/ginkcodex/agent-sessions/releases/tags/{tag}`)
  with `GITHUB_TOKEN`; drafts are refused.
- Download `SHA256SUMS`, parse it strictly, and check `repo-meta.json`
  against it. A release without `repo-meta.json` is recorded but not listed
  in the repositories.
- Classify every asset by name into os, arch and kind, using the names
  `make package-linux` produces; other names get kind `other`.

## Likely files

`web/src/server/github.ts`, `web/src/server/assets.ts`, tests beside them.

## Acceptance criteria and tests

- Classification of the 1.5.5 asset list (fixture) matches a golden table.
- A `repo-meta.json` whose hash differs from `SHA256SUMS`, a missing
  `SHA256SUMS`, malformed lines, and a tag that is not semver are each
  refused with a message.
- The client sends a `User-Agent` and the token, and reports rate limiting
  as its own error.

## Done

In `agent-sessions-web`, branch `feat/linux-repos`, commit `db187fe`. The
Worker's code lives in `worker/`, not `src/server/`.

- `worker/release.ts`, pure functions:
  - `versionOf(tag)`: `v` plus semver, as the database checks.
  - `parseSha256Sums`: `<hash>  <name>` lines as `sha256sum` writes them,
    lowercase hashes, newline at the end, names the database accepts, no
    name twice. Anything else is refused with the line number.
  - `classify(name, version)`: os, arch (Go's names, `amd64`/`arm64`, for
    every kind) and kind. Only this version's own package names are `deb` or
    `rpm` (with nfpm's `~` for pre-releases); `repo-meta.json` is `meta`;
    the dmg, msi, setup exe and CLI archives get their os and arch; other
    names are `other` with neither.
  - `checkRelease(tag, release, sums, meta)`: refuses a draft, another tag
    than asked for, no publish time, an asset that is not `uploaded`, an
    asset whose URL is not our release's download URL, odd or duplicate
    names. SHA256SUMS must exist, match its size and GitHub's digest, parse,
    list only the release's assets, and list every package and
    `repo-meta.json`. Other files it does not list are recorded without a
    hash (v1.5.6's `SHA256SUMS.minisig` is one). GitHub's `sha256:` digest
    of any asset must agree with SHA256SUMS.
  - `repo-meta.json`, when present: size and SHA256 as listed, UTF-8, and
    the same content checks as `packaging/release-checksums.sh` (exactly
    the release's packages, their arch, sizes and hashes, and each
    paragraph's and `<package>` element's location, size and hash). It is
    returned verbatim. Without it the release is recorded but not listed.
- `worker/github.ts`:
  - `GitHub.release(tag)` reads `/repos/ginkcodex/agent-sessions/releases/tags/{tag}`
    with `Authorization: Bearer`, a `User-Agent` and the API version header.
  - `download` fetches the public download URL without the token (it
    redirects to another host), and stops reading past a cap: 64 KB for
    SHA256SUMS, 1 MB for `repo-meta.json`. Package files are never
    downloaded.
  - Errors: `NotFoundError`, `RateLimitError` (403 with no requests left,
    or 429, with the reset time from `x-ratelimit-reset` or `retry-after`),
    `GitHubError` for other statuses; check failures are `ReleaseError`.
  - `readRelease(github, tag)` refuses a bad tag before any request, then
    reads, downloads and checks.
- `npm run test:worker` runs `worker/test/*.test.ts` with Node's test
  runner, which strips the types (so imports name `.ts` files and
  `erasableSyntaxOnly` is on). `npm run check:worker` type-checks the tests
  too.

## Evidence

- `npm run test:worker`: 15 passed.
  - The 1.5.5 asset list (fixture from the API) classifies as a golden
    table of 12 rows; pre-release names, other versions' packages and
    unknown names are covered.
  - Refused with a message each: a `repo-meta.json` whose bytes differ from
    SHA256SUMS (same size or not); one for another version, missing or extra
    packages, a wrong size, hash or arch, a paragraph or `<package>` naming
    another location, a non-list `deb`; a missing SHA256SUMS, one that
    differs from GitHub's digest, a malformed line (10 kinds), one that
    leaves out a package or lists a file the release lacks; a package whose
    GitHub digest differs; a draft, another tag, no publish time, an asset
    not uploaded, a foreign download URL, a duplicate or dot name; tags
    that are not `v` plus semver (7 kinds).
  - The client sends the token and a `User-Agent` to the API, and no token
    to the download URL; a bad tag makes no request; 403 with no requests
    left and 429 give `RateLimitError` with the right reset time, other 403s
    do not; 404, a failed download and an over-cap body are errors.
- Mutations: turning off the `repo-meta.json` hash check, the GitHub digest
  check, the `repo-meta.json` content check, the "packages must be listed"
  check or the URL check each made a test fail.
- Real data: `readRelease` with the maintainer's token over all 44 published
  releases (v0.9.33 to v1.5.6): 44 read and checked, none refused. Every
  release has 2 `deb`, 2 `rpm`, a dmg, Windows installers and four CLI
  archives; the only unclassified file is v1.5.6's `SHA256SUMS.minisig`. No
  release has `repo-meta.json` yet, so the real-data run did not exercise
  that check; the tests use one built in repo-meta.sh's shape.
- `npm run check:worker`, `npm run check` and `prettier --check .` pass.
- The client inside workerd ran in LR-05's end-to-end check against the
  real GitHub.
- Not checked: GitHub's real rate-limit answers.
