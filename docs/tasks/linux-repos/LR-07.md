# LR-07 — Release workflow calls ingest

- **Status:** ✅ Done. Not run in a real release yet: that is LR-19, with `LINUX_REPOS_TOKEN` set
- **Estimate:** 1.5 h
- **Depends on:** LR-05
- **Plan:** [linux-repos.md](../../plan/linux-repos.md)

## Scope

In this repository, a `linux-repos` job in `.github/workflows/release.yml`
after `release`, for stable releases:

- `curl --fail-with-body` to `POST https://agent-sessions.ginklab.cv/api/ingest`
  with `LINUX_REPOS_TOKEN`, retrying three times.
- Skipped with a warning when the secret is not set (forks, manual runs).
- Its failure does not affect the published release; the cron catches up.

Document the secret in the workflow's header comment, like the AUR secret.

## Likely files

`.github/workflows/release.yml`, `packaging/linux/notify-ingest.sh`.

## Acceptance criteria and tests

- `actionlint` passes.
- A manual run without the secret skips the job with a warning.
- The first real release with the secret set shows `{"changed": true}` in
  the job log (recorded in LR-19).

## Done

- `packaging/linux/notify-ingest.sh <site> <tag>` posts `{"tag"}` to
  `<site>/api/ingest` with `LINUX_REPOS_TOKEN`, passed to curl in a mode
  600 file rather than on its command line. It checks the tag (`v` plus
  semver) and the site URL first.
  - No token: a `::warning::` and exit 0.
  - 200: done. Network errors, 404 (GitHub's API may lag a release made
    seconds ago) and 5xx: retried three times, 15, 30 and 45 s apart.
    Other 4xx: an error at once.
  - A 500 that says `"changed": true` (recorded, but the rebuild failed)
    is an error at once: asking again would answer `changed: false` and
    hide it. The cron retries the rebuild (LR-06).
- `release.yml`: a `linux-repos` job after `release`, for published stable
  versions only (the same condition as `aur`), with a sparse checkout of
  the script and a 10-minute limit. The site is the repository variable
  `LINUX_REPOS_SITE`, else `https://agent-sessions.ginklab.cv`. The header
  comment describes the secret and the variable. A failure leaves the
  release published.

## Evidence

- `actionlint` 1.7.12: no new findings. It still reports one SC2046
  warning in the macOS signing step (`security list-keychains ... $(...)`),
  which was there before this change and splits words on purpose.
  `shellcheck` on the script: clean.
- Against a stub server (Python, answers scripted per request):
  502, 502, 200: three requests, exit 0. 503 four times: four requests,
  then the error, exit 1. 401 and 422: one request, exit 1. A 500 with
  `"changed":true`: one request, exit 1. A 500 "database error" then 200:
  two requests, exit 0. No server: four attempts, exit 1. The stub saw
  `Authorization: Bearer <token>` and the body `{"tag":"v1.5.6"}`.
- Against `wrangler dev` (local workerd, compose Postgres, real GitHub,
  tokens from a temporary env file, removed afterwards): v1.5.6 `changed:
  true`, again (site URL with a trailing slash) `changed: false`; a wrong
  token: 401, not retried; v9.9.9: 404 four times, exit 1; v1.5.5
  `changed: true`. The local rows were cleared after.
- No token: the warning, exit 0. A tag with a quote, a site with a space,
  or one argument: refused, exit 2.
- Not checked: the job in a GitHub Actions run. Manual runs never publish,
  so the job's `if` skips it there, as it does `aur`; the warning path
  runs only in a publishing run without the secret. The first release
  with the secret set records `changed: true` in LR-19.
