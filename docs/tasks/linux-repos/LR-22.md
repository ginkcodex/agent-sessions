# LR-22 — App: Linux update commands upgrade only this app

- **Status:** ✅ Done
- **Estimate:** 0.5 h
- **Depends on:** [LR-17](LR-17.md)
- **Plan:** [linux-repos.md](../../plan/linux-repos.md)

Found after the 1.7.4 release: the website's dnf repository listed 1.7.4,
but `sudo dnf upgrade` on a Fedora machine found nothing. dnf kept its
cached index from the day before; the `.repo` file sets no
`metadata_expire`, so dnf's default (up to 48 h) applies. The toast's
commands also upgraded the whole system, where users only want this app.

## Scope

The Linux update toast's commands:

| Install | Before | After |
|---|---|---|
| apt | `sudo apt update && sudo apt upgrade` | `sudo apt update && sudo apt install --only-upgrade agent-sessions` |
| dnf | `sudo dnf upgrade` | `sudo dnf upgrade --refresh agent-sessions` |
| AUR | `paru -Syu agent-sessions-bin` | `paru -S agent-sessions-bin` |

`--refresh` makes dnf fetch the index again. `--only-upgrade` stops apt
installing the app where it is missing. On Arch, `paru -S` rebuilds from
the AUR's current version without syncing pacman's databases; `-Sy` without
`-u` would be a partial upgrade, which Arch does not support.

## Likely files

`frontend/src/lib/update.ts` (`UPGRADE_COMMANDS`),
