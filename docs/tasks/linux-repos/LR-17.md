# LR-17 — App: Linux update toast knows the repository

- **Status:** ✅ Done
- **Estimate:** 2.5 h
- **Depends on:** —
- **Plan:** [linux-repos.md](../../plan/linux-repos.md)

## Scope

- Go: on Linux, `CheckForUpdate` also reports how the app was installed:
  `apt-repo`, `dnf-repo` (a source file naming `agent-sessions.ginklab.cv`
  in `/etc/apt/sources.list.d/` or `/etc/yum.repos.d/`), `aur`
  (`/etc/arch-release`), or `manual`.
- Frontend: the toast's text and action follow it. Repository installs
  show the upgrade command with a copy action; manual installs link to the
  website's install guide.

## Likely files

`internal/update/update.go`, `internal/update/install_linux.go`,
`internal/app/app.go`, `frontend/src/lib/update.ts`,
`frontend/test/update.test.mjs`.

## Acceptance criteria and tests

- Go tests with temporary `/etc`-like roots for each case, including a
  source file for another repository.
- Frontend tests for each toast.
- macOS and Windows toasts are unchanged.

## Evidence

- Go: `update.LinuxInstall(root)` (`internal/update/install.go`) reads
  `etc/apt/sources.list`, `.list` and deb822 `.sources` files in
  `etc/apt/sources.list.d/`, `.repo` files in `etc/yum.repos.d/` and
  `etc/arch-release` under root. Only a source that is not commented out
  and not disabled (`Enabled: no`, `enabled=0`) and that names
  `agent-sessions.ginklab.cv` counts; a repository wins over Arch.
  - It is in a plain file, not `install_linux.go`, so its tests run on every
    system; only `internal/app/update_linux.go` wires it in, on Linux.
  - `update.Info` and `update.Status` gained `install` (omitted when empty).
    `App.CheckForUpdate` fills it, and `Manager.Install` fills it in every
    status, so a window that only gets `update:state` knows it too.
- Frontend: `linuxUpdateToast` in `frontend/src/lib/update.ts`.
  - apt, dnf and AUR toasts show the command (`code`) and **Copy command**,
    which copies through the native clipboard (`copyToClipboard`) and
    confirms with a toast, or shows Couldn't copy.
  - A package installed by hand gets **Open install guide**
    (`https://agent-sessions.ginklab.cv/download`) and **Open release page**.
  - Without `install` (macOS, Windows) the toasts are as before, and a ready
    update is always the Restart now toast.
- Tests:
  - `TestLinuxInstall`: 18 temporary `/etc` roots: none, apt `.list`, a line in
    `sources.list`, another file name, deb822, deb822 disabled, ours in a
    second deb822 paragraph with a continuation line, a line commented out
    on upgrade, another repository, our host only in a comment, a
    `.list.save`, dnf `.repo`, dnf `enabled=0`, another dnf repository, our
    host only in `name=`, a `.repo.rpmsave`, Arch, Arch with our apt source.
  - `TestManagerStatusSaysHowTheAppIsInstalled`,
    `TestCheckForUpdateSaysHowLinuxInstallsGetUpdates` (and empty without a
    method), and on Linux `TestLinuxReportsHowItGetsUpdates`.
  - `frontend/test/update.test.mjs`: one test per toast (apt, dnf, AUR with
    the copy action; manual with both pages), the update state alone, and
    unchanged macOS/Windows toasts.
- Runs:
  - `go test ./internal/update/ ./internal/app/`: pass on macOS (Darwin
    arm64).
  - The same packages' new tests in a `golang:1.26` Linux container
    (`CGO_ENABLED=0`): pass.
  - `go vet` of both packages for linux and windows: clean.
  - `npm test` in `frontend`: 1450 pass, 0 fail. `npm run check`: 0 errors.
- Not checked: the toast in a running Linux desktop app, and a real system
  with the repository set up (the repository does not exist yet; LR-16 and
  LR-19).
