# IR-04 — Side-effect review of the rendering changes

- **Status:** ✅ Done
- **Estimate:** 2 h
- **Depends on:** IR-01, IR-02
- **Plan:** [idle-rendering.md](../../plan/idle-rendering.md)

## Scope

After the user's native macOS test (GPU still rose to about 70%, then settled
around 20–30%), review every IR-01/IR-02 change for side effects. Remove
anything whose risk outweighs its benefit. Keep the changes that help with the
window visible.

## Likely files

`frontend/src/style.css`, `frontend/src/App.svelte`,
`frontend/src/lib/animationVisibility.ts`,
`frontend/test/idle-rendering.test.mjs`, idle-rendering docs.

## Acceptance criteria and tests

- No global rule can freeze one-shot entrance animations (dialogs, menus,
  toasts start at opacity 0) or connecting/loading indicators.
- Reduced-motion users keep a slowly turning spinner where it is on screen,
  as before IR-02. Icon-only spinners have no other progress sign.
- Tests guard both rules. The frontend suite, type check and build pass.

## Findings

| Change | Side effect found | Action |
|---|---|---|
| `.stale *` animation pause (IR-02) | Panes are `.stale` while a first connection is locked, so the session list `.discovering` and group tree `.tree-message.loading` pulses froze exactly while connecting. One-shot fades caught mid-way also froze. Stale is rare, so the GPU gain was negligible. | Removed |
| `html[data-animations-paused] *` with document visibility (IR-02) | Paused all 37 component uses of `dialog-in`, `pop-in` and `scrim-in`, which start at opacity 0. If any web view reported `document.hidden` while visible, dialogs and menus would stay invisible. WebKit and WebView2 already throttle hidden pages, and the user's improvement was observed with the window visible. | Removed, along with `trackDocumentVisibility` and its App wiring |
| Reduced-motion spinner exception removed (IR-02) | Reversed an earlier, deliberate accessibility choice. The transcript's jump-to-bottom spinner is icon-only. | Restored, limited to visible spinners (`[data-animation-visible]`) |
| IntersectionObserver spinners (IR-02) | None found. Ordinary icons create no observer. A spinner starts at most one observer callback late. Offscreen and hidden-panel spinners stay still, but their "running" text remains. | Kept |
| Static Live dot and ring (IR-01) | Intended visual change: Live is shown by the badge and dot without pulsing. | Kept |
| List `translateZ(0)` only on Linux (IR-01) | Added on 2026-11-09 for Linux only (SS-07, commit 31549ce). macOS and Windows return to their earlier behavior. The list has no fixed-position descendants that depend on the containing block. Rows are transformed, so `CountTooltip`'s z-index stacks within its row. | Kept |

Other perpetual animations that do not go through `Icon` are unchanged:
`AttentionDot .working`, session list `.discovering`, group tree loading,
skeleton shimmer, refresh/reconnect/loading spinners, host connecting pulse.
They are candidates for the remaining load (see [IR-05](IR-05.md)), not side
effects of this work.

  starting at opacity 0; and the visible-only reduced-motion spinner.
- The first run failed (1 test) because a CSS comment contained the literal
  `animation-play-state`. The comment was reworded and the rerun passed.

  `git diff --check` passed.
