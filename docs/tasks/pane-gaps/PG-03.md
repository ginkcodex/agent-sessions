# PG-03 — Accent line fades out without shrinking

- **Status:** ✅ Done
- **Estimate:** 0.5 h
- **Depends on:** PG-01
- **Plan:** [pane-gaps.md](../../plan/pane-gaps.md)

## Scope

When the pointer left a gap splitter, the blue accent line jumped back to the
grip's position at once but kept shrinking from full length to the grip's
18px over the 0.15s transition, so a long blue bar hung down from the middle
of the splitter while it faded. Draw the grip and the accent line as separate
layers that keep their size and only fade.

## Likely files

- `frontend/src/lib/components/common/Splitter.svelte`

## Acceptance criteria and tests

- The accent line keeps the splitter's full length and fades out in place
  when the pointer leaves, for horizontal and vertical gap splitters.
- The grip fades back in at the same time. Hover, drag and focus still show
  the line and hide the grip.
- Nested hairline splitters are unchanged.

## Evidence

Done:

- In gap mode, `.line` is always the full-length 2px accent line, and only its opacity changes (0 at rest, 1 on hover, drag or focus). The grip is now the splitter's `::before`, which fades out while the line shows. Neither layer changes size, so nothing animates geometry.

Verified on Linux (2026-11-28), in headless Chrome against the Vite dev server with the mock backend. Driven over CDP: move the pointer onto the splitter, then away, sampling the line's box and the opacity of both layers.

- Before the fix, on the sidebar splitter (751px tall), the line was 668px tall at +30ms, 207px at +80ms and 18px at +300ms. It was still blue while it shrank.
- After the fix, on the sidebar splitter, the line stayed 751px. Its opacity went 1.00 → 0.65 → 0.15 → 0.00 while the grip's went 0.00 → 0.21 → 0.51 → 0.60.
- On the terminal panel's vertical splitter, the line kept its 2px thickness with the same fade.

- `test/splitter.test.mjs`: 9/9 pass.
- `npm --prefix frontend test`: 1,631 pass, 0 fail, 5 skipped.
