# NG-01 — Git ignore scope for walked repositories

- **Status:** ✅ Done
- **Estimate:** 2 h
- **Depends on:** —
- **Plan:** [nested-repo-gitignore.md](../../plan/nested-repo-gitignore.md)

## Scope

A per-listing helper in `internal/files` that, given a repository folder
found by the walk, returns its ignored files and wholly ignored folders,
prefixed with the folder's path relative to the listing root, or "unknown".

- One `git ls-files -z --others --ignored --exclude-standard --directory`
  through `gitOutputEnv` (no fsmonitor, literal pathspecs, unquoted paths),
  with History's environment and `GIT_CEILING_DIRECTORIES` set to the
  repository's parent.
- Unknown when Git fails or is missing, the context ends, Git answers `./`,
  or the listing's budget (64 queries, 5 s) is spent.
- Keep `IgnoredDirectories` (code-check discovery) as it is; share the
  parsing where it reads cleanly.

## Likely files

`internal/files/walk_scope.go` (new), `walk_scope_test.go`.

## Acceptance criteria and tests

Real Git: ignored file, wholly ignored folder, folder with tracked and
ignored files (not collapsed; its ignored files reported), nested
`.gitignore`, `.git/info/exclude`, an invalid `.git` inside an outer
repository answers unknown (ceiling), `./` answer, missing Git (empty
`PATH`), budget by count and by time, a configured fsmonitor script does not
run.

## Evidence

- `internal/files/walk_scope.go`: `repositoryIgnored` (the query, with
  `GIT_CEILING_DIRECTORIES` set to the repository's parent and History's
  environment; `gitOutputEnv` adds `core.fsmonitor=false`), `parseIgnored`
  (now also used by `IgnoredDirectories`), and `walkScopes`, which asks each
  repository once in walk order (64 queries, 5 s) and answers for the
  innermost repository holding a path. The walk does not use it yet (NG-02).
- `walk_scope_test.go` (real `git` 2.53.0): ignored file, wholly ignored
  folder, `logs/` with only ignored files (Git reports the folder and the
  file), `keep/` holding a tracked file (not collapsed; its new file
  reported), nested `.gitignore`, `.git/info/exclude`; an invalid `.git`
  inside an outer repository that tracks a file there answers unknown (the
  test fails with the ceiling removed); no `git` on `PATH`; `./`; innermost
  repository lookup; budget by count, by time and a cancelled walk; the
  query's deadline is the walk's. `fsmonitor_test.go` covers
  `repositoryIgnored`.
- `go test -count=1 ./internal/files/ ./internal/codediagnostics/` passes.
  `go tool golangci-lint run ./internal/files/`: no findings in the changed
  files (50 existing ones elsewhere, unchanged).
- Not checked: Windows Git (path separators in the ceiling).
