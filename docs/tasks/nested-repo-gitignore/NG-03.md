# NG-03 — Blame bar says when Git ignores the file

- **Status:** ✅ Done
- **Estimate:** 2 h
- **Depends on:** —
- **Plan:** [nested-repo-gitignore.md](../../plan/nested-repo-gitignore.md)

## Scope

In `FileViewer.svelte`, a blame answer with `ignored` no longer hides the
blame bar. The bar reads "Ignored by Git — no blame" for that file, on every
line, without asking the host again. A file the listing already lists as
ignored (`ignoredByGit`) still shows no bar. Moving to another file, host or
folder starts over as today.

## Likely files

`frontend/src/lib/components/common/go-to-file/FileViewer.svelte`,
`frontend/test/file-blame-api.test.mjs` or a viewer test beside it.

## Acceptance criteria and tests

- Host answers `ignored`: the bar stays and shows the message; a second line
  in the same file shows it with no new request.
- A file listed in `listing.ignored` shows no bar and makes no request.
- Ordinary blame, uncommitted lines and errors unchanged.
- `npm test` and `npm run check` pass.

  stays and reads "Ignored by Git — no blame", and the blame effect returns

  the loading state then. The key is the directory and path, so another file
