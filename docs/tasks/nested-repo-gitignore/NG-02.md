# NG-02 — Walk lists each repository with its own ignore rules

- **Status:** ✅ Done
- **Estimate:** 4 h
- **Depends on:** NG-01
- **Plan:** [nested-repo-gitignore.md](../../plan/nested-repo-gitignore.md)

## Scope

`walkPaths` applies the Walk table of the plan: on entering a folder with its
own `.git` marker it records the repository (as today), starts its status (as
today) and asks its scope (NG-01). Inside a repository with a known scope,
wholly ignored folders go to `IgnoredDirectories` and are not walked, ignored
files go to `Ignored`, and `skipDirs` no longer applies. Unknown scope and
folders outside any repository keep the name rules. Ignored files count
toward the file cap. A repository marker is a `.git` directory or regular
file, not a symlink.

Search for a non-Git root follows, since it reads the walk's `Files`.

## Likely files

`internal/files/files.go` (`walkPaths`, `Listing` doc comments),
`files_test.go` or a new `walk_ignore_test.go`, `search_test.go`.

## Acceptance criteria and tests

Real Git, a plain root holding repositories:

- An ignored folder in a repository is in `IgnoredDirectories`, its files in
  no list; an ignored file is in `Ignored`, not `Files`; a tracked file that
  matches an ignore rule stays in `Files`.
- A repository folder the outer repository ignores is walked with its own
  rules and is in `Repositories`; a repository inside an ignored folder is
  not found.
- A committed `vendor/` is listed; a non-repository `node_modules` outside any
  repository is still skipped by name.
- Git failing for one repository: that repository is walked with the name
  rules; the others still use Git; the listing does not fail.
- File cap reached with ignored files counted; `Truncated` set.
- Status of nested repositories unchanged (`NB-04` tests still pass).
- Search on a plain root does not return matches from ignored files.
