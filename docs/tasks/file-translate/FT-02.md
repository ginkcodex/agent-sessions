# FT-02 — Cache file translations across preview closes

- **Status:** ✅ Done
- **Estimate:** 3 h
- **Depends on:** FT-01
- **Plan:** [file-translate.md](../../plan/file-translate.md)

## Scope

Move whole-file translation ownership to a bounded in-memory store independent of
FileViewer. Keep pending/completed translations across Esc, viewer teardown,
preview toggles and tab changes. Match host/project/path/language and exact source
before reuse; never automatically translate changed content.

## Likely files

- `frontend/src/lib/stores/fileTranslations.svelte.ts`
- `frontend/src/lib/components/common/go-to-file/FileViewer.svelte`
- `frontend/test/file-translation.test.mjs`, viewer fixtures and cache tests

## Acceptance criteria

- Reopening unchanged source restores translation and original/translated choice
  without another provider call; pending work survives close and deduplicates.
- Different source, language, path, project or host never shows another result.
- Late old-source replies cannot overwrite newer requests; Retry/retranslate work.
- Cache is memory-only, bounded to 20 entries / 16 MiB estimated string storage.
- Source files remain unchanged; selected-text translations are unaffected.

## Tests

Test store boundaries, identity/source isolation, deduplication and out-of-order
results. Update compiled viewer interaction tests to share the real cache across
unmount/remount, including pending requests. Run focused/full frontend tests,
check/build and repository Go race tests; record native/live-provider gaps.

## Evidence

- Added an independent `FileTranslationsStore` singleton. Exact source matching
  and host/project/path/language keys restore completed translations and the
  original/translated toggle without relying on tab object identity.
- Pending requests survive viewer teardown, preview exits and navigation. The
  store deduplicates same-source pending requests; changed-source requests
  supersede their slot and old replies cannot overwrite them. Reopening never
  automatically sends source to a provider.
- Added LRU eviction at 20 entries / 16 MiB estimated UTF-16 string storage,
  covering keys, original content, results and error strings. Evicted or cleared
  requests cannot repopulate entries. No disk/browser-storage persistence.
- Updated the actual compiled viewer-flow harness to use the real compiled
  reactive store. Six added tests cover completed/pending close/reopen, preserved
  toggles, preview/tab/language round trips, changed-source out-of-order replies,
  key isolation, LRU/byte limits and late results after clear.
- Focused file/selection tests: 51/51 passed. Re-ran all 13 file translation tests
  after removing obsolete harness helpers; all passed.
- Full frontend suite: 1,215 passed, 1 skipped, 0 failed.
- `npm run check`: 0 errors, 0 warnings.
- `make test` (`go test -race ./...`): passed.
- `npm run build`: passed; existing large-chunk warning remains.
