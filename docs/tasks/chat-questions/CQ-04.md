# CQ-04 — Bindings and remote hosts

- **Status:** ✅ Done
- **Estimate:** 2 h
- **Depends on:** CQ-03
- **Plan:** [chat-questions.md](../../plan/chat-questions.md)

## Scope

- `internal/app`: `ChatAnswer(chatID, questionID, action, content)` for local
  and remote chats; the app's chat start sets `Questions`; the binding
  contract test.
- `internal/rpc`: `chatAnswer` method, `ChatAnswerParams`,
  `Capabilities.ChatQuestions`; the client refuses `ChatAnswer` and sends no
  `Questions` flag to a server without it.

## Acceptance and tests

- RPC round trip of `chatAnswer`; the capability; an old server keeps the
  fallback (no flag sent).
- Binding contract updated.
- `go test -race ./internal/app/ ./internal/rpc/`, `make lint`.

## Evidence

- `internal/rpc`: `Capabilities.ChatQuestions` (set with `ACPChat`, omitted
  when false), the `chatAnswer` method with `ChatAnswerParams`, and the
  `question_not_found` error code for `engine.ErrQuestionNotFound`. The
  client returns `ErrNoChatQuestions` from `ChatAnswer` and clears
  `ChatStartRequest.Questions` when the host does not offer questions, so an
  older server's agents keep their own fallback.
- `internal/app`: `ChatAnswer` for local chats and for a host's chats
  (`ErrChatRemote` when the host has no chats); `ChatAnswer` is in the
  frontend's `APP_METHODS`.
- The app does not set `Questions` on its own: the frontend sends
  `questions: true` from CQ-06, when the question card exists, and the
  binding passes it through. Until then no chat asks for questions, so no
  question can wait unseen.
- Tests:
  - `TestChatRPCQuestions`: the question's fields arrive in order; an unknown
    ID gives `ErrQuestionNotFound`; an answer outside the options is
    refused with its message; the accepted answer reaches the fake agent;
    with the capability cleared, `ChatAnswer` gives `ErrNoChatQuestions` and
    a new chat's agent sees no elicitation.
  - `TestChatRPCCapability` covers `ChatAnswer` without chats;
    `TestErrors_RoundTripSentinels` covers the new code.
  - `TestChatAnswerBinding` (local and remote): the question shows in
    `ChatList`, an unknown ID is refused, the answer ends the turn and the
    question leaves the state. `TestChatRefusedForHosts` covers
    `ChatAnswer`.
- Ran: `go test -race -count=1 ./internal/app/ ./internal/rpc/` (pass),
  `node --test test/desktop-runtime.test.mjs` (11/11), gofumpt and
  golangci-lint on the changed files (no findings in them; the packages'
  existing findings elsewhere are unchanged).
- Not run: `make lint` over the whole tree, which reports existing issues
  in other packages.
