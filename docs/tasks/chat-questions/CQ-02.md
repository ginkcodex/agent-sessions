# CQ-02 — ACP form elicitation in the client

- **Status:** ✅ Done
- **Estimate:** 4 h
- **Depends on:** CQ-01
- **Plan:** [chat-questions.md](../../plan/chat-questions.md)

## Scope

- `internal/acp/elicitation.go` (new; `types.go` only gains
  `ClientCapabilities.Elicitation`): `ElicitationCapabilities`, `CreateElicitationRequest`,
  `ElicitationSchema`, property schemas (string, number, integer, boolean,
  array; `oneOf`/`enum`, `items.anyOf`/`items.enum`, limits, `_meta`),
  `CreateElicitationResponse`.
- `ClientCapabilities.Elicitation` set to `{form: {}}` only when
  `ClientOptions.OnElicitation` is set.
- `Client.handleRequest`: `elicitation/create` in form mode goes to
  `OnElicitation`; URL mode and unsupported schemas get -32602; turn cancel and
  close answer `cancel`, like permission waits.
- `Conn`: a context per incoming request, cancelled by `$/cancel_request` with
  its ID; the reply is then error -32800.
- `ElicitationSchema.Supported()` and `Validate(content)`: the rules in the
  plan's Validation section.

## Acceptance and tests

- Capability advertised only with the callback.
- A form request reaches the callback; accept, decline and cancel go back as
  sent.
- `$/cancel_request` cancels the callback's context and replies -32800.
- URL mode, an unknown property type, a nested object and a `format` are
  refused.
- Validation: unknown keys, an option not in the list, duplicate or too many
  items, length, pattern, number limits, integer, required.
- `go test -race ./internal/acp/`, gofumpt and golangci-lint on the changed
  files.

## Evidence

Done:

- `internal/acp/elicitation.go` holds the types, kept in sent order by
  `ElicitationFields` (a Go map would sort the keys, and integer-like keys
  would also be reordered in JavaScript). It also holds `Supported()` and
  `Validate()`.
- `ClientOptions.OnElicitation` turns on `clientCapabilities.elicitation.form`.
- `Client.handleRequest` routes `elicitation/create` as follows:
  - modes other than form, a form without a session and unsupported schemas
    get -32602;
  - forms are registered like permission waits, so `Cancel`, `Close` and the
    agent's exit answer `cancel`;
  - an accepted answer is validated once more and sent as `cancel` if it does
    not fit;
  - `decline` drops any content.
- `Conn` gives each incoming request its own context. `$/cancel_request`
  cancels it, and the reply becomes -32800 "request cancelled".
- `CallWithdrawing` (used by the fake agent) sends `$/cancel_request` when its
  context ends and expects the late reply instead of reporting it.
- The fake agent has two new prompts:
  - `question claude|codex|opencode|url|email` asks forms shaped like each
    adapter's (`acptest.QuestionForms`);
  - `withdraw MS` asks a form and withdraws it.

Verified:

- `go test -race -count=1 ./internal/acp/...` passed. The new tests are:
  - `TestElicitationFieldsKeepOrder`, `TestElicitationSupported`,
    `TestElicitationValidate`;
  - `TestCancelRequestWithdrawsHandler`, `TestCancelRequestUnknown`,
    `TestCallWithdrawing`;
  - `TestQuestionsNeedOnElicitation`, `TestQuestionAnswers` (accept, own
    answer, decline, cancel, unknown action, invalid answers, Codex's required
    note, OpenCode's limits, URL mode and `format` refused),
    `TestQuestionFieldOrder`;
  - `TestCancelAnswersPendingQuestion`, `TestCloseAnswersPendingQuestion`,
    `TestWithdrawnQuestion`.
- `go build ./...` passed, and `go test ./internal/engine/ ./internal/rpc/`
  passed.
- `go tool gofumpt` was run on the changed files, and
  `go tool golangci-lint run ./internal/acp/...` reported 0 issues.
