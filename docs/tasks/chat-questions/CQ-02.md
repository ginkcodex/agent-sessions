# CQ-02 — ACP form elicitation in the client

- **Status:** ⬜ Not started
- **Estimate:** 4 h
- **Depends on:** CQ-01
- **Plan:** [chat-questions.md](../../plan/chat-questions.md)

## Scope

- `internal/acp/types.go`: `ElicitationCapabilities`, `CreateElicitationRequest`,
  `ElicitationSchema`, property schemas (string, number, integer, boolean,
  array; `oneOf`/`enum`, `items.anyOf`/`items.enum`, limits, `_meta`),
  `CreateElicitationResponse`.
- `ClientCapabilities.Elicitation` set to `{form: {}}` only when
  `ClientOptions.OnElicitation` is set.
- `Client.handleRequest`: `elicitation/create` in form mode goes to
  `OnElicitation`; URL mode and unsupported schemas get -32602; turn cancel and
  close answer `cancel`, like permission waits.
- `Conn`: a context per incoming request, cancelled by `$/cancel_request` with
  its ID; the reply is then error -32800.
- `ElicitationSchema.Supported()` and `Validate(content)`: the rules in the
  plan's Validation section.

## Acceptance and tests

- Capability advertised only with the callback.
- A form request reaches the callback; accept, decline and cancel go back as
  sent.
- `$/cancel_request` cancels the callback's context and replies -32800.
- URL mode, an unknown property type, a nested object and a `format` are
  refused.
- Validation: unknown keys, an option not in the list, duplicate or too many
  items, length, pattern, number limits, integer, required.
- `go test -race ./internal/acp/`, gofumpt and golangci-lint on the changed
  files.
