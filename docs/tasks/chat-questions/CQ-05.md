# CQ-05 — Question model, store and mock

- **Status:** ✅ Done
- **Estimate:** 4 h
- **Depends on:** CQ-04
- **Plan:** [chat-questions.md](../../plan/chat-questions.md)

## Scope

- `frontend/src/lib/types.ts` and `api.ts`: `ChatQuestion`, the updates,
  `chatAnswer`, the Wails binding and its cancel-on-close handling.
- `frontend/src/lib/chatQuestions.ts` (pure): schema → questions (kind,
  header, question text, options with descriptions, default, limits,
  required); own-answer pairing for each adapter; the Codex "Other" option
  hidden; a draft; `missing(draft)`; `content(draft)` for each adapter's shape;
  a summary line.
- `stores/chats.svelte.ts`: pending questions per chat from updates and state;
  `answer()`; the summary in the live tail after Submit.
- Mock agent: asks Claude-, Codex- and OpenCode-shaped forms on a keyword, and
  withdraws one.

## Acceptance and tests

- Unit tests for each adapter's shape, pairing, required, limits, content and
  summary; store tests for asked, answered, resolved and withdrawn;
  `npm run check`.

## Evidence

What was done:

- `types.ts`: `ChatQuestion`, `ChatQuestionField`, `ChatQuestionOption`,
  `ChatAnswerAction`, the `question` and `question_resolved` updates,
  `ChatState.questions` and `ChatStartRequest.questions`. `api.ts`:
  `chatAnswer` over the `ChatAnswer` binding, passed through on a host
  switch like `chatRespond`. Cancelling on close stays on the backend: every
  exit path answers `cancel` (CQ-03), and the store drops the cards.
- `chatQuestions.ts` (pure): `questionForm` turns the fields into questions
  (choice, multi, text, boolean, number) with header and question text,
  Codex's swapped the other way; options with descriptions, a default marked
  but not chosen, limits, required. Own-answer pairing: Codex's `user_note`
  by `questionId`, with its "Other" option hidden and sent with the note;
  `<key>_custom` for Claude Code and OpenCode. A required choice or a
  required own field is not paired, so it stays a question of its own. The
  draft functions (`choose`, `toggle`, `setOwn`, `chooseOwn`, `setText`,
  `setYes`, `setNumber`, `clear`) can change any answer until Submit;
  `missing`, `problem`, `submitBlocker`; `content` sends only answered
  fields (no empty lists or blank text); `summary` for accept, decline,
  withdrawn and cancel.
- `chatTail.ts`: a `TailAnswer` item (`addAnswer`). `reconcile` drops it
  once the tool call that asked is saved, or with its saved turn. `chat.ts`
  shows it as text for now; CQ-06 gives it its own look.
- `stores/chats.svelte.ts`: `Chat.questions` from updates and from
  `chatList` after a reload; `answer()` drops the card after the call and
  throws a refused answer, so the card stays. `question_resolved` removes
  the card and, except for `cancel`, adds the summary line. `turn_end`, exit
  and reset clear the questions.
- Mock agent: the prompt keyword "question" asks a form shaped like the
  chat's adapter (Claude Code: three questions with `_custom`, nothing
  required; Codex: required, note and "Other"; OpenCode: required choice,
  multi-select with `_custom`, yes/no). "withdraw" asks and withdraws after
  `withdrawMs`, with Codex's `autoResolutionMs` in `meta`. A chat started
  without `questions` is never asked. `chatAnswer` checks fields, options and
  required answers as the backend does.
- Fixed along the way: the fake Codex form in `internal/acp/acptest` now
  matches codex-acp 2.6.0, where only the question is required, not the note,
  and the question carries `_meta.codex`. The dependent cases in
  `internal/acp/client_test.go` and `internal/engine/chat_test.go` were
  updated (a choice alone is accepted; a note alone is refused).
