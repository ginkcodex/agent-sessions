# RR-05 — Backoff that stays at 10 s; Retry while reconnecting

- **Status:** ✅ Done
- **Estimate:** 1.5 h
- **Depends on:** —
- **Plan:** [remote-reconnect.md](../../plan/remote-reconnect.md)

## Scope

- `reconnectBackoff` becomes 1, 2, 5, 10 s; attempts past the end use the
  last step instead of wrapping (`internal/app/remote.go:391`, `:457`).
  One helper picks the delay for both places.
- `ReconnectBanner.svelte` shows Retry while reconnecting as well as while
  disconnected. It keeps calling `connectionStore.connect(host)`, which
  starts a new generation and cancels the running attempt.

## Likely files

`internal/app/remote.go`, `internal/app/remote_test.go`,
`frontend/src/lib/components/common/ReconnectBanner.svelte`,
`frontend/test/connection.test.mjs`.

## Acceptance criteria and tests

- A table test of the delay helper: attempts 1…8 give 1, 2, 5, 10, 10,
  10, 10, 10 s.
- Retry during `reconnecting` cancels the running attempt: the fake dialer
  sees its context cancelled before the new dial starts, and only one dial
  runs at a time.
- The banner test covers Retry in both phases and none while connected.
- Frontend tests, `npm run check` and the Go tests for `internal/app` pass.
