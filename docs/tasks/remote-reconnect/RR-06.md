## Scope

- `connectionStore.resetStores` tells `appState` whether the host stayed
  the same (the files store already gets this distinction).
- `appState.reset` on the same host keeps the selected group, the selected
  session and the back/forward history. It reloads groups, then sessions
  (same order as today), then the selected session's metadata and
  transcript. If the selected session is gone, it falls back to today's
  behavior (clear and select the first session).
- A host switch and a return to Local reset everything, as today.
- Request guards still drop replies from the previous backend.

## Likely files

`frontend/src/lib/stores/appState.svelte.ts`,

## Acceptance criteria and tests

- Drop and reconnect on the same host: the same session stays selected,
  its transcript reloads, history entries remain and back/forward work.
- The selected session was deleted while disconnected: the first session
  is selected and history no longer points at it as current.
- Host switch: everything resets (existing tests keep passing).
- A late reply from before the reconnect does not overwrite the reload.
- Frontend tests, `npm run check` and `npm run build` pass.
