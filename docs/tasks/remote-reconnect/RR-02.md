# RR-02 — `$/ping` and the client liveness watchdog

- **Status:** ✅ Done
- **Estimate:** 4 h
- **Depends on:** —
- **Plan:** [remote-reconnect.md](../../plan/remote-reconnect.md)

## Scope

Server (`rpc.Server`):

- Answer a `$/ping` request with `{}` in a handler goroutine, before the
  initialize check, without touching the backend or the startup gate.

Client (`rpc.Client`):

- Wrap the transport reader in a counter that stores the time of the last
  received byte (atomic), below `FrameReader`.
- Add a watchdog, started by the session from the preface on: after
  `livenessProbeAfter` (5 s) of silence, send one `$/ping` without blocking
  on the write; after `livenessDeadline` (20 s) of silence, close the
  client with `ErrLinkSilent`. A reply of any kind, including an error,
  counts. The watchdog stops when the client closes.
- `ErrLinkSilent` maps to the existing disconnected error for callers, so
  pending calls fail as on any drop and mutations report "outcome unknown".
- Check that the notification handlers run in the read loop do not block
  (emitter calls, diagnostics bookkeeping). Move one off the loop if it can.

## Acceptance criteria and tests

With shortened durations and barriers, not sleeps where avoidable:

- A server that stops reading and writing (pipes kept open) makes the
  client close with `ErrLinkSilent` after the deadline, and `Session.Done`
  fires.
- A server that sends one large response in small chunks, slower than the
  deadline in total but never silent for long, is not dropped.
- A blocked write (the server never reads) does not stop the watchdog.
- A server that answers `$/ping` with an error (simulating an older build)
  keeps the link alive.
- `$/ping` before initialize, and during a slow initialize, gets a reply.
- At most one ping is in flight.
- `go test -race ./internal/rpc/... ./internal/remote/...` passes.

## Evidence

Implemented byte-level monotonic activity tracking, a 5 s quiet probe and
20 s silent deadline, one outstanding ping, and immediate server replies
before/during initialize. Termination publishes `ErrLinkSilent` (wrapping
`ErrDisconnected`) before cancelling the SSH/WSL transport, so pending calls
fail and `Session.Done` follows even with a blocked pipe. Existing mutation
error mapping remains unchanged. Initialization preserves the silent reason.

Notification callbacks and emitters now run on an ordered delivery worker,
not the transport reader; diagnostics ownership/sequence bookkeeping remains
synchronous and does no external I/O. A blocked callback test confirms replies
still reach the activity reader.
