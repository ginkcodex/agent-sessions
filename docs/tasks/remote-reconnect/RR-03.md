# RR-03 — Fresh connection after a silent drop

- **Status:** ✅ Done
- **Estimate:** 2 h
- **Depends on:** RR-02
- **Plan:** [remote-reconnect.md](../../plan/remote-reconnect.md)

## Scope

- Let `remote.Session` report why it ended (`ErrLinkSilent` or other).
- In `dialLoop`, after a session ends with `ErrLinkSilent`, stop the host's
  ControlMaster before the backoff wait, unless `busy(host)` reports a
  terminal tab using it. Use the existing `stopMaster` with
  `stopMasterTimeout`. Not on Windows (no master).
- Set the phase error to "no response from the host for 20s" (from the
  deadline value) instead of "connection lost" for that case.

## Likely files

`internal/remote/session.go`, `internal/app/remote.go`,
`internal/app/remote_test.go`.

## Acceptance criteria and tests

- With a fake dialer and a fake master stopper: a silent drop stops the
  master once, before the next dial; a plain drop (server exit) does not;
  a busy host does not.
- The emitted `reconnecting` state carries the new message.
- A stop that fails or times out does not block the retry.
- A newer generation (host switch, Disconnect) during the stop does not
  start a dial for the old host.

## Evidence

Session exposes its terminal RPC reason and the configured deadline message.
Silent drops publish that message and close the unused master before waiting
and retrying; busy terminals and no-master configurations retain their current
transport behavior. Cancellation is rechecked after master cleanup.
