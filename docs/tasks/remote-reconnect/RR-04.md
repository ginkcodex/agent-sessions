# RR-04 — Time limit on automatic attempts

- **Status:** ✅ Done
- **Estimate:** 3.5 h
- **Depends on:** —
- **Plan:** [remote-reconnect.md](../../plan/remote-reconnect.md)

## Scope

- Mark dial attempts as automatic when `dialLoop` retries (after a drop or
  a failed attempt). The first attempt of a `Connect` stays as today.
- For an automatic attempt on Unix, apply `probeTimeout` (45 s) to the
  probe, as Windows and WSL already have.
- Pause that limit while an askpass prompt for this connection is open:
  the broker reports prompt open/closed (it has no such state today), and
  the limit is a pausable timer that cancels the attempt context when it
  runs out.
- A timed-out attempt is a transient error: it goes to the next backoff
  step, with a message naming the limit.

## Likely files

`internal/app/remote.go`, `internal/remote/probe.go`,

## Acceptance criteria and tests

- A fake probe that never returns is cancelled after the (shortened) limit
  on an automatic attempt, and the loop moves on to the next attempt.
- The same probe on the user's first connect is not limited
  (`TestSSHProbeAllowsUnixPrompts` keeps passing).
- An open prompt pauses the limit; answering or cancelling it resumes the
  remaining time.
- Windows and WSL keep their existing 45 s probe limit.

## Evidence

- `dialLoop` labels every attempt after the first in a `Connect` generation
  automatic, including retries after a failure or a connected session drops.
  A fresh manual `Connect` starts with an unbounded Unix probe again.
- Automatic probes use the 45 s active-time budget. The per-connection askpass
  broker synchronously reports pending-prompt state; open prompts pause the
  timer, and the last answer, cancellation, broker closure, prompt timeout or
  helper disconnect resumes the remaining budget. Multiple pending prompts
  keep it paused until all close. No credentials are retained by the timer.
- The timeout error names the configured limit and wraps
  `context.DeadlineExceeded`, so existing transient-error retry handling
  advances the backoff. Deploy and serve-handshake limits are unchanged, as
  required by the plan; Windows/WSL retain unconditional probe deadlines.
- Passed `go test -race ./internal/remote ./internal/app` and
  `go test -race ./internal/remote -run 'TestAskpass_ProbeBudget|TestSSHAutomaticProbeTimeout' -count=5`.
  Coverage includes a hanging fake SSH probe, the existing first-connect
  Unix-prompt test, answer/cancel/close pause transitions, remaining-budget
  preservation, overlapping prompts, disconnected helpers, and automatic
  retry marking after failures/drops. The connection-loop test models the
  timeout with a shortened context; the actual child-process timeout is
  exercised separately in the remote package.
- `git diff --check` passed. Native Windows/WSL/macOS and Docker SSH integration
  were not run for this task. Shared progress indexes are left to the coordinator.
