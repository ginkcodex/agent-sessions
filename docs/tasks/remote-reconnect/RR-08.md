# RR-08 — Release retained SSH stderr on cancellation

- **Status:** ✅ Done
- **Estimate:** 1 h
- **Depends on:** RR-02
- **Plan:** [remote-reconnect.md](../../plan/remote-reconnect.md)

## Scope

The first RR-07 Docker run exposed an extra 5 s between the silent deadline
and Session.Done: exec.Cmd's implicit stderr copier waited for WaitDelay when
a mux/proxy child retained the write end. Own the stderr pipe/drain and close
its read end alongside stdout on cancellation. Keep bounded stderr diagnostics.

## Likely files

`internal/remote/session.go`, tests beside it.

## Acceptance criteria and tests

- Silent transport cancellation does not wait for an inherited stderr pipe.
- SSH recovery scenarios meet the 25 s detection bound.
- Remote race tests and full SSH harness pass.

## Evidence

2026-11-08: first integrated Docker run failed the 25 s bound (one observed
drop at 25.1 s). Own stderr draining and cancel both pipes; a regression test
spawns a child retaining stderr for 3 s and requires Session.Done within 2 s
with the shortened 300 ms watchdog.

- `go test -race ./...` — pass after this fix and the new regression test.
- Production-timing Docker scenario rerun — pass: both drops detected in
  21 s, network-cut recovery 9.1 s, frozen-host recovery 0.2 s.
- Full SSH harness final rerun is recorded under RR-07; native clients not
  checked.
